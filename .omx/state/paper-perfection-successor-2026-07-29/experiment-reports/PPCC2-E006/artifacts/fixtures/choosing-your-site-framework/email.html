You're about to

This guide exists so you can make that choice with open eyes: what each framework is genuinely good at, where it will bite you, and which one fits the site you actually want to ship. There is no single right answer — only the right answer *for your project*.

The short version.

For most content sites — blogs, docs, marketing, portfolios —

Astro

is the best default, and it's the one you can spawn today. If you need a heavily interactive app, you'll want a server-rendered framework like Next.js or TanStack Start. Read on for why.

Barkpark keeps your

site and your content on the same wire

— the site fetches from your Barkpark project over an internal connection, not the public internet. That means faster builds, private reads, and instant updates when your content changes. Static sites get this at build time; server-rendered sites get it on every request.

— updates roll out with zero downtime, the same way the rest of your Barkpark runs.

"Ships JS by default"

is a proxy for page weight and speed. Less shipped JavaScript means faster loads and better search rankings — which is why content-first frameworks win on SEO.

The frameworks in depth

Astro — the content-site flagship

Astro is built for exactly what a CMS produces: pages of content. It renders to static HTML by default and only ships JavaScript for the interactive "islands" you explicitly ask for. If you're building a blog, documentation site, marketing site, or portfolio, this is the one to reach for.

Best for:

blogs, docs, marketing sites, portfolios, landing pages, changelogs.

Pros

Blazing fast by design

— ships near-zero JavaScript, so pages load instantly and score top marks on Core Web Vitals.

Built for headless CMS

— its content layer is designed to pull from an external source like Barkpark, so the integration is natural, not bolted on.

Excellent SEO out of the box

— fast, static, semantic HTML is what search engines reward.

Use any UI library

— drop in React, Svelte, Vue, or Solid components as islands; you're not locked into one.

Gentle learning curve

— if you know HTML and a little JS, you can be productive in an afternoon.

Cheapest to host

— static output means your site is basically free to serve and scales without limit.

Grows with you

— start static, add server-rendering later for the few pages that need it.

Huge, active ecosystem

of themes and integrations to start from.

Cons

Not built for app-like UIs

— if your site is mostly dashboards, live filtering, or complex client state, Astro's island model fights you.

Islands take a mental shift

— sharing state between separate interactive components is deliberately awkward.

Smaller component ecosystem

than the React/Next world.

Server-rendering is younger

than Next's — battle-tested less at very large scale.

Recommended default, and spawnable today.

If you're unsure, start here — you can always graduate to a heavier framework later.

Next.js — the do-everything heavyweight

Next.js is the most popular React framework and can build essentially any kind of site — from a static blog to a full SaaS app. That power comes with weight and complexity.

Best for:

apps with logged-in users, dashboards, e-commerce, anything that mixes content with heavy interactivity.

Pros

Does everything

— static pages, server-rendering, and incremental updates all in one framework.

The largest ecosystem

— the most tutorials, templates, integrations, and hireable developers of any framework here.

Great for interactive apps

— if your site has accounts, carts, or dashboards, Next is at home.

Incremental Static Regeneration

— pages can rebuild in the background as content changes, blending static speed with fresh data.

First-class React

— access to the entire React component universe.

Cons

Heavy

— ships a lot of JavaScript, so pages are slower than a static Astro or Hugo site unless carefully tuned.

Complex

— React Server Components and the App Router have a real learning curve, and the "right way" keeps evolving.

Frequent breaking changes

— major versions can mean real migration work.

Server-rendering costs more to run

— dynamic pages need a live process, which grows with traffic.

Overkill for a brochure site

— you'll carry complexity you never use.

TanStack Start — the modern, type-safe challenger

TanStack Start is a newer full-stack React framework built around the excellent TanStack Router. It prioritises end-to-end type safety and a fast, modern developer experience.

Best for:

highly interactive, data-heavy applications where type safety and routing power matter.

Pros

End-to-end type safety

— from your routes to your data, mistakes get caught before they ship.

Best-in-class routing

— TanStack Router handles complex, nested, data-driven navigation elegantly.

Fast, modern tooling

— built on Vite, so builds and hot-reload are quick.

Excellent for interactive apps

— streaming server-rendering keeps data-heavy pages snappy.

Cons

The newest option here

— smaller community, fewer templates, fewer answers when you hit a wall.

Not content-first

— overkill for a blog or marketing site.

Server-rendering runtime

— same running-process cost as Next.

Fewer hireable specialists

— a smaller talent pool than React/Next.

Younger = more risk

— APIs are still settling compared to mature frameworks.

SvelteKit — small, fast, and pleasant

SvelteKit compiles your components away at build time, so the browser downloads very little framework code. It handles both static and server-rendered sites and is widely loved for its developer experience.

Best for:

teams who want small, fast sites and enjoy a clean, minimal syntax — content or app.

Pros

Tiny bundles

— the framework compiles itself out, so pages are light and fast.

Loved developer experience

— concise syntax, less boilerplate than React.

Flexible

— does static and server-rendering equally well.

Built-in essentials

— routing, data loading, and forms come in the box.

Cons

Smaller ecosystem

than React — fewer ready-made components and integrations.

Fewer Svelte developers

to hire than React developers.

Server-rendering runtime cost

when you choose SSR.

Less enterprise track record

than Next at very large scale.

Nuxt — the Vue powerhouse

Nuxt is to Vue what Next is to React: a mature, full-featured framework for building both content sites and applications. If your team knows Vue, this is the natural home.

Best for:

Vue teams building content-rich sites or full applications.

Pros

Mature and complete

— years of production use, batteries included.

Great content tooling

— a dedicated content module makes CMS-driven sites straightforward.

Does static and server-rendering

— flexible per page.

Approachable

— Vue is often considered gentler to learn than React.

Cons

Smaller talent pool here

than React-based options.

Server-rendering runtime cost

identical to Next when you go SSR.

Ships more JS

than an islands or compiled framework like Astro or Svelte.

Vue-only

— you can't borrow the React component universe.

Hugo — the fastest static builder there is

Hugo is a single Go binary that turns content into a static site faster than anything else on this list. No Node.js, no runtime — just files. It's a superb fit for large content sites where build speed matters.

Best for:

large blogs, documentation, and content sites where raw build speed and simplicity win.

Pros

Fastest builds on the market

— thousands of pages in seconds.

No JavaScript runtime needed

— a single binary, nothing to keep alive, nothing to patch.

Cheapest and safest to host

— pure static output, no server code to attack.

Massive theme library

— hundreds of ready-made designs.

Rock-solid and stable

— mature, with few breaking changes.

Cons

Weak on interactivity

— no built-in "islands" story; dynamic bits need hand-rolled JavaScript.

Go templates are clunkier

than modern component syntax.

Not for app-like sites

— static only, by design.

Smaller front-end developer familiarity

than the JavaScript frameworks.

Eleventy (11ty) — dead-simple static

Eleventy is a minimalist static site generator. It does very little on purpose, which makes it fast, predictable, and easy to reason about.

Best for:

simple content sites where you want maximum control and minimum magic.

Pros

Extremely simple

— little to learn, little to go wrong.

Zero JavaScript shipped

— pages are as light as they get.

Fast builds

and a tiny footprint.

Template-language freedom

— write pages in whichever templating style you like.

Cons

No interactivity story

— you add all dynamic behaviour yourself.

Very hands-on

— the minimalism means more wiring for anything non-trivial.

Smaller ecosystem

than Astro or Next.

Static only

— no server-rendering path.

Barkpark Native — the instant, zero-effort site

Not every site needs a framework. Barkpark can render your content as a live site directly — no build step, no code, no framework to learn. Publish content, get a site. It's the fastest way from "I have content" to "it's online."

Best for:

getting content live in seconds, previews, and anyone who doesn't want to touch a framework at all.

Pros

Instant

— live in seconds, with nothing to build or deploy.

Zero code and zero maintenance

— Barkpark handles the rendering and the updates.

Always in sync

— the site *is* your content; there's no separate copy to fall out of date.

No runtime to pay for or secure

— it runs on infrastructure you already have.

Cons

Barkpark's look, not yours

— you theme within what Barkpark offers, rather than designing freely.

Not for bespoke designs

— if you need pixel-level custom layouts, reach for a framework.

Limited custom interactivity

— it's a content site, not an app platform.

Available today.

The zero-friction way to get online while you decide whether you need a full framework.

How your site goes live — and stays live

Every site you spawn deploys the same way, whether it's Astro, Hugo, or Barkpark Native. The process is built around one promise:

your live site never goes down, and a broken build never reaches your visitors.

1. Trigger

You click deploy — or you simply publish content and Barkpark rebuilds on its own

No manual redeploy for content changes

2. Build in isolation

Your site is built on separate infrastructure, reading your content over a private link

Your live site keeps serving the whole time

3. Health check

The new build is tested before anyone sees it

A broken build stops here — your current site is untouched

4. Atomic switch

The instant the new build passes, visitors flip to it

Zero downtime, no half-updated state

5. Instant rollback

The previous version is kept, ready to restore

If something's wrong, revert in one click, instantly

What you can spawn today — and what's coming

Barkpark Cloud rolls these out in order of demand. Every framework plugs into the same engine, so the ones marked *coming* are add-ons on a shared foundation, not rewrites.

Available now:

Astro (static) and Barkpark Native (instant).

Next up:

Hugo — proving the same engine serves a second static framework with zero Node runtime.

Then:

Next.js and TanStack Start — server-rendered frameworks, once the secure per-site runtime lands.

After that:

SvelteKit, Nuxt, and Eleventy — filling out the menu.

Escape hatch:

for teams who want a global edge or a fully managed host, Barkpark can also deploy your site to an external platform instead of running it close to your content.

Not sure? Start with Astro.

It covers the vast majority of sites beautifully, it's spawnable today, and nothing you build is wasted if you later graduate to a heavier framework.
