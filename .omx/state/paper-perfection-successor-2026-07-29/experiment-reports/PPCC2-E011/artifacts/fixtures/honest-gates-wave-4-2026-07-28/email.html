The direction: protection ships, and the merge protocol ships as an ARTIFACT, not a sentence

Wave 3 framed the blocker as 'protection needs a merge-protocol replacement.' That framing is right and incomplete. The replacement it proposed — rewrite PROCESS RULE 2 — is a SENTENCE, and this epic's own charter law says a slice is not done without part three: the population and the ratchet. A sentence has neither. D48 is the proof already in the record: the same merge folklore occurs 253 times across 68 files and its highest-leverage copy lives OUTSIDE the repo where no builder and no CI guard can reach it. A prose merge protocol is exactly the kind of predicate this epic exists to abolish — one that cannot be executed, cannot be tested, and cannot be proven able to fail.

So the centrepiece of this wave is not the PUT. The PUT is four minutes of work with tooling that already exists and is mutation-proven. The centrepiece is that THE FLEET'S MERGE VERB BECOMES A SINGLE EXECUTABLE ARTIFACT, and every prose site collapses into a pointer at it.

What the finished experience looks like. An agent finishes a slice, pushes, and runs one command — the sanctioned merge verb. It runs the deadlock detector FIRST (set difference of the committed spec against the check runs actually rendered on the head, exit 3 as a third state), so a PR that can never merge is refused in seconds with the missing context NAMED — something GitHub itself will never tell you at N=2, where the refusal reads '2 of 2 required status checks are expected.' and names nothing. If the PR is merely not-yet-green, the verb waits within a bounded budget and merges the moment it goes green; if the wait exceeds the budget it hands off to GitHub's own auto-merge and says so. If a required check is genuinely red, it refuses and quotes the refusal. If the ledger is down, it says the ledger is down and names the exit. The agent never types --admin, never types --auto, and never has to know which of GitHub's six refusal shapes it is looking at. Every one of those shapes maps to one row of an enumerated exit table, and every row has one command.

And the break-glass is not a curl. A curl cannot be attributed on a user-owned repo and cannot be prevented from being left open. The break-glass becomes a script that CANNOT OPEN WITHOUT WRITING A RECORD: it refuses without a reason and a task id, writes the record to the ledger first, then DELETEs enforce_admins — and while it is open, the required-checks verify guard reds in CI, so the repo itself screams until it is closed. One attributable command down, one back, impossible to leave open silently — the wish's words, satisfied mechanically rather than by discipline.

The choices I lean toward, tentatively:

  • BOTH names on day one, as the committed spec already pins: 'Elixir gate' + 'PR references an active task'. D43's refusal of a ratchet-free required set stands, and Elixir gate is where every ratchet waves 1-3 built actually rides.
  • hgw3-s7-charter-via-pr is a HARD precondition and ships in round 1. D39 is L1: protection rejects a direct push with GH006, and 12.7% of main arrives that way from the epic-cycle's own Decide phase. Without it, every concurrent wave hangs at Decide the day the flip lands.
  • hgw2-s4-format-ceiling-reland is NOT a precondition and must not gate the flip. It adds a blocking job to the aggregator's needs, which changes Elixir gate's COMPOSITION, not the required NAME. It carries its own hazard in the other direction (a stale roster reds the required context repo-wide), so it lands BEFORE the flip with a fresh roster or it is explicitly deferred with the hazard named — never squeezed in after.
  • The lease gets DECIDED, not documented, and it is a hard sibling of the flip rather than a nice-to-have. The 6h grace is already exceeded on a live PR's own task. Requiring the task gate on top of a predicate we have measured to be currently false is installing a known false red — the epic's disease inside the epic's own flip.
  • allow_auto_merge: lean YES, but as a MECHANISM the artifact invokes behind a mandatory pre-flight, never as a protocol agents type. The wave decides it on evidence (the api-PR ratio, real merge dwell) and adopts hg-bl-enable-auto-merge-under-protection rather than re-filing it (D14).
  • The fleet unfreeze is executed and evidenced, not asserted — with one measurement first that could collapse its cost by an order of magnitude (survey key unfreeze-cost).

The direction debate: four rivals, argued

RIVAL 1 — FLIP AND FOLLOW. Install protection with the two names; the merge-protocol replacement is 'delete one flag' (D40 measured that a plain gh pr merge --squash merges under enforce_admins:true the moment the required context goes green); rewrite PROCESS RULE 2; decide auto-merge NO. Smallest possible change, lowest blast radius, ships in one round.

Why it loses. It is the wave-3 plan with the deferral removed, and it repeats a mistake the charter already documented. A prose-only merge verb has no population step and no ratchet, and D48 measured what happens to prose in this fleet: 253 occurrences, 68 files, and the one that reaches every session automatically lives in a different repository. Worse, it leaves each agent to interpret GitHub's refusal themselves — and D38 measured that at N=2 the refusal names NOTHING, and that a deadlock and a red are only distinguishable by a set difference nobody is doing. An agent that cannot tell a deadlock from a red, holding a token with admin rights, will open the glass. That is D13 a fifth time by a different door.

RIVAL 2 — THE MERGE VERB BECOMES AN ARTIFACT (the winner). Same flip; the deliverable is one executable merge verb plus one executable break-glass, both harnessed and mutation-proven, and every prose site — bp-loop-ledger.md:43, .claude/agents/felix.md:44, connectors/README.md:189, docs/ops/merge-gates.md, and the out-of-repo memory file as a lead action — repointed at them.

Why it wins. It is the only rival that satisfies the epic's own acceptance law. CAUSE: protection installed with enforce_admins true. POPULATION: every merge path in the fleet repointed, not the one sentence that happened to be cited. RATCHET: the verb's own harness, the break-glass that cannot open silently, the verify guard that reds while it is open, and a tripwire that reds if --admin reappears as a sanctioned verb. It also converts the auto-merge question from a fleet-wide behavioural change into an implementation detail behind a pre-flight — which is precisely how to absorb the sharpest objection against it.

RIVAL 3 — STAGE THE TEETH: protect with ONE name today, add the second once the fleet is unfrozen. Genuinely attractive: it kills the plain sentence within the hour and makes a fifth deferral structurally impossible, because protection would already be installed when the unfreeze work begins. The obvious staging is 'task gate first' — it renders on 15 of 15 open PRs, so the freeze cost is ZERO, it re-fires without a push (D43), and its p50/p90 are 16s/57s.

Why it loses, and why its INVERSE survives as a fallback. Task-gate-first is the worst possible single name: it is the ONE required context whose verdict depends on guerrilla, a host measured at 2.8-10.3s under concurrent waves that 500s outright on large payloads, and whose lapse predicate is measurably false RIGHT NOW on hgw2-s5. Requiring it alone means one ledger outage deadlocks the entire repository with no other check to reason from, and D49's only documented exit — the hotfix! label — needs a push to engage and records nothing. The INVERSE staging (Elixir gate only on day one, task gate second) is strictly safer: it depends on GitHub alone. It survives as the wave's fallback if the unfreeze or the lease decision proves more expensive than measured — but it is not the plan, because both names are already pinned in a spec that was generated, selection-tested across 8 heads of different path shapes, and reviewed.

RIVAL 4 — FIX THE LEASE AND THE HOTFIX BREAK-GLASS FIRST, FLIP NEXT WAVE. Honest-sounding: do not require a gate you have measured to be currently lying. Rejected as deferral #5 wearing a lab coat. The lease fix is a predicate change in one script with an existing 62-fixture harness; it is a SIBLING of the flip, not a prerequisite round. Sequencing it as a prerequisite is exactly the move that produced three better-reasoned deferrals.

The sharpest attack on the winner, and how the wave absorbs it

THE ATTACK. 'The merge verb as an artifact' introduces a new mandatory tool to a fleet of roughly 250 agent-runs a day that reads prose and acts on habit. D26 is the charter's own warning: a harness nobody runs is not a ratchet. If agents keep typing gh pr merge --squash --admin from muscle memory, the artifact changes nothing — except that now the habitual command FAILS LOUDLY, and the agent's most natural recovery, holding a token with repo admin, is to open the glass. The wave would then have built a beautifully-harnessed verb nobody uses and a break-glass everybody does. That is D13 a fifth time, installed by the wave that was supposed to end it.

HOW THE WAVE ABSORBS IT. Four ways, and they are acceptance criteria, not intentions.

  • GRACEFUL DEGRADATION. The verb is a THIN wrapper. If an agent ignores it entirely and runs a plain gh pr merge --squash, that still works and still respects protection — D40 measured it. The artifact adds pre-flight and waiting; it does not add a required dependency. Only --admin breaks, and only when it should.
  • THE POPULATION LANDS IN THE SAME SESSION AS THE FLIP. Not the same wave — the same session. The three live agent-facing prose sites plus merge-gates.md ship in the flip's own PR, and the out-of-repo memory file is a named LEAD ACTION executed alongside, because no builder worktree can reach it (D48).
  • THE GLASS IS DELIBERATELY HIGHER-FRICTION THAN THE CORRECT PATH. Merging correctly is one command with no arguments. Opening the glass demands a reason and a task id, writes a record before it acts, and makes CI red until it is closed. The friction gradient must point at the correct path, and that is testable.
  • ADOPTION IS MEASURED, NOT ASSUMED. 'The same PR merges once green' generalises: the wave does not close until real fleet merges have gone through the new verb and the audit of what actually happened is in the debrief. If the fleet routes around the verb, that is a finding this wave must report, not one the next wave discovers.
