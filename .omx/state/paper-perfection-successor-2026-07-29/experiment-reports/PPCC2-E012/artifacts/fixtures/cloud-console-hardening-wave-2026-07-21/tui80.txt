CORRECTION 1 — THE SSE TICKET IS NOT FREE, AND THIS IS THE SINGLE MOST IMPORTANT
NEW FACT. The direction named the constraint 'EventSource cannot set headers, so
a header is NOT the fix — mint a short-TTL single-use SSE-scoped ticket.' The
first half is right. The second half hides an architectural tension the survey
exposed: EventSource freezes its URL at construction (app.js:11919), and the
client's onerror handler (11943-11954) only toasts and repaints the liveness
chip — it never closes or reopens the stream. Native browser reconnect therefore
replays the SAME frozen URL forever. A literal single-use ticket means the first
connection consumes it and EVERY subsequent native retry 401s permanently — a
regression strictly worse than the leak being fixed, and it would fail the
task's own criterion 2 on any network flap. There are exactly two honest
resolutions: (a) ship short-TTL MULTI-connect and name it that, never
overselling it as single-use; or (b) ship true single-use AND rewrite the client
reconnect path — close, mint over a bearer header, reconstruct EventSource, add
explicit backoff to avoid a mint storm, and extend the liveness state machine to
model an app-driven remint gap. This is a DECIDE-TIME RULING, not a builder
detail. The mechanism itself needs no migration: user_tokens.context is an
unconstrained string column, 2fa_pending is the short-TTL mint template, and
reset_password_by_token is the battle-tested single-use consume-in-transaction
template.
