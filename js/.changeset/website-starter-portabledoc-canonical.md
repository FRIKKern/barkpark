website-starter: migrate the about, pricing, and post pages off the legacy Sanity `PortableText` renderer onto the canonical `@barkpark/react` `PortableDoc` — mirroring the blog-starter migration. All three now render `renderPortableDocument(blocks)` inside a shared `.bp-paper-surface` island (`app/portable-doc-surface.tsx`, skinned by `@barkpark/react/paper-surface.css`), which hydrates media mount points via `hydratePortableDoc` from `@barkpark/react/client` (mermaid diagrams + asciicasts; images stay static `<img>`). No `PortableText` import remains. The `page.body` and `post.content` schema fields carry `surface: 'body'` and the seed's paragraph helper now emits the canonical `{ type: 'paragraph', content: [...] }` block shape instead of a Sanity-style `_type: 'block'`. `@barkpark/react` is pinned to `^1.0.0-preview.2`, and `mermaid` + `asciinema-player` join the template deps (lazy-loaded only if content ever uses those block types). `lib/csp.ts` and `middleware.ts` comments are corrected: the scaffold now has one trusted `dangerouslySetInnerHTML` sink (the PortableDoc emitter's escaped output), and the nonce-based CSP is defense-in-depth on top of that, not a "zero raw-HTML injection" claim.

Note: as with the earlier blog-starter migration, a freshly scaffolded site cannot yet build end-to-end against the *published* `@barkpark/react` — the npm package still ships `1.0.0-preview.1`, which predates `PortableDoc` and the `./client` subpath (tracked by `rpu-backlog-publish-react-canonical`, human-gated). This change is source-verified against the workspace build (typecheck passes with zero new errors versus origin/main, confirmed by a differential `tsc --noEmit` run).
