core: an id that is a relative-path operator can no longer retarget a request at a different endpoint. `encodeURIComponent` escapes `/` and `\` but not `.`, so an id of `'..'` survived every path builder intact and fetch's URL parser resolved it before the request left — `revokeCollectionShare('..')` emitted `DELETE /v1/media/:dataset/:id` (an asset deletion) instead of a share revoke, `getCollection('..')` returned a truthy bogus collection from the collection INDEX where a real miss returns `null`, and `getAssetRelations('..')` ate the client's own dataset segment. One shared runtime guard (`assertSegment`) now covers every value interpolated into a path segment — the media asset/collection ids, `doc`/`getHistory` type+id, `getRevision`/`restoreRevision` revId, `getTagDocs` tag, `getSchema`/`deleteSchema` name, `getBacklinks`/`getRelated`/`getGraph` id, and the webhook CRUD id — rejecting `''`, whitespace-only, `'.'`, `'..'`, and (for ids, not tags) `/` and `\` with a `BarkparkValidationError` before any network call. A hierarchical tag like `a/b` is still accepted: `encodeURIComponent` collapses it to a single `a%2Fb` segment. Percent-encoded forms (`%2e%2e`) are deliberately not rejected — every call site encodes the value, so the `%` is escaped and they can never decode back to `..`.

core: `imageUrl()` no longer hands back a url whose scheme it never checked. The inline-url branch returned the stored image field verbatim, so `javascript:`, `data:text/html`, `vbscript:` and protocol-relative `//host` strings came straight out of a function whose entire job is to produce a URL for markup — content that, in a CMS, is attacker-writable. It now returns `null` for anything that is not an absolute `http(s)` URL or a relative path on the caller's own origin, using the same parse-and-allowlist the package already applies to webhook delivery urls (there is now exactly one such allowlist, `isHttpUrl`). Severity stated plainly: the only sink traced in this repo is `<img src>`, where `javascript:` does not execute — this is a latent API-contract defect, not a proven XSS, and it becomes one at any consumer that puts the result in an `<a href>`.

Both guards are runtime checks, not type signatures: this package ships CJS/ESM to plain JS callers with no types at all. Deduplicating the fourteen hand-rolled non-empty-id checks paid for the new logic, so the bundle got smaller (ESM 16377 → 16376 B gzip, CJS 17062 → 17061 B) and the size cap was not raised.
