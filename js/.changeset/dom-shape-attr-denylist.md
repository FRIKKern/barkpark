Widen the cross-surface DOM-shape comparator from an implicit attribute ALLOWLIST to a small, justified DENYLIST (test-only; no runtime or API change). `tests/support/dom-shape.ts` compared only tag + class-set + `data-*` + `style` + text + child order, dropping every other attribute on a rationale ("comparing e.g. CDN image URLs would red on cross-surface query ordering") that covers the URL-bearing attributes and nothing else. Measured across all 64 `pd-golden` fixtures: 41 distinct attribute names appear on the two mirrors and were compared by nothing — including `role`, `aria-label`, `aria-hidden`, `aria-selected` (accessibility semantics), `scope` (table structure), `alt`, and the entire SVG geometry surface (`x`, `y`, `points`, `d`, `viewBox`, `fill`, `stroke`) which for the `route` block IS the content. All 41 currently agree, so the exclusion hid no live divergence — only future ones: flipping the Elixir mirror's `scope="row"` to `scope="col"` (real screen-reader breakage) left the harness green at 81/81. The comparator now projects every remaining attribute into `ShapeNode.attrs` and diffs it, exempting only the exported `VARIABLE_ATTRS` set (`href`, `src`, `srcset`, `poster`, `id` — values that legitimately vary between surfaces without structural meaning) plus `width`/`height` on media tags, which `composed-doc-parity`'s RESPONSIVE WIDTHS case defines as sizing hints; on `<svg>` those two names stay compared because there they are geometry. Six new protective self-tests pin the new leg red on a divergent `role`/`aria-hidden`, `scope`/`colspan`, and a missing `rel="noopener"`. All three consuming surfaces stay green under the stricter comparator: react 597/597, astro-parity 69/69, next-parity 70/70.
