Close three defects on the anonymous-visitor surfaces of the shipped starter templates.

**website-starter — the contact form could never work, and failed loudly.** `app/contact/actions.ts` built `defineActions({ client: barkparkClient })`, and `barkpark.config.ts` builds that client with no token, while `POST /v1/data/mutate/:dataset` always requires one — so every submission on a freshly scaffolded site failed. The Server Action now attaches `BARKPARK_SERVER_TOKEN` itself via `barkparkClient.withConfig({ token: resolveServerToken(process.env) })`, the same precedent the read path already set in `lib/barkpark.ts`; the credential stays in a `'use server'` module rather than on the shared config, so no client component can import it. The catch also returned `Submission failed: ${err.message}` — the raw upstream answer, which can name your API host, dataset, workspace/project slugs, schema fields, or a token-rejection reason — straight into a page any anonymous visitor can load. The visitor now gets one fixed sentence (`lib/submission-error.ts`) and the detail goes to the server log. Adds `schemas/contact.ts` (the type the form writes, `visibility: 'private'` because submissions carry a visitor's email address).

**blog-starter — `?page=` was clamped on one side only.** `Math.max(1, Math.floor(Number(sp.page ?? '1') || 1))` bounded the low end and nothing else, and `<Pagination>` then ran `Array.from({ length: totalPages })` in a Server Component. Measured: `?page=20000` rendered 20 000 `<Link>` elements server-side per request, and `?page=Infinity` (truthy, so it walked past the `|| 1`) threw `RangeError: Invalid array length` and 500'd the route. New `lib/page-param.ts` rejects non-finite input with `Number.isFinite` and clamps the page to the real corpus size (`countDocs`), and `pageWindow` caps how many numbered links a single render can build, so the array length is bounded no matter what a caller passes.

**blog-starter — the preview secret is compared in constant time.** `/api/preview` is the only thing between an anonymous GET and `draftMode().enable()`, and it compared the secret with `!==`, which exits early and leaks the secret's length and first-wrong-byte position. It now uses `lib/constant-time-equal.ts` (SHA-256 both sides, then `crypto.timingSafeEqual`, which throws on a length mismatch and so cannot take raw input directly) — matching the `timingSafeEqual` standard already used by `@barkpark/nextjs`'s `createDraftModeRoutes` and `@barkpark/core`'s webhook verifier. The route pins `runtime = 'nodejs'`; its same-origin redirect guard and fail-closed-in-production arm are untouched.
