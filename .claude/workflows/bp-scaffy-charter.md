# Scaffy Epic — Charter

The epic's memory. Every wave reads this before it plans. Wave Paper (living story) per wave; this file is the durable spine.

## Vision

**Scaffy = commands as content.** A command is a `.scaffy` file: a declarative, idempotent, reversible scaffolding document that CREATEs a vertical slice AND injects its wiring into the accretion files a plain generator can never touch (registries, routers, barrels, index files, config maps) — at guarded, marker-planted anchors, closing with assertions that run the repo's own gates. Commands become a Barkpark document type — authored in Studio or as `.scaffy` text, stored, versioned, tagged, served over one connect, executed by `bp`. The doctrine: *every fact has one owner; every derived surface is collected at runtime (plugin behaviour), generated from a manifest (capabilities/tokens/codegen), or applied by a command — never maintained by hand.* Design paper: `/papers/scaffy-commands-as-content` (masterplan, published 2026-07-16). Lineage: the nextgen-cli command concept (see `~/github/nextgen-vscode/ng-test-example.nextgen` for the reference grammar and its known bugs) reborn on a hardened grammar, with Barkpark as the command store.

The epic's north star: `bp add block-type --var BlockName=timeline` → 30 seconds → a new PortableDoc block rendering on all four surfaces, parity at birth. The fast path IS the standard path; standards become executable.

## Decisions

- **D1 — The extension and brand are `.scaffy`.** The format previously sketched as `.nextgen` is absorbed: same sentence-shaped DSL voice, Scaffy name everywhere. No `.nextgen` references in any new artifact; the masterplan paper gets patched (D8).
- **D2 — Wave 1 ships the COMMAND CORPUS + SHOWCASE, no engine.** Full-text, complete, copy-ready `.scaffy` commands — never sketches or elided `…` bodies. Repo home: `scaffy/commands/*.scaffy` + `scaffy/README.md` (doc-tier: human). NO new docs card (7-card hard cap; router gets no new row this wave). Engine (parse/apply/remove) is W2/W3.
- **D3 — The corpus DEFINES the hardened v2 grammar by example.** Binding rules, from the format review: (a) every multi-line anchor/target is fenced (`::: anchor :::`), never bare; (b) every mutating op carries `MARK "NAME"` — first run anchors structurally and plants the mark, later runs anchor at the mark (this is also the remove handle); (c) guards derive from the payload by default — explicit `ASLONG` only when the payload isn't self-identifying, and a guard must match text the op itself writes (the quote-mismatch re-insert bug is the canonical failure); (d) every token resolves to a declared `VARIABLE` (spelling-as-transform casing allowed: `{{.BlockName}}`/`{{.block-name}}`/`{{.blockName}}`); (e) shared payloads use `SNIPPET`/`USE`, never paste-twice; (f) commands close with `ASSERT FILE … CONTAINS` postconditions and, where a real gate exists, `ASSERT CMD` invoking it (`go test ./internal/pdrender/`, `scripts/docs-anchors-check.sh`); (g) path-position and URL-position tokens of the same variable must agree on casing.
- **D4 — Command set: 6–8 commands covering what Barkpark development actually repeats.** Mandatory flagship: **add-block-type** (Go renderer + test + `DefaultRegistry` map line in `internal/pdrender/pdrender.go` (~L241, `r.blocks["…"] = …`), Elixir clause reachable from `render.ex` `render_block/2` (~L182), JS registration in `js/packages/react/src/blocks/registry.ts`, edit CSS in `root.html.heex`). Mandatory symmetry pair: **add-docs-card + remove-docs-card** (routing-table row in `CLAUDE.md` + card file with `doc-tier` header; the 7-card cap makes remove non-optional). Strong candidates for the rest, DECIDE picks: **add-plugin** (behaviour module + minimal slice `plugins/<name>/{cli,…}.ex` + migration — CREATE-heavy since `discover_and_register/0` auto-collects; encode the canonical minimal callback set, cf. tickets' slice), **add-oban-worker** (worker + test + crontab entry in `api/config/config.exs` `Oban.Plugins.Cron` block ~L223), **add-cli-verb** (one entry in a plugin's `cli_commands/0` list, cf. `tickets.ex:311` — showcases "architecture already made this a one-liner"), **add-migration** (timestamped `api/priv/repo/migrations/` — timestamp arrives via `--var ts=…`, commands have no clock), **add-schema-type**, **add-api-route-parity** (route + SDK method + capabilities — router.ex is ordering-hostile: marks mandatory, mount only in a plugin `register_routes` context if too risky).

A command referencing a nonexistent anchor = failed criterion. Where a stable anchor is missing, the command may specify planting one — but the FIRST-run structural target must exist today.

### Wave-2 DECIDE (2026-07-16) — D20–D32, locked on run-proofs (matcher fork parsed with Elixir, lint dry-run over the live corpus, tsc/vitest greened in a fresh worktree, gh API protection checks)

- **D20 — REPLACE matcher pinned: byte-exact fenced-bytes.** The anchor matches the exact fenced bytes wherever they occur; REPLACE swaps ONLY those bytes — never the enclosing line/region. Proven on real config.exs: whole-line match fails clean on run 2 (accretion impossible); substring-consume-whole-line reproduces the recorded SyntaxError (task-5901b9eff006f553); byte-exact splice parses across 3 runs. Engine law (W3): the anchor must occur exactly once at apply time.
- **D21 — Run-≥2 re-anchor is first-class syntax: `REANCHOR "<mark-name-prefix>"`** — optional clause directly after `MARK` on REPLACE. Semantics (README-pinned, engine-independent): when any planted `MARK:<prefix>…` exists in the target file, the effective anchor is the LAST planted block of that family (the mark comment line + its marked payload line(s)) and WITH re-emits that block + separator + the new block; otherwise the fenced structural target applies (run 1). Proven: mark-scoped re-anchor yields FORWARD order (Foo→Bar→Baz), parses, and the ASLONG guard keeps same-worker re-runs no-op; the planted mark line is the ONLY safe key — a naive "last `Workers.X` tuple" tail-finder grabs the pre-existing non-scaffy TagDistribution tuple (config.exs:232). Corpus: add-oban-worker AND add-cli-verb (same defect class — its comment promises mark re-anchoring its op cannot express) gain `REANCHOR`. Lint upgrade (E-005): a self-consuming REPLACE (target ⊂ its own payload) without BOTH a payload-derived ASLONG and a REANCHOR is an ERROR.
- **D22 — VARIABLE annotations become grammar — ONE ruling for the opaque/pair/shape trio.** Optional structural keywords between the quoted name and TITLE: `OPAQUE` (value never re-cased; references use exactly ONE token spelling per file — any legal joiner-output of the declared name — and are exempt from path-casing lints), `SHAPE "ts14"` (named shape catalog; `ts14` = exactly 14 ASCII digits forming a real UTC YYYYMMDDHHMMSS instant — D16 discharged as code), `SUCCESSOR "CountBefore"` (value = named sibling + 1; validator lints EXAMPLES pairs — the +1 lint the corpus prose already requests). Corpus edits: Ts → `OPAQUE SHAPE "ts14"`; TableName/ColumnName/ColumnType/Summary/PathTemplate/CronExpr/Group/TaskPattern/CountBefore/CountAfter → `OPAQUE`; CountAfter additionally `SUCCESSOR "CountBefore"`. Transform variables (BlockName, WorkerName, PluginName, CardName, MigrationName, Noun, Verb) resolve via ONE shared word-list (`_`/`-`/case boundaries equivalent) + four deterministic joiners; not all 4 spellings need appear — every spelling that DOES must be a joiner output.
- **D23 — Direction is DECLARED, never inferred: required header field `DIRECTION "add"|"remove"`** (after VARIANT). Proven: polarity is textually undecidable — the containment heuristic false-positives on remove-docs-card's correct un-sweep REPLACE (a swap where neither side contains the other). One direction-driven rule family: add ⇒ `ASLONG FILE DONT CONTAIN`; remove ⇒ positive `ASLONG FILE CONTAIN` + consumed marks + `ASSERT FILE … ABSENT`.
- **D24 — Unplantable MARK ratified as `MARK VIRTUAL "name"`.** A plain MARK requires its planted text (`MARK:<name>`) verbatim in the op's OWN payload (ERROR otherwise — this is the lint that would have caught W1's one real bug mechanically); VIRTUAL declares a nominal handle with zero in-file bytes and REQUIRES an ASLONG guard (idempotency must rest somewhere). The docs-pair INDEX sweep ops (the one corpus case — `MARK:index-cards` appears nowhere, proven by grep) are rewritten VIRTUAL. Mark uniqueness is pair-scoped: unique within a file; cross-file reuse legal only between DIRECTION-opposed commands.
- **D25 — New-by-example spellings RATIFIED as first-class grammar:** `REMOVE` (consumed mark), `DELETE FILE IF PRESENT` (a content-distinguishing ASLONG required — the canonical-for guard pattern), `ASSERT FILE … EXISTS` + `ABSENT` (correction: EXISTS is already W1 corpus, add-plugin:197 — only ABSENT debuts), positive-polarity ASLONG on remove ops (via D23), CountBefore/CountAfter (via D22). `SNIPPET`/`USE` stays in the grammar with zero corpus instances — exercised by synthetic fixtures only.

Fence lines are flush-left and never part of the payload. CREATE implies `mkdir -p` — README engine prose, NOT a W2 lint.
