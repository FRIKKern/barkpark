# Scaffy Epic — Charter

The epic's memory. Every wave reads this before it plans. Wave Paper (living story) per wave; this file is the durable spine.

## Vision

**Scaffy = commands as content.** A command is a `.scaffy` file: a declarative, idempotent, reversible scaffolding document that CREATEs a vertical slice AND injects its wiring into the accretion files a plain generator can never touch (registries, routers, barrels, index files, config maps) — at guarded, marker-planted anchors, closing with assertions that run the repo's own gates. Commands become a Barkpark document type — authored in Studio or as `.scaffy` text, stored, versioned, tagged, served over one connect, executed by `bp`. The doctrine: *every fact has one owner; every derived surface is collected at runtime (plugin behaviour), generated from a manifest (capabilities/tokens/codegen), or applied by a command — never maintained by hand.* Design paper: `/papers/scaffy-commands-as-content` (masterplan, published 2026-07-16). Lineage: the nextgen-cli command concept (see `~/github/nextgen-vscode/ng-test-example.nextgen` for the reference grammar and its known bugs) reborn on a hardened grammar, with Barkpark as the command store.

The epic's north star: `bp add block-type --var BlockName=timeline` → 30 seconds → a new PortableDoc block rendering on all four surfaces, parity at birth. The fast path IS the standard path; standards become executable.

## Decisions

- **D1 — The extension and brand are `.scaffy`.** The format previously sketched as `.nextgen` is absorbed: same sentence-shaped DSL voice, Scaffy name everywhere. No `.nextgen` references in any new artifact; the masterplan paper gets patched (D8).
- **D2 — Wave 1 ships the COMMAND CORPUS + SHOWCASE, no engine.** Full-text, complete, copy-ready `.scaffy` commands — never sketches or elided `…` bodies. Repo home: `scaffy/commands/*.scaffy` + `scaffy/README.md` (doc-tier: human). NO new docs card (7-card hard cap; router gets no new row this wave). Engine (parse/apply/remove) is W2/W3.
- **D3 — The corpus DEFINES the hardened v2 grammar by example.** Binding rules, from the format review: (a) every multi-line anchor/target is fenced (`::: anchor :::`), never bare; (b) every mutating op carries `MARK "NAME"` — first run anchors structurally and plants the mark, later runs anchor at the mark (this is also the remove handle); (c) guards derive from the payload by default — explicit `ASLONG` only when the payload isn't self-identifying, and a guard must match text the op itself writes (the quote-mismatch re-insert bug is the canonical failure); (d) every token resolves to a declared `VARIABLE` (spelling-as-transform casing allowed: `{{.BlockName}}`/`{{.block-name}}`/`{{.blockName}}`); (e) shared payloads use `SNIPPET`/`USE`, never paste-twice; (f) commands close with `ASSERT FILE … CONTAINS` postconditions and, where a real gate exists, `ASSERT CMD` invoking it (`go test ./internal/pdrender/`, `scripts/docs-anchors-check.sh`); (g) path-position and URL-position tokens of the same variable must agree on casing.
- **D4 — Command set: 6–8 commands covering what Barkpark development actually repeats.** Mandatory flagship: **add-block-type** (Go renderer + test + `DefaultRegistry` map line in `internal/pdrender/pdrender.go` (~L241, `r.blocks["…"] = …`), Elixir clause reachable from `render.ex` `render_block/2` (~L182), JS registration in `js/packages/react/src/blocks/registry.ts`, edit CSS in `root.html.heex`). Mandatory symmetry pair: **add-docs-card + remove-docs-card** (routing-table row in `CLAUDE.md` + card file with `doc-tier` header; the 7-card cap makes remove non-optional). Strong candidates for the rest, DECIDE picks: **add-plugin** (behaviour module + minimal slice `plugins/<name>/{cli,…}.ex` + migration — CREATE-heavy since `discover_and_register/0` auto-collects; encode the canonical minimal callback set, cf. tickets' slice), **add-oban-worker** (worker + test + crontab entry in `api/config/config.exs` `Oban.Plugins.Cron` block ~L223), **add-cli-verb** (one entry in a plugin's `cli_commands/0` list, cf. `tickets.ex:311` — showcases "architecture already made this a one-liner"), **add-migration** (timestamped `api/priv/repo/migrations/` — timestamp arrives via `--var ts=…`, commands have no clock), **add-schema-type**, **add-api-route-parity** (route + SDK method + capabilities — router.ex is ordering-hostile: marks mandatory, mount only in a plugin `register_routes` context if too risky). 
- **D5 — Every anchor is VERIFIED, with evidence.** For each `IN` file and each structural anchor, the builder greps the live tree and records `file:line` + quoted context in the task's acceptance evidence. A command referencing a nonexistent anchor = failed criterion. Where a stable anchor is missing, the command may specify planting one — but the FIRST-run structural target must exist today.
- **D6 — Showcase paper, premium, native blocks.** New paper (slug `scaffy-command-showcase`), same block vocabulary as the masterplan paper (eyebrow/ingress/stats/diagram/terminal/callout/table/code). Per command: what-it-does paragraph, annotated file tree (● created / ○ injected), the FULL `.scaffy` text in code blocks, a terminal mock of run + idempotent re-run, and for the symmetry pair a remove demo. Publish wall: description + registered distinct-strength tags (`scaffy` tag EXISTS in the registry; main_tag scaffy). Ingest: POST `/v1/plugins/bulldocs/papers` with native `blocks` (admin token works — admin-can-call-ingest is deployed).
- **D7 — Hand-traceability is the wave's quality bar.** No engine exists yet, so a reviewer must be able to apply any command manually: unambiguous anchors, exact payloads, explicit occurrence (`FIRST`/`LAST`) whenever an anchor could match twice.
- **D8 — Patch the masterplan paper.** `/papers/scaffy-commands-as-content`: replace `.nextgen` mentions with `.scaffy`, link the showcase paper. Same ingest path re-POST (full blocks re-ingest keyed by slug).
- **D9 — Merge lane.** Wave-1 repo artifacts are new files only (`scaffy/**`, charter) — no `.ex/.exs/.heex/api-assets` touched, so PRs merge on their own gates without waiting for the Elixir Test lane. PR body carries `Task: <id>`. ### Wave-2 DECIDE (2026-07-16) — D20–D32, locked on run-proofs (matcher fork parsed with Elixir, lint dry-run over the live corpus, tsc/vitest greened in a fresh worktree, gh API protection checks)

- **D20 — REPLACE matcher pinned: byte-exact fenced-bytes.** The anchor matches the exact fenced bytes wherever they occur; REPLACE swaps ONLY those bytes — never the enclosing line/region. Proven on real config.exs: whole-line match fails clean on run 2 (accretion impossible); substring-consume-whole-line reproduces the recorded SyntaxError (task-5901b9eff006f553); byte-exact splice parses across 3 runs. - **D21 — Run-≥2 re-anchor is first-class syntax: `REANCHOR "<mark-name-prefix>"`** — optional clause directly after `MARK` on REPLACE. Semantics (README-pinned, engine-independent): when any planted `MARK:<prefix>…` exists in the target file, the effective anchor is the LAST planted block of that family (the mark comment line + its marked payload line(s)) and WITH re-emits that block + separator + the new block; otherwise the fenced structural target applies (run 1). Proven: mark-scoped re-anchor yields FORWARD order (Foo→Bar→Baz), parses, and the ASLONG guard keeps same-worker re-runs no-op; the planted mark line is the ONLY safe key — a naive "last `Workers.X` tuple" tail-finder grabs the pre-existing non-scaffy TagDistribution tuple (config.exs:232). Corpus: add-oban-worker AND add-cli-verb (same defect class — its comment promises mark re-anchoring its op cannot express) gain `REANCHOR`. Lint upgrade (E-005): a self-consuming REPLACE (target ⊂ its own payload) without BOTH a payload-derived ASLONG and a REANCHOR is an ERROR.
- **D22 — VARIABLE annotations become grammar — ONE ruling for the opaque/pair/shape trio.** Optional structural keywords between the quoted name and TITLE: `OPAQUE` (value never re-cased; references use exactly ONE token spelling per file — any legal joiner-output of the declared name — and are exempt from path-casing lints), `SHAPE "ts14"` (named shape catalog; `ts14` = exactly 14 ASCII digits forming a real UTC YYYYMMDDHHMMSS instant — D16 discharged as code), `SUCCESSOR "CountBefore"` (value = named sibling + 1; validator lints EXAMPLES pairs — the +1 lint the corpus prose already requests). Corpus edits: Ts → `OPAQUE SHAPE "ts14"`; TableName/ColumnName/ColumnType/Summary/PathTemplate/CronExpr/Group/TaskPattern/CountBefore/CountAfter → `OPAQUE`; CountAfter additionally `SUCCESSOR "CountBefore"`. ### Wave-3 DECIDE (2026-07-16) — D33–D43, locked on live run-proofs (static-K splice byte-clean on the real targets, all 9 LOCAL ASSERT CMDs executed via sh -c, E-013/014/015 runtime probes fired, CLI run/remove stub full-suite green)

- **D33 — D21 extent rule PINNED: static-K-from-template.** A planted mark-family block's extent is K lines, where K = the UNSUBSTITUTED template's line count from the mark-comment line through the payload's last line (cli-verb K=19: mark + 18-line map; oban K=2: mark + tuple). Substitution is line-count-invariant, so run-N re-anchor needs NO prior-run vars, NO receipt continuity, NO brace-balancing. Proven live: 3× cli-verb + 2× oban splices parse at every step and retract to `git diff --stat` EMPTY; the mark-scoped finder correctly ignored the pre-existing non-scaffy TagDistribution tuple (config.exs:232). Corollaries, binding: (a) **--var values MUST be single-line** — the engine rejects newline-bearing values (usage error, exit 2), else K-invariance dies and every future re-anchor of the family is poisoned; (b) splice mechanics: find the LAST line carrying the family mark comment; the separator comma is edited in-place onto the prior block's closing line (byte-adjacent to the brace, never line-start); the engine asserts the prior block's tail-line shape before splicing — fail loud on desync.
- **D34 — Byte-clean is THE remove gate; parse-only gates are vacuous.** Proven: Elixir parses `[1,2,3,]`, so a K-line remove that leaves a stray trailing comma PASSES a parse gate and only `git diff` catches it. Every remove acceptance check is `git diff --stat` empty; parse checks are supplements. (With D35 fat receipts, comma restoration is implicit in the post→pre image swap.)
- **D35 — Receipt schema: uniform FAT (store-resolved-images), one receipt per run.** REANCHOR run-≥2 REPLACE pre-images are a SIBLING run's payload — never derivable from the removing run's own vars (Strategize's "tree alone" holds for anchoring, NOT remove-reversal) — so fat is mandatory on the hard case; uniform kills op-kind branching and decouples remove from `.scaffy` source drift. Per op: kind, resolved path, resolved mark name, post-image bytes + sha256; REPLACE-family adds pre-image bytes; CREATE records written-bytes sha. Envelope: receipt_version, command path + source sha256, direction, resolved var map, timestamp. Location: `<repo-root>/.scaffy/receipts/<concept>--<primary-var-kebab>--<sha256(sorted resolved k=v)[:12]>.json` — cwd = repo root, the same resolution every `IN` path already uses; per-command+vars keying so two oban receipts coexist and retract independently. `.gitignore` gains an explicit `.scaffy/` line (house explicit-name convention).
- **D36 — Remove dispatch: `bp scaffy remove <add>.scaffy --var …` = RECEIPT REPLAY** (load the receipt keyed command+vars, invert ops in reverse) — the only path that can satisfy the north star (5 of 6 add commands have no authored inverse). DIRECTION-remove commands (remove-docs-card) are `bp scaffy run` targets, first-class, never objects of `remove`. Drift-refusal per op before inverting: post-image present + hash match → invert; post-image absent but pre-image present → already retracted, clean skip (exit 0, idempotent remove); neither / multiple matches → REFUSE fail-loud `file:line: SCAFFY-DRIFT …` (exit 5) — never fuzzy-match, never partial-apply. LIFO within a mark family falls out of drift-refusal (removing an earlier sibling first finds its post-image mutated → the error names the later sibling); receipts across commands/files are order-free.
- **D37 — D22 runtime contract for `--var`.** SUCCESSOR: the LAW wins over the Strategize draft's "derived +1" — the caller supplies BOTH flags (`--var CountBefore=42 --var CountAfter=43`); the engine CHECKS after==before+1 (mirroring E-014), never computes silently. SHAPE ts14 is re-validated against the actual supplied value at run time (proven: E-013/014/015 are source-text lints over declared EXAMPLES; no runtime path exists). OPAQUE substitutes verbatim, never re-cased. Transform vars resolve via words.go's unexported joiners — the engine lives in package `internal/scaffy`, zero new exports. Pre-apply gate: `ValidateFile` == zero findings, never bare `Parse` (partial ASTs on dirty input). SNIPPET/USE byte-resolution is engine work with its own dedicated apply tests against `testdata/green/add-widget.scaffy` (it inherits zero protection from corpus_test.go).
- **D38 — ASSERT CMD exec: `sh -c '<verbatim Assert.Text>'` from repo root; `Env = append(os.Environ(), "CC=/usr/bin/clang")`; default per-CMD timeout 900s.** Proven: argv-split or cd-strip mis-executes 8 of 15 CMDs (cd-chains + inline `CC=` prefixes need a shell); trailing `#` comments are sh-native; never pre-cd (strings carry their own `cd`). Asserts run AFTER all ops apply (add-widget's `go build ./internal/widgets/` target doesn't exist pre-apply — proven).
