## Vision

Any AI agent — Claude Code, Copilot, Cursor, Codex, a generic MCP client — goes from zero to installed + logged-in + creating on Barkpark in ONE step per surface. Wave 1 made `bp onramp` a teleprompter (print-first configs for six targets + five premium docs). Wave 2 makes it DO the work: `--write` merges the barkpark stanza into the user's config without touching anything else they put there, re-runs say "unchanged" and exit clean, and every write reports exactly what it created/updated/skipped — in text and `-o json`. The idempotence contract IS the product: an emitter that clobbers a user's mcp.json once poisons the whole "one step" promise. Wave 2 also lands the two highest-reach emitters: Copilot (`.vscode/mcp.json`, ~20M users) and the canonical consumer AGENTS.md (the ~23-tool convergence standard, the only path to Aider) — collapsing three drifting teach texts into one gate-enforced source.

- **D2 — Copilot stanza: top-level `servers` + `type:"stdio"` + `${env:BARKPARK_API_TOKEN}` via its OWN `copilotTokenRef` constant; no `inputs` array emitted.** *Why:* VS Code's workspace MCP file keys on `servers` (NOT `mcpServers`) — the one structural difference from every sibling; the env-ref keeps the secret in the shell like all wave-1 targets (decision-9 named-constant precedent: value equals `cursorTokenRef`, constant never shared); `inputs`/promptString is COPILOT.md prose, not emission. Leak-guards adapt: copilot legitimately shares `${env:}` with cursor, so the discriminating asserts are contains-`servers` + NOT-contains-`mcpServers` + contains-`type: stdio`. Live-pin the shape against current VS Code docs before freezing the golden — this surface churned during preview (mcpServers→servers).
- **D3 — The canonical AGENTS.md is emitter OUTPUT, never a barkpark-committed asset.** It lives as a Go constant + `internal/cli/testdata/agents_md.golden` (depth ≥3 escapes docs-anchors §4's maxdepth-2 AGENTS.md scan; `.golden` matches repo convention). *Why:* repo-root `AGENTS.md` is the shell-danger-rules doc at 698B of a FROZEN 700B cap — the slot is spoken for, and any shallow committed AGENTS.md trips §4 header + §5 slug + budget gates. Its existence is also the proof the emitter must marker-merge: a real consumer AGENTS.md routinely already holds unrelated content.
- **D4 — The SUPERSET survives the wrapper collapse.** Ground truth (byte-diffed): the cursor/claude wrappers differ in exactly 2 lines, but CODEX.md's AGENTS.md block is a reworded LOSSY subset (dropped `bp task prime`, the Conventions header, the parent_id nesting line, the 409 `doc_changed_since_claim` line). All three wrappers become framing + canonical body + ≤2 target-specific lines, and a Go parity test reads the three files so drift reds CI. *Why:* collapsing to the drifted subset silently loses content; a test makes the dedup permanent.
- **D5 — `--write` mechanics: key-parametrized RawMessage merge, per-file strategy, atomic 0644.** One merger over `map[string]json.RawMessage` touching ONLY the barkpark entry, parametrized by top-level key — THREE shapes exist, not one: `mcpServers`-map (cursor/claude-code/windsurf/gemini-cli), `servers`-map (copilot), and cursor-cloud's flat `install` key in environment.json; cursor-cloud emits two files, so strategy metadata rides `onrampFile` as omitempty fields (the print `-o json` contract stays byte-stable, TestOnrampJSONShape green). Temp-file+rename per the SaveConfig idiom (config.go:229) but dir 0755 / file 0644, NOT 0600 — these are project-committed configs holding an env placeholder, not secrets. Actions: created / updated / unchanged / skipped(+"use --force"); report via machineOut in both modes. Codex TOML write stays wave 3 — NO TOML dep lands; its file reports "skipped".
- **D6 — Marker-managed markdown blocks.** `bp onramp agents-md --write` wraps the block in `<!-- barkpark:onramp:begin/end -->`: no file → create; file without markers → APPEND (never rewrite user content); markers present → replace between them only; identical → "unchanged", exit 0. *Why:* the same idempotence law as JSON, expressed the only way markdown allows.
- **D7 — Integration order: copilot ∥ docs-debt ∥ write-plumbing in parallel; agents-md LAST.** agents-md routes its `--write` through the write slice's exposed seam (rebases on its merge); copilot and the write slice cross-stamp merge metadata on whichever merges second. *Why:* agents-md + write-plumbing both touch the runOnramp flag loop — sequencing beats a merge war; everything else is disjoint-region parallel (the two hub-row edits and two CODEX.md edits are different regions, trivial rebases).
- **D8 — Docs stay inside wave-1 law.** COPILOT.md + AGENTS-MD.md are human-tier G1-headed docs (slugs `copilot-onramp`, `agents-md-onramp` — verified unused), NOT budget-capped (decision 11), NOT cards (7-cap untouched), NOT in docs/INDEX.md (1200B cap, 3B headroom). Linkify uses RELATIVE filenames from inside docs/setup/ (§3c resolves against the linking file's own dir — a `docs/setup/...` path from within docs/setup/ REDS CI); config-filename backticks (`AGENTS.md`/`CLAUDE.md`/`GEMINI.md`) stay backticks.
- **D9 — Onramps-charter decision 8 reconciled in writing (epic acceptance criterion).** The amendment (committed by the agents-md slice into bp-agent-onramps-charter.md): the wrapper-NAME dodge stands unchanged; the canonical emission is NOT a repo-shipped asset (D3's gate math); marker-merge exists precisely because consumer AGENTS.md files pre-exist — barkpark's own root file is the living proof.
