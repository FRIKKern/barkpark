## Vision

Any AI agent — Claude Code, Copilot, Cursor, Codex, a generic MCP client — goes from zero to installed + logged-in + creating on Barkpark in ONE step per surface. Wave 1 made `bp onramp` a teleprompter (print-first configs for six targets + five premium docs). Wave 2 makes it DO the work: `--write` merges the barkpark stanza into the user's config without touching anything else they put there, re-runs say "unchanged" and exit clean, and every write reports exactly what it created/updated/skipped — in text and `-o json`. The idempotence contract IS the product: an emitter that clobbers a user's mcp.json once poisons the whole "one step" promise. Wave 2 also lands the two highest-reach emitters: Copilot (`.vscode/mcp.json`, ~20M users) and the canonical consumer AGENTS.md (the ~23-tool convergence standard, the only path to Aider) — collapsing three drifting teach texts into one gate-enforced source.

- **D11 — Prefix-aware span ownership (the kill-switch fired and this is the fix, not a lib).** LIVE RUN of real `codex mcp add` (codex-cli 0.144.1, sandboxed CODEX_HOME) proved codex writes `env` as a NESTED `[mcp_servers.barkpark.env]` sub-table (alphabetically sorted keys), refuting the flat-only assumption. Law: the owned span = the `[mcp_servers.barkpark]` header table PLUS every `[mcp_servers.barkpark.*]` continuation table, ending at the first header NOT sharing the dotted prefix (or EOF). A sub-table-shaped stanza is a DIFFERING stanza — skipped without `--force`, replaced whole-span with the canonical flat stanza on `--force` — NEVER an error (erroring on codex's own output would be hostile). Root dotted-key form (`mcp_servers.barkpark.command = …`, no header) and inline-table form (`mcp_servers.barkpark = {…}` / `barkpark = {…}` under a bare `[mcp_servers]` header) DO error loudly, file untouched — a textual splice cannot own them safely. Header match is on the header TOKEN (a trailing `# comment` after `]` must not break detection). CRLF and no-final-newline conventions round-trip. Honest contract (goes in doc + report note): every byte OUTSIDE the owned span survives verbatim; `--force` replaces the WHOLE owned span (including any user key inside our table).
