# Preview Contract — epic charter

Epic task: `preview-contract` (published, guerrilla ledger). Design paper: `/papers/preview-contract` on guerrilla.
Wave discipline: worktrees only · api/** waits for the Elixir Test gate · no Co-Authored-By · pr-task-gate needs the PUBLISHED task in_progress + `Task: <id>` on its own line in the PR body.

## Vision

Every Barkpark document presents itself as a rich, branded card — internally and on the open web. ONE preview manifest per document (`content["preview"]`), OpenGraph-shaped, computed at WRITE TIME beside `content["body"]` so it can never drift, consumed by every surface, and emitted outward as og:/twitter:/JSON-LD so a shared guerrilla `/papers` link unfurls beautifully in Slack, Discord, iMessage, LinkedIn. Today the papers reader ships ZERO og tags. That brand failure ends with this epic. The OG moment — paste a `/papers` link into Slack and watch a branded 1200×630 card appear — is the definition of done.

## Decisions

- **D1 — Manifest key + seam.** Manifest lives at `content["preview"]`, computed by new module `Barkpark.Preview` — `project(content, blocks, opts \\ %{})` — stamped INSIDE `Projection.project/4` (projection.ex:131, the sole-writer walk) right after `Map.put("body", ...)`. Why: every projection caller gets it free; coverage and drift profile become IDENTICAL to `content["body"]`'s proven no-drift guarantee. NOT Envelope.render (leaky), NOT anything named after `/v1/preview` (draft tunnel, `PreviewToken`). Note: `project/3` is a shim head — the real walk is `project/4`; the filed task text saying "project/3 at :104" was anchored on the shim.
- **D2 — Purity by injection.** Projection stays Repo-free. Callers that hold Repo + scope (block_ops `maybe_project` :1228 and its other Projection.project call sites; writer.ex scaffold paths :389/:583) put a `:preview` sub-map into the existing `render_opts` map: `%{media_resolver: fun, url: "/papers/#{slug}", doc_type: "paper"}`. The resolver (defined once, `Barkpark.Preview.media_resolver/1`) maps a `/media/files/<path>` src → `Media.get_file_by_path(path, opts)` → `%{"url" => Renditions.url(file, "og"), "width" => 1200, "height" => 630, "type" => "image/jpeg"}`. No `:preview` opts → pure degraded manifest (still valid). Why: keeps the pure contract testable (tests inject stubs) while confining the ONE read-only lookup to callers that already touch Repo. Render.render_blocks ignores the extra render_opts key.
- **D3 — Store RELATIVE urls, absolutize at emission.** Manifest `url` and MediaFile-backed `image.url` are stored as relative paths; emitters prepend `BarkparkWeb.Endpoint.url()` (returns scheme://host with NO internal port — the #1190 fix, test-guarded). Why: a PHX_HOST change must never stale the stored corpus; ogp.me's absolute-URL requirement is an emission concern. External (pasted) image srcs stay absolute as-is.
- **D4 — Exact-crop og rendition.** The `"og"` preset ALREADY EXISTS (renditions.ex:27, since 827a3e90) but is max-fit. Change it to exact-crop: add optional `crop: :attention` to the spec map, extend the ImageBackend `@type`/spec to allow `:crop`, thread it in Vix (`Image.thumbnail(img, w, height: h, crop: spec.crop)` — Image 0.67 supports it) and Magick (`-resize WxH^ -gravity center -extent WxH`). Keep jpg q85. Why: a constant 1200×630 output is the ONLY way the manifest can truthfully hardcode width/height with zero lookup (dimensions live in asset-doc fileInfo as strings, not on MediaFile). Upscaling small sources to fill is accepted — consistent card geometry wins. Renditions build eagerly at upload AND lazily on first GET (media_controller.ex:95), so legacy media need no backfill and pc-w1 triggers no write-time generation.
- **D5 — Branded default card at EMISSION, not in the manifest.** New static asset `api/priv/static/images/og-default.jpg` (1200×630, evergreen brand + wordmark, <300KB). Emitters use it when `manifest["image"]` is nil. Why stored-nil: a later brand refresh must not require a corpus rewrite. Every document unfurls branded, never blank.
- **D6 — Legacy corpus via read-time fallback, no migration.** When `content["preview"]` is absent at render, the reader calls the SAME pure `Barkpark.Preview.project` on the fly. Same function = same bytes = no drift; old papers unfurl on day one. (Write-time stamping only covers block-bearing writes — papers/sheets/forms/layout schemas — exactly `content["body"]`'s set. Classic no-block docs get the read-time path or the default card.)
- **D7 — image object carries 5 fields** `{url,width,height,alt,type}` — the paper's ratified shape (with mime `type`) wins over the task text's 4-field shape; emit `og:image:type`. `alt` comes from the featured BLOCK (media records carry no alt); falls back to doc title.
- **D8 — `type` stays raw; emitters map.** Manifest `type` = raw doctype (`paper`, `sheet`, `task`, …). Emitters map paper/post → `og:type=article`, everything else → `website`. JSON-LD `Article` for paper/post only this wave.
- **D9 — Extensions Ring 3 (typed, sparse).** paper `{published_time, authors[], tags[], section}` · task `{status, assignee, done_ratio}` · sheet `{tab_count}` · ticket `{key, state}`. Stamp only what's available; a core-only manifest is valid (degradation invariant).
- **D10 — NO oEmbed. Anywhere.** Explicit divergence from the design paper's Emission Layer 4: Slack prefers oEmbed over og and a careless endpoint downgrades every card. pc-w4 records the decision; no emitter exists in the repo today (verified) and none may be added.
- **D11 — Description** = explicit excerpt field → first body paragraph plain text → nil; ~110 chars, word-boundary truncation + `…`.
- **D12 — One shared emission helper.** `BarkparkWeb.ShareMeta` (function component or Layouts helper) renders the whole head block: og uses `property=`, twitter uses `name=` (`twitter:card=summary_large_image`), ONE canonical `og:url`, JSON-LD `<script type="application/ld+json">`. Placed immediately after `<title>`, BEFORE the multi-KB inline style blob (Slack reads only the first 32KB). Must be nil-safe: bulldocs.html.heex is ALSO the root layout for non-LiveView renders (share_link_controller.ex:61, scoped_paper) — those paths get the `:preview` assign too (share links ARE the sharing flow), and a nil manifest renders site-default meta, never crashes.
- **D13 — Email render path untouched.** Byte-locked golden. The share heads are reader-layout work only.
- **D14 — Sequencing.** pc-w2 consumes the `Barkpark.Preview.project/3` interface frozen in D1/D7/D8/D9; if pc-w1 is unmerged, the pc-w2 builder branches off pc-w1's branch. Integration order: pc-w1 → pc-w2.
