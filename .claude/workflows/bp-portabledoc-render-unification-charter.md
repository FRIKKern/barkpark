# Charter — Render-Path Unification (PortableDoc → 3 renderers)

Epic task: `portabledoc-blog-epic-goal` · Design paper: `/papers/perfect-portabledoc-blog-next-astro-phoenix`

## Vision

A perfect content blog that renders the FULL PortableDocument block grammar IDENTICALLY on Next, Astro, and Phoenix. Underneath the blog is the real work: collapse the FIVE PortableDoc renderers that exist today to THREE — Elixir (source of truth + block registry), Go/pdrender (the proven TUI twin), and ONE canonical JS renderer living in `@barkpark/react`. Today's five: (1) Phoenix native (`api/lib/barkpark/portable_doc/render/*`, ~50 plugin-free block types, `:article` mode emits bare semantic tags + `bp-*` classes skinned by the one compiled-in `Render.Stylesheet.css/0` sourced from `api/assets/paper-surface/paper-surface.css`); (2) Go/pdrender; (3) `web/components/portable-doc.tsx` (~30-type PRIVATE fork at 3-way structural parity, Tailwind-classed, does not import `@barkpark/react`); (4) `@barkpark/react/src/PortableText.tsx` (a Sanity-shaped renderer keyed on `_type:'block'` — renders 0 of the type-keyed blocks); (5) the Astro/Next starters (render ~nothing).

The finished experience of the FOUNDING wave (Wave 1) is not a blog page — it is a GREEN cross-surface parity test: `@barkpark/react` exports a real type-keyed `PortableDoc({value})` that a cold Next/Astro surface drops in for Phoenix-faithful output, and a harness proves — block by block, every registered non-plugin type — that the JS DOM shape equals the Elixir golden. Blog pages, Astro SSR consumption, Next multipage/basePath, and deleting the `web/` fork all come AFTER `@barkpark/react` reaches parity.

## Decisions

- **D1 — PORT logic, REWRITE every className.** Seed `PortableDoc` by lifting `web/portable-doc.tsx`'s block dispatch + prop-parsing, but rewrite every className from Tailwind to the exact `bp-*` vocabulary `walk.ex` emits and wrap the root in `.bp-paper-surface`. *Why: the web fork is structure-parity but 0/30 cases emit `bp-*` classes; a fresh rewrite reopens parity risk while the class swap is mechanical.*
- **D2 — New `PortableDoc` export from BOTH `index.ts` and `server.ts`; `PortableText` stays the legacy shim; extend the exports-guard tests.** *Why: `PortableText` is the Sanity shim (keep untouched); the type-keyed renderer is net-new and must be RSC-safe (context-free) so it ships from both entries.*
- **D3 — Reference.tsx is NOT a Wave-1 fix; it is a guarded regression.** The `react-server` `createContext` break is already contained (`server.ts` type-only-exports from `Reference`; `dist/server.mjs` is 195B; 71 tests green). Wave 1 only keeps the guard green by adding `PortableDoc` context-free to both entries + listing it in `exports-server.test.ts`. *Why: two surveyors ran the build — nothing to fix, only a regression to guard.*
- **D4 — Inline marks emit `<span style=…>` + bare `<code>`/`<a>`, NOT `bp-*` classes.** `walk.ex` renders bold/italic/underline/strike/color as inline-style bare spans (no class ever, nested one-span-per-mark, first-mark-outermost) and `:article`-mode code/link as bare class-less tags styled by `.bp-paper-surface code`/`a` element selectors. The ONLY class a text span ever carries is `bp-role-{eyebrow,byline,ingress,pullquote}`. *Why: the wish's "same bp-* classes" is FALSE for marks; inventing `bp-mark-*` would DIVERGE from the golden. Parity target = same inline-style attribute + same bare-tag shape.*
- **D5 — diagram + asciicast are `_raw` byte-exact passthrough, NOT class-migrated.** Emit `<figure …><pre class="mermaid">{entity-encoded source}</pre>{figcaption}</figure>` (and the `div.bp-asciicast` mount point) matching `figures.ex`'s inline-style escape hatch. Fixing the web fork's diagram regression (missing `class="mermaid"`) IS in scope as a ~10-line static-shape fix; loading mermaid.js/asciinema at runtime is a consuming-app concern (deferred). *Why: Elixir special-cases these as `_raw`; the `pre.mermaid`/`div.bp-asciicast` selectors need exact markup.*
- **D6 — CHAT: fix the tokens, keep chat IN Wave-1 parity (Option a).** `paper-surface.css` gains the 5 missing base tokens — `--primary`, `--muted-surface`, `--border-muted`, `--fg-dim`, and `--font-mono` (aliasing the existing `--paper-font-mono`) — light+dark, scoped under `.bp-paper-surface, .bp-paper-body` (same block as the existing `--ok`/`--danger` tone tokens at ~L369), values lifted from `root.html.heex`'s default theme. Chat markup stays `_raw` byte-exact (no rewrite). This slice edits `paper-surface.css` = source of `Render.Stylesheet.css/0`, so it runs through the view-edit-parity gate and also fixes the latent `/papers`-reader chat-styling bug. *Why: cheapest correct fix (~10 lines of tokens, no renderer change), keeps port-don't-rewrite intact. Caveat: computed-color parity holds only vs the default theme; shape-parity holds unconditionally.*
- **D7 — Kitchen-sink array = 42 in-scope types; the 14 schema-field/embed types are OUT.** `compose.ex` dispatches 56 distinct types; `field-{string,slug,text,boolean,select,datetime,color,reference,image}`, `composite`, `arrayOf`, `codelist`, `localizedText`, `embed` have ZERO web-fork seed, are schema-editor renderers not blog grammar, and are never named in the wish. Keep BOTH members of the 3 alias pairs (`questionnaire`/`form`, `stat-grid`/`stats`, `task-list`/`tasks`) so the harness exercises alias dispatch. *Why: cutting them keeps the array at the exact 42 that are port-seedable and blog-relevant; the OUT set is one grep-`excluded`-string edit from being pulled back.*
- **D8 — "Generated from the registry" = hand-authored array + a bash completeness grep-guard.** There is NO registry data structure (103 pattern-match clause heads). The kitchen-sink array is hand-authored; a guard greps `compose.ex`'s `"type" => "X"` clause heads + `t in [...]` guard members, subtracts the `excluded` set, and fails CI if any in-scope type is missing from the array. The guard MUST carry `#!/usr/bin/env bash` and be invoked with `bash` — under zsh it word-splits vacuously and passes covering nothing (a distrust-vacuous-green trap). *Why: that guard IS the anti-drift mechanism; a reflection generator is unbuilt, riskier, unprecedented.*
- **D9 — Reuse the golden MECHANISM as a PATTERN in a SIBLING task; build the comparator + HTML golden fresh.** Model on `barkpark.paper_components.gen_golden_parity` (pure `build/1` → 3-mirror byte-equal write → freshness lock → realization loop), do NOT extend it in place: that generator emits semantic JSON projections for 13 component types; Wave 1 needs a frozen per-type golden + a DOM-shape comparator for 42 core+gap types. The wish's "pc-w4-parity-gate" names `barkpark.preview.gen_parity` — right doctrine, wrong artifact. *Why: different artifact, different type set; "reuse the mechanism" is satisfiable at the pattern level.*
- **D10 — Parity is SHAPE-equal, not byte-equal.** Elixir HEEx and JS SSR HTML never match byte-for-byte. Each runtime freezes its own snapshot (Layer 1); a Layer-2 comparator asserts DOM shape — tag + class-SET + `data-*` + text, node-for-node. This comparator is net-new and STRICTER than any repo precedent (Go asserts only text presence/order). *Why: matches the shipped Go precedent, whose golden is shape-equal to Elixir's.*
- **D11 — Ship `paper-surface.css` as a plain-file COPY via tsup `onSuccess` → `dist` + an `exports` subpath, NEVER inlined into the JS bundle.** It gzips to 15.9KB — inlining blows both size-limit budgets. Copy at build time to `dist/paper-surface.css`, add `"./paper-surface.css"` to `exports`; it does not count against size-limit (`path` targets `dist/index.mjs` only). *Why: one source of truth stays authoritative; the JS copy is derived, not hand-mirrored.*
- **D12 — Add a byte-identity drift guard for the shipped CSS; accept turbo may serve stale on CSS-only `api/` edits.** `api/assets/paper-surface/paper-surface.css` lives OUTSIDE `js/`'s turbo+pnpm workspace, so turbo's build-cache hash never sees it. Rather than vendor a checked-in copy (defeats one-source-of-truth), keep the `onSuccess` fs-copy AND add a mirror-check test asserting `dist/paper-surface.css` is byte-equal to the api source. *Why: the drift guard is the real safety net, not turbo's hash.*
- **D13 — size-limit: add a named `PortableDoc` entry and set budgets off ACTUAL usage (1.2KB / 3.1KB), not the digest's wrong 8KB/15KB.** Those numbers are the configured LIMITS; real usage is far lower. A ~42-type renderer will grow the bundle — raise the total deliberately with headroom from a measured prototype. *Why: pick the new number from evidence, not from the misread baseline.*
- **D14 — task-board and sheet are IN the array but are REWRITES sized like gap types, not near-zero ports.** task-board's web case is 100% Tailwind + a LiveView spinner (discard both; reuse only the role-bucketing/label logic; write fresh `bp-board__*`/`bp-bcard*` JSX). sheet's web case delegates to `SheetSnapshot` (a 514-line interactive widget with a categorically different DOM — row-number gutters, checkbox glyphs); do NOT import it — write a fresh table renderer from `walk.ex`'s `sheet/3` algorithm targeting `bp-table`/`bp-sheet__th`/`bp-sheet__td`. *Why: budgeting them as ports overruns; `SheetSnapshot`'s chrome can never shape-match the plain `bp-sheet` table.*
- **D15 — status/role classes are sourced from `design/status-manifest.json`, not hand-copied.** `bp-board__col--<role>`/`bp-rm__bar--<role>`/`bp-g--<role>` key off the dynamic role ladder (`open/ready/progress/blocked/done/cancel`) compiled from the manifest. A JS port that hand-copies drifts when the manifest gains a role. Wave 1 may hand-author the current ladder but MUST add a drift note/guard. *Why: the Elixir side is compile-time-generated specifically to prevent this drift.*
