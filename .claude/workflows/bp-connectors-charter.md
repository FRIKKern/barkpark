# Barkpark Connectors — Epic Charter

Make it a first-class, two-minute product action to connect a Barkpark agent to an external
service. Design paper: `/papers/personal-agent-provider-bridge`. Epic: `bp-connectors-epic`
(task `task-e640bb01fca6ea38`).

## Vision

A Barkpark workspace connects an agent to the services its people already use — you TALK TO the
agent from Slack/Discord/Telegram/Teams/WhatsApp/iMessage, and the agent ACTS ON GitHub/Linear —
through one provider-agnostic core, with a Barkpark **Session as the durable cross-surface memory**
(start on Slack Monday, continue on Discord Friday, same thread). Cloud multi-tenant from day one:
each workspace installs its own connectors, credentials isolated, the agent runs sandboxed with
NO host access. The brain and most of the plumbing already exist — this epic builds the *connect
experience* on top of them, not a new engine.

## Two directions, one catalog

- **Channel connector** = inbound, you talk to the agent → **Vercel Chat SDK** adapter (`chat` npm).
- **Tool connector** = outbound, the agent acts → **MCP** (Barkpark already serves MCP via `bp mcp serve`; the mirror is the runner consuming an external MCP).

## Decisions

Tagged **[RATIFIED]** = user/design decision, locked. **[VERIFY]** = must be proven by the verify
fleet with run output before a builder relies on it (distrust vacuous green). **[DECIDED]** = settled
at a wave's Decide with verify rounds in hand.

- **D1 [RATIFIED] — Cloud multi-tenant from day one.** Every workspace connects its own services; credentials + sessions isolated per workspace.
- **D2 [RATIFIED] — Channel-first.** The first shipped direction is Channel connectors; Tool connectors (GitHub/Linear via MCP) follow.
- **D3 [RATIFIED] — Six first-focus channels, grouped by ONBOARDING not code.** Easy trio (Telegram, Slack, Discord — light official adapters, prove the core) → heavy pair (Teams = Azure Bot reg + Bot Framework; WhatsApp = Meta Business + number + app review + 24h session window) → **iMessage = self-hosted operator profile ONLY** (community adapter, Apple has no server API, needs a Mac + Apple ID relay; does NOT fit Cloud multi-tenant).
- **D4 [RATIFIED] — External Node bridge on the Chat SDK, not three protocols in Elixir.** One codebase, swappable adapters, streaming piped from Barkpark SSE. The BEAM stays the engine; the bridge is a client of `/v1/chat`.
- **D5 [RATIFIED] — Two execution profiles behind one Connector/Session layer.** Self-hosted/operator = the `claude` CLI subprocess, full host access, `bypassPermissions` OK, gate = your user-id. Cloud tenant = a **sandboxed runner per workspace**, no host access, connector-scoped tools, gate = external user → workspace principal. This **reverses** `bypassPermissions` for Cloud (it survives only self-hosted).
- **D6 [RATIFIED] — Session = memory, keyed by the Claude session UUID (`chat_sessions.id`).** A thread ↔ session map (`thread_id → session_uuid`) is the only per-conversation state the bridge holds. The SAME session is reachable from any channel by its UUID (cross-surface continuity). See D31 for the wave-3 scope refinement (automatic thread→session mapping is per-CHANNEL; true cross-CHANNEL resumption needs identity-linking, deferred to P4).
- **D7 [VERIFIED — total leak] — Session ownership migration.** Proven: `chat_sessions`/`chat_messages` had ZERO owner/workspace column on origin/main; Slice A added `owner_workspace_id` (nullable `binary_id`, no FK, no default) + sealed the store funnels. See D14–D17.
- **D8 [VERIFIED — ALREADY MERGED] — `/v1/chat` HTTP+SSE transport is on main and live.** PR #2857 (commit `0b699edf`) merged an 8-route ChatController (CRUD + send/interrupt/approval + SSE) to origin/main; guerrilla answers 401 not 404. **All builders branch off freshly-fetched `origin/main`, never local HEAD** (the shared primary checkout drifts). See D18.
- **D9 [VERIFIED — premise CORRECTED, deferred to P1] — Per-workspace OAuth install + routing.** run-secrets is NOT workspace-scoped — it is a flat instance-global `name→value` KV (`secrets`, PK `:name`), gated global `:require_admin`. Real per-workspace scoping needs a new `workspace_id` column + scoped-admin gating — build work, filed P1 (`task-5766dc5ca985ddc8`), NOT a P2 gate. The `provider_team_id → workspace` map lands with P2/P3 routing (see D29 — the bridge owns it, no Elixir change).
- **D10 [RATIFIED — Wave 2, measured] — The sandbox runner = Vercel Sandbox (Firecracker microVM), snapshot-baked `claude` image + warm pool.** `Port.open` → a sandbox exec on the SAME `{exe,args,env,cwd}→NDJSON` contract. Measured headless: fresh create 7.54s; per-boot npm install 7.50s → per-boot-install DEAD; snapshot bake 5.52s (one-time); create-from-snapshot 3.02s + ~0.6s claude ≈ 3.6s claude-ready. Model first-token in-sandbox is human-gated (D23). Rejected: raw containers. Retained as documented complement: plain Messages-API agent.
- **D11 [RATIFIED] — Notion is OUT.** Not a messaging surface; if ever wanted, it is a Tool (MCP), never a channel.
- **D12 [RATIFIED] — Streaming cadence starts post-once-per-turn** (rate-limit-safe), live-edit-on-throttle is a later refinement. See D26 for the SDK mechanics: there is NO `thread.stream()`; post-once = accumulate the SSE reply and call `thread.post(finalText)` ONCE.
- **D13–D20 — Wave 1 = P0 decisions.** (Migration additive/greenfield; `scope_to_workspace/3` fail-closed semantics; external principal = workspace-bound `ApiToken` with a `chat` permission, NOT airdrop Grant/ClaimFlow; seal at the STORE layer; new `RequireChatAccess` plug resolves `:global` vs `{:workspace, ws}`; mandatory cross-tenant LEAK negative test; hold the line on D10.) SHIPPED grade A- (PR #2857). Full text preserved in the Wave 1 wave-log commits on `loop-epic/connectors-w1-wavelog`.
- **D21 [RATIFIED — Wave 2] — The 10s bar is a Barkpark UX goal, NOT a Linear correctness gate.** Split: (a) **ack-latency ≤10s** = the P2 bridge's job (ack-first, boot-async — a HARD P2 requirement, folded into the turn loop, see W3 Slice 3); (b) real-turn ≤30min = trivially cleared. Barkpark ADDS a self-imposed UX target (first real token ~10s of the ack on the warm path) as a product goal.
- **D22 [RATIFIED — Wave 2] — Warm pool is a UX-latency lever, not a correctness requirement.** Reuse the dwb-10 warm-pool mechanism + a new per-workspace/region shard column. Filed to P1-runner-build backlog.
- **D23 [RATIFIED — Wave 2] — Model first-token is human-gated; name the command, never fabricate.** Env-injection seam PROVEN in-sandbox (no key → `Not logged in`; bogus key → `Invalid API key`). Human-gated: `vercel sandbox exec <vm> --env ANTHROPIC_API_KEY=<key> -- bash -lc 'time claude -p "say ok"'`.
- **D24 [RATIFIED — Wave 2] — Reversing `bypassPermissions` for Cloud is a 5-knob build**, not a flag flip (structural unreachability; Cloud `--disallowedTools`; connector-scoped `bp mcp serve --tools <subset>`; connector-grant-scoped token mint; unattended auto-approval policy). Depends on the D9 secrets-scope fix. Filed to P1-runner-build backlog.
- **D25 [VERIFIED — Wave 2] — The runner is a thin `chat`+`workspace_id` HTTP+SSE client; no new Barkpark-side API work.** Proven on origin/main (`chat_controller_test` 42/42; cross-tenant 404 oracle). Minimal credential = the `chat` permission + non-nil `workspace_id`.

## Wave 3 = P2 — decisions (D26–D33, DECIDED with two verify rounds in hand)

The verify fleet scratch-installed `chat@4.34.0` + adapters and read the real `.d.ts`/`.js`, ran
`chat_controller_test` (42/42), and re-checked git/CI freshness. The keystone premise correction:
**there is NO `thread.stream()`.** Everything below is grounded in run output (see the wave Paper
`connectors-wave-3-2026-07-14`). The whole wave is a Node/TypeScript build; P2 ships ZERO `.ex`
changes (D33). The zero-core-change-for-P3 invariant IS the acceptance bar.

- **D26 [DECIDED — keystone SDK correction] — Streaming is `thread.post()`, not `thread.stream()`.** `thread.stream()` does NOT exist (proven: `ThreadImpl` in `messages-BSoJG691.d.ts:468-469` exposes only two `post()` overloads; the only public `stream` symbol is a `StreamingPlan` property). The public overload is `post(message: string | AdapterPostableMessage | AsyncIterable<string> | ChatElement)`. **For D12 post-once-per-turn: accumulate the `/v1/chat` `event:chat` frames into one final assistant string, then call `thread.post(finalText)` exactly ONCE per turn.** The clean turn-end signal is the stream-json `type:"result"` frame (has `.result` + `stop_reason`), NOT `event:exit` (exit = subprocess died; the stream stays open for lazy resume — never treat exit as turn-completion). Pin `chat`, `@chat-adapter/telegram`, `@chat-adapter/state-pg` **all at `4.34.0`** together (they dedupe to a single `chat@4.34.0`).
- **D27 [DECIDED — HOME] — Standalone `connectors/` Node service at repo root** (sibling to `web/`, `api/`, `js/`), `private:true`, its own `package.json` + `package-lock.json` (**npm**, proven installable — 184 pkgs, `tsc --noEmit` + `vitest run` both exit 0 against the real SDK types), its own `vercel.json` mirroring `web/`. NOT a `js/` package (js/ is a changesets + size-limit publish-only SDK monorepo; the bridge is a deployable service, not a published lib). **Kept OUT of the root `pnpm-workspace.yaml`** (which lists only `web` + `js/packages/core`) and **MUST NOT** add a nested `pnpm-workspace.yaml` (it shadows the root and breaks `pnpm install`). Tradeoff accepted: the bridge cannot free-ride `js/test-utils`; it vendors its own `vitest`+`msw` and copies the SSE-mock PATTERN from `js/packages/core/tests/fixtures` (pattern, not module). Keeps P3's zero-core-change promise scoped to files under `connectors/` only.
- **D28 [DECIDED — state] — The `thread_id → session_uuid` map is a BRIDGE-OWNED dedicated table** `chat_bridge.thread_session_map (workspace_id, thread_id, session_uuid, created_at, PRIMARY KEY (workspace_id, thread_id))`, queried directly via the bridge's `pg.Pool`. **Do NOT ride `thread.setState`** — it hardcodes a 30-day TTL (`THREAD_STATE_TTL_MS = 30*24*60*60*1e3`, `index.js:510`), so an idle thread silently loses its Session. `@chat-adapter/state-pg` is STILL configured as the SDK's `StateAdapter` for the SDK's own internal bookkeeping (its 5 auto-created tables: subscriptions/locks/cache/lists/queues). Isolation: point state-pg at Barkpark's own Postgres via a `pg.Pool` whose connection pins **`search_path=chat_bridge`** (a dedicated schema), so the SDK's 5 UNQUALIFIED `CREATE TABLE IF NOT EXISTS` land in `chat_bridge`, never Barkpark's `public`. `keyPrefix` is a ROW column, NOT a schema switch — it does not move the tables. The bridge runs `CREATE SCHEMA IF NOT EXISTS chat_bridge` + its own map/installs DDL on boot (idempotent). NO Ecto migration.
- **D29 [DECIDED — tenant routing] — Bring-your-own-bot per workspace; tenant resolved by CREDENTIAL/inbound-path, not a payload `team_id`.** Telegram has no team/org field in its payload, so the abstraction MUST NOT assume a payload-extractable tenant id. Bridge-owned `chat_bridge.connector_installs (provider, install_key, workspace_id, credential_ref, PRIMARY KEY (provider, install_key))`. Each Connector declares a `tenantResolution` strategy: `credential-bound` (Telegram — the bot token / webhook path IS the tenant binding, resolved BEFORE payload inspection) or `payload-team-id` (Slack — extract `team_id`). `provider_team_id → workspace` is thus ONE strategy among two; P3 Slack lands with zero core change. Reads scope fail-closed (mirror `Content.Scope.scope_to_workspace/3` semantics).
- **D30 [DECIDED — connector abstraction] — A `Connector` is a TS declaration in a plain registry, NOT an Elixir `Barkpark.Plugin`.** Shape: `{ id, direction: 'channel'|'tool'|'both', auth: 'oauth'|'token'|'signing-secret', tenantResolution, adapterFactory(creds) => Adapter, resolveTenant(event, ctx) => workspace_id }`, registered into a `connectorRegistry` map. The SDK's own `new Chat({ adapters: Record<string,Adapter>, state })` shape already delivers "register an adapter, no core change" — adding a P3 channel = one registry entry + its `@chat-adapter/*` dep. The core loop (resolve tenant → resolve-or-mint session → POST turn → stream SSE → post reply ONCE) never changes. Telegram registers as a first-class Connector, identical in shape to every future channel — the smoke adapter is an adapter swap, not a special case.
- **D31 [DECIDED — continuity scope] — This wave delivers per-CHANNEL continuity; cross-CHANNEL identity-linking is deferred to P4.** The thread key is the raw provider thread id namespaced by `(provider, workspace)`: resuming the same Telegram chat returns the same Session. True cross-CHANNEL continuity (one human on Slack + Discord → one Session) requires a cross-provider identity-linking step that does not exist. Corrects the design paper's "cross-surface continuity is free": the Session is reachable by UUID from anywhere, but the AUTOMATIC thread→session mapping is per-channel. Filed as backlog.
- **D32 [DECIDED — deploy shape] — Persistent always-on Node process, NOT Vercel serverless functions.** No `/v1/chat` turn-latency SLA exists to justify the 300–800s Fluid-Compute envelope; P3 Discord needs a persistent Gateway websocket; Telegram `getUpdates` polling wants a long-lived loop. The streaming glue is a long-lived fetch/SSE client loop. A `vercel.json` can deploy webhook-only providers later; P2's core assumes a persistent process. Host is TBD — not a commitment this wave.
- **D33 [DECIDED — zero-Elixir smoke] — The bridge authenticates per-workspace with an EXISTING workspace-bound `chat`-permission `ApiToken`.** `Auth.create_token/5` already mints `["chat"]`+`workspace_id` tokens (proven live in `chat_controller_test.exs:166-167`). NO HTTP mint endpoint is required for P2: the operator mints the smoke token out-of-band (mix/console), or uses the global-admin dev token (→ `:global` chat scope). **P2 ships ZERO `.ex` changes.** Gotcha carried: a `chat` token WITHOUT `workspace_id` is 403 — per-workspace tokens MUST carry `workspace_id`. A self-serve chat-token mint endpoint is optional P3 polish (backlog; if ever built it is an isolated Elixir slice behind the Elixir Test gate).

## Builder discipline

- Every builder isolates in a **worktree**, branches off **freshly-fetched `origin/main`** (`git fetch origin main` first — the shared primary checkout drifts, ~9 ahead/7 behind; never branch off local HEAD). Slices 2–5 rebase onto W3-1's branch before merge.
- P2 is Node/TypeScript only — no `.ex` change is expected. IF a slice ever adds one (it should not), it **WAITS for the Elixir Test gate** (`[[dont-merge-before-elixir-test]]`) and is its own isolated slice.
- **JS/docs slices dodge the pre-existing main-wide reds** (`task-9ad2d5988f7ca274` = stale `.sobelow-skips` `media.ex` line drift; `task-openapi-drift-chronic` = chronic `docs/openapi.json` drift). Neither is slice-caused; a pure `connectors/` slice touches neither file and may merge over them.
- **Distrust vacuous green** (`[[distrust-vacuous-green]]`): the map's mint-once/resume-after and the turn loop's post-ONCE must be proven by assertion, not asserted by prose. Live Telegram round-trip is an honest human gate (real bot token + running `/v1/chat`), delivered as a runnable harness + unit tests against a faithful recorded-SSE mock — never a fabricated "it works".
- Wire contract for `/v1/chat`, the SSE frame shapes, and the state/isolation model are FIXED in this charter (D26/D28) — parallel builders share one written truth.
- The wave Paper (`connectors-wave-3-2026-07-14`) is the live spine: workers report `coverage[]`, stamp evidence as they go.
