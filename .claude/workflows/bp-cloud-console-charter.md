# Barkpark Cloud Operator Console Epic — "Feel In Touch"

Wish: *"A Barkpark Cloud operator console where we feel in touch — a place the operator opens and immediately senses the health, activity, and levers of the whole fleet, and can act (rollback a bad deploy, manage members/usage, watch live meters) without leaving it. Make it feel alive and in-command, not a static admin table."*

Focus surface: the Cloud SPA (`cloud/priv/static/app.js` + `app.css` + `__preview__/`) and its control plane (`cloud/lib/barkpark_cloud/`), plus the `bp cloud` CLI twins (`internal/cli/`).

**Parent epic:** this is a focused child of `.claude/workflows/bp-cloud-epic-charter.md` (Peak Aesthetics/UX/DX, decisions D1–D36). Those decisions BIND here — especially D2 (closed SSE registry, no new types without a same-PR consumer), D13 (one app.js slice per wave region; sequential append-only merge train), D17 (nav frozen at 4 places + Settings; capability grows only as Fleet lenses / instance sub-tabs, no dead shells), D25 (every terminal state carries exactly one recovery action), D48/D51 (honest meters — never a fake zero, one bad source degrades one meter not the envelope), D49 (a sub-tab ships only WITH live backend + content). This epic runs PARALLEL to the parent's in-flight aesthetic sweep (D24) / airdrop / pdrender waves — it never edits app.css token blocks, `statusMeta`/dep-pill code, index.html, or styleguide.html; all CSS additions are append-only component rules at the file tail.

## Vision

The operator opens the console and it breathes. A topbar liveness chip proves the SSE spine is up (green "live" / amber "reconnecting" when the stream drops) — the page never lies about whether it is current. Every meter on screen is a real number or an honest "unmetered — <source>"; when an SSE tick actually changes a rendered value it pulses once (motion = data changed, never idle decoration, collapses under prefers-reduced-motion). Drill into an instance and a fourth sub-tab, Usage, is the meter wall: documents, datasets, webhook deliveries, DB size, disk, seats — a live count when `measured_at` is nil, a skeleton (not a dead spinner) while a hung instance holds `/usage` ~15s, a quiet "unmetered" state where a source can't be reached, every failure carrying exactly one recovery action. Members lives in Settings — the whole seat roster and pending invitations, invite/re-role/revoke one confirm away — killing the last curl-only surface. A bad deploy is a story you watch, not a form you submit: the shipped promote/rollback UI is proven against its criteria and the stale-paint race that could show instance A's sites in B's slot is closed. And the same truths answer in the terminal: `bp cloud usage` and `bp cloud members` paint the identical envelopes. The whole weekly loop — sense health, watch a deploy, roll one back, manage people, watch usage — happens without leaving the page, and every number can say where it came from.

## Decisions

Numbered OC# to avoid collision with parent D#. Each binds future waves.

1. **OC1 — The rollback-gui task is verify-and-close, NOT rebuild.** The full sites promote/rollback UI shipped 2026-07-04 in `58100d00` — `promotePath`/`promoteActionFor`/`promoteConfirmCopy`/`promoteFailure` all live and exported via `__bpTestHook` (app.js:3655+/7175), on the shared `confirmModal`. *Why: rebuilding a shipped feature burns the wave's biggest slot and risks two-builders-one-region merge failure; the genuine residue is criteria-proof + the owed `loadInstanceSites` race, then close the task with evidence.*
2. **OC2 — The Usage renderer is GENERIC, driven only by the `/usage` envelope shape** `{value|"unmetered", quota, warn_at, source, measured_at}` (verified: `Usage.meter/3` already emits exactly this; `quota`/`warn_at` are nil in v1). *Why: this is the structural payoff — it makes C11 (real counts) and future quota limits pure Elixir slices that light up in an unchanged SPA, forever. Preserves D13: one app.js slice this wave.*
3. **OC3 — C11 is Elixir-only.** Real documents/datasets counts (replace the hardcoded `:unmetered` at `build_usage`, router.ex ~4649) over the vault-token instance-API seam (Verify.run/1 discipline: admin token never in a return value; bounded timeout under the 15s skeleton budget; per-meter failure degrades that ONE meter to `:unmetered` per D51), plus a cross-dataset webhook total (today's meter is `production`-only — the code says so). *Why: with OC2's generic renderer, meters light up with zero SPA edits — C11 and C10 have no app.js overlap and no merge ordering between them.*
4. **OC4 — The deleted-elsewhere webhook stops lying.** rotate/deliveries/replay against a webhook 404 currently ALL map to `capability_unavailable` / "update this instance" (verified router.ex:5766) — a lie when the webhook was simply deleted elsewhere. C11 introduces a distinct code **`webhook_gone`** (hint: refresh the list) for the deleted case, keeping `capability_unavailable` for genuinely-old instances (discriminate by the instance's advertised capability/version; if no reliable signal exists, ship the softened neutral copy and file the discriminator as a follow-on — honesty about the uncertainty beats a confident wrong sentence). The SPA copy branch is owned by C10 via `failureCopy` (agreed code string, so merge order is irrelevant). *Why: "update the instance and nothing changes" is the exact dead-end D25 exists to kill.*
5. **OC5 — Members is a Settings-cluster view; Usage is an instance sub-tab.** `SETTINGS_VIEWS += "members"` (team-scoped truth lives with tokens/billing); `INSTANCE_TABS += "usage"` (per-instance truth, D49-legal — C9 usage backend is live). The frozen IA (D17) grows only as a sub-tab + a Settings view — never a fifth top place. The already-registered `members` SSE type (events.ex) finally gets its real consumer (today `TYPE_ACTIONS.members` is a no-op at app.js:5101). *Why: co-locating people-management inside an instance to satisfy a build constraint would be IA vandalism; the D13 constraint is honored by making C10 ONE app.js slice, not by warping the screen map.*
6. **OC6 — Aliveness WITHOUT new SSE types.** No new event vocabulary, no fleet telemetry stream (D2/D33 froze the registry; a payload stream is the monitoring-product-in-embryo D23 forbids). The "alive" feeling = (a) a topbar liveness chip bound to the existing EventSource state (`evtErrored`, app.js:4985) that degrades honestly to "reconnecting" and recovers silently; (b) a value-tick pulse when an SSE tick actually changes a rendered number; (c) freshness stamps ("as of Xs ago") that tick. All pure helpers (`liveDotState`/`heartbeatState`, `freshnessOf`, `meterTick`) pinned in the node:vm harness. *Why: perceived liveness is motion + honesty about staleness, not a new backend; Vercel's dashboards poll too.*
7. **OC7 — Quotas ride the envelope LATER, renderer is quota-aware NOW.** The meter shape already has `quota`/`warn_at` (nil in v1). C10's renderer draws a quota bar with warn/over tones *when a limit is present* and no bar when absent. Wave 1 emits no limits (honest: no fake ceilings), so no bars render; a later Elixir-only slice sources real plan limits and the bars appear with zero SPA edits. *Why: same OC2 payoff; drawing a bar "to nowhere" for an unlimited meter is exactly the dishonesty the wish forbids.*
8. **OC8 — CLI twins are zero-collision parallel work.** `bp cloud usage <instance>` and `bp cloud members` render the same `/usage` + team envelopes (both live today; usage is all-unmetered until C11 lights it up). Dispatch registers in `runCloud` (hetzner_cmd.go:80 — NOT cloud_cmd.go; the wave-4 correction). Meter-name vocabulary asserted against a committed fixture shared with the SPA so the two surfaces can never drift. *Why: "one product, two surfaces" (parent D36) decays one missing twin at a time; a Go-only slice fills a parallel slot with zero app.js/Elixir contention.*
9. **OC9 — app.js contention protocol (carried verbatim from parent wave 4).** Each SPA slice declares its region; appends-only to the shared tails (`__bpTestHook` exports, `__app.test.mjs`, `app.css` end, `__preview__/scenarios.mjs`); the lead merges the SPA slices SEQUENTIALLY (textual-only conflicts in the tails). Every new pure helper is exported via `__bpTestHook` and tested; every new visual state gets a `__preview__` scenario (amendment 2.4). *Why: wave 4 proved 3 concurrent app.js slices merge cleanly under exactly this discipline; without it the 7.2k-line file eats the wave.*
10. **OC10 — Deferred, on the roadmap, not this wave:** instance-release rollback (roll off a bad *blessed* release via autoupdate-pin + self-update — genuinely operator-critical now that the fleet is autoupdate-by-default #1230, but LARGE and needs a verify-first spike on whether the updater honors a *downgrade* pin); the fleet usage-sampler worker + `/v1/usage/summary` + Overview fleet meter strip (high-risk structural bet — a migration + worker + endpoint); Cmd+K palette; sparklines/Metrics sub-tab. *Why: wave 1 ships the two genuinely-missing weekly surfaces + closes the stale task cleanly; don't gamble the marquee slot on an unspiked question or collide with the parent's in-flight aesthetic sweep.*
