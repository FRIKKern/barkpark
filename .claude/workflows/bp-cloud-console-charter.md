# Barkpark Cloud Operator Console Epic — "Feel In Touch"

Wish: *"A Barkpark Cloud operator console where we feel in touch — a place the operator opens and immediately senses the health, activity, and levers of the whole fleet, and can act (rollback a bad deploy, manage members/usage, watch live meters) without leaving it. Make it feel alive and in-command, not a static admin table."*

Focus surface: the Cloud SPA (`cloud/priv/static/app.js` + `app.css` + `__preview__/`) and its control plane (`cloud/lib/barkpark_cloud/`), plus the `bp cloud` CLI twins (`internal/cli/`).

**Parent epic:** this is a focused child of `.claude/workflows/bp-cloud-peak-aesthetics-charter.md` (Peak Aesthetics/UX/DX, decisions D1–D36; formerly at `bp-cloud-epic-charter.md`, which now holds the studio-ui-premium charter). Those decisions BIND here — especially D2 (closed SSE registry, no new types without a same-PR consumer), D13 (one app.js slice per wave region; sequential append-only merge train), D17 (nav frozen at 4 places + Settings; capability grows only as Fleet lenses / instance sub-tabs, no dead shells), D25 (every terminal state carries exactly one recovery action), D48/D51 (honest meters — never a fake zero, one bad source degrades one meter not the envelope), D49 (a sub-tab ships only WITH live backend + content). This epic runs PARALLEL to the parent's in-flight aesthetic sweep (D24) / airdrop / pdrender waves — it never edits app.css token blocks, `statusMeta`/dep-pill code, index.html, or styleguide.html; all CSS additions are append-only component rules at the file tail.

## Vision

The operator opens the console and it breathes. A topbar liveness chip proves the SSE spine is up (green "live" / amber "reconnecting" when the stream drops) — the page never lies about whether it is current. Every meter on screen is a real number or an honest "unmetered — <source>"; when an SSE tick actually changes a rendered value it pulses once (motion = data changed, never idle decoration, collapses under prefers-reduced-motion). Drill into an instance and a fourth sub-tab, Usage, is the meter wall: documents, datasets, webhook deliveries, DB size, disk, seats — a live count when `measured_at` is nil, a skeleton (not a dead spinner) while a hung instance holds `/usage` ~15s, a quiet "unmetered" state where a source can't be reached, every failure carrying exactly one recovery action. Members lives in Settings — the whole seat roster and pending invitations, invite/re-role/revoke one confirm away — killing the last curl-only surface. A bad deploy is a story you watch, not a form you submit: the shipped promote/rollback UI is proven against its criteria and the stale-paint race that could show instance A's sites in B's slot is closed. And the same truths answer in the terminal: `bp cloud usage` and `bp cloud members` paint the identical envelopes. The whole weekly loop — sense health, watch a deploy, roll one back, manage people, watch usage — happens without leaving the page, and every number can say where it came from.
