# Theme System — Epic Charter

Epic task: `theme-system` (published, priority 1). Design paper: /papers/theme-system on guerrilla.

## Vision

One theme, every surface. A frick-principled theme system: typed palette authoring in `design/tokens.json` → deterministic compiler → derived slots, with paw-grade craft (hue-tinted neutrals, mechanical hue-preserved dark inversion, formula accent ramps, contrast-aware on-accent, frozen structure + thin swappable skin). North-star invariants:

1. No surface holds a color literal the theme compiler did not put there.
2. Theme identity and light/dark mode are two orthogonal switches.
3. Adding theme N+1 touches exactly one new file.

Surfaces in scope: reader article (bulldocs), Studio (root.html.heex), email bytes (Elixir render), mail-client popup chrome (--mail-*), TUI (pdrender + taskboard), web demo, cloud SPA, CLI chrome. Today evergreen is ~70% token-driven, 30% hand-stamped; Wave 1 is the CAPTURE wave — make the current evergreen truly single-source with provably zero visual change, so the later compiler swaps values under a structure that already owns every byte.

## Decisions

- **D1 — Adopt, don't refile.** ts-w1..ts-w5 (children of `theme-system`) stand. ts-w1 is perfected in place as one slice; ts-w2 is SPLIT (its two halves are different languages, gates, and risk profiles): ts-w2 is rewritten as the Elixir email slice, `ts-w2b-pdrender-chrome-thread` is the new Go slice. One new slice `ts-w1c-exemption-ledger` makes the "counted, shrinking remainder" criterion mechanical (check.mjs has no such feature today — gate-wiring exploration confirmed it is NEW code).
- **D2 — Verbatim capture, hex-as-hex, rgba-as-rgba.** tokens.json grows `paper`, `mailChrome`, `paperEmail`, `paperCallout` families holding today's hand values byte-verbatim (like the existing `color.code` role). No HSL conversion, no derivation, no dedup of overlapping values across families — that is ts-w3 compiler business. Why: Wave-1 acceptance is *emitted bytes == today's bytes*.
- **D3 — Do NOT thread Elixir onto the existing `Render.TokensGen` brand/rule slots.** They derive from shared `primary`/`border` and are ALREADY drifted from the hand email values (#1e5243 vs #1e5347; #e4e4e7 vs #dde7e2) — consuming them is a real retint that reds the email golden. New verbatim slots are emitted instead; the existing slots stay untouched until w3 reconciles. Consequence: **zero email-golden regen** is the acceptance — stronger than the originally sanctioned regen-with-justification. (Decision 8's "email indigo → evergreen" premise is stale; the indigo kill already shipped by hand.)
- **D4 — bulldocs.html.heex becomes emit artifact #16** via the existing delimited-marker splice (same mechanism as root.html.heex). The reader skin emits its OWN values verbatim — including the deliberate solid `--paper-rule: #dde7e2` (vs paper-surface's rgba) and the dark-block re-stamps — never collapsed onto shared tokens in this wave. Load-bearing rationale comments are emitted verbatim from `bulldocsBlock()` so `emit --write` preserves them. The `--mail-*` var-definition block is physically relocated into the single marker region (custom-prop definitions on distinct selectors reorder safely; builder proves no other rule sets `--mail-*`).
- **D5 — paper-surface.css `--paper-*` color block (§41-98) relocates into the existing GENERATED marker region**, emitted by an extended `paperBlock()`. Relocation is the one non-append change; the builder proves no same-selector custom-prop redeclaration is reordered, and the paper-editor mirror follows automatically.
- **D6 — pdrender gets its chrome roles re-emitted into its OWN package.** pdrender may import only lipgloss + x/ansi + stdlib (enforced isolation) — it can NEVER import `internal/semrole`. `emit.mjs pdrenderGo()` grows 4 chrome slots (accent/ink/text-secondary/dim) sourced from the existing `color.cliChrome` tokens (no new authoring for these). pdAccent keeps the LEGACY blue `#1d4ed8` (byte-exact capture; evergreen migration is w3). **Decoy warning:** existing `GenInk`/`GenDim` in pdrender are the reading-family values, NOT pdInk/pdDim's zinc chrome values — threading them would silently retint (`pdLabel→GenDim` IS exact; `pdDim→GenDim` is NOT).
- **D7 — toneNeut gets its promised token now** (verbatim `#374151`/`#9ca3af`, new tokens.json role, emitted as a pdrender slot). `pdBtnFg` (`#ffffff`/`#ffffff`, no twin anywhere) stays a counted lit-allow; ChromaStyle names are non-hex and unflagged. `scripts/go-literal-check.sh` gains `internal/pdrender/theme.go` in FILES so the capture sticks; the pdrender styleguide golden is EXTENDED to the chrome/code/rule/terra/label roles because every other pdrender golden is Ascii-stripped — without this, a wrong thread ships with no test catching it.
- **D8 — Exemption ledger in check.mjs (new Part).** A committed baseline (`design/exemptions.json`) lists each hand-stamped remainder file with its literal count; check.mjs recounts (color literals outside GENERATED markers) and FAILS on any mismatch — growth is a regression, shrink requires updating the baseline in the same diff. Initial entries: root.html.heex outside-marker (~137, family-allowed today), bulldocs.html.heex post-capture remainder (traffic-light dots, TUI-preview chrome, etc.), cloud app.css body (~15 brand marks + mask geometry — exempt-by-design but now tripwired), `internal/cli/setup/assets/deploy.sh` holding page (4, previously gate-blind).

- **D10 — Sequencing:** merge order S1 → S2 → S3 → S4 (paper first — flagship + ungated third copy; email second — bytes ship to mail clients; Go third — coordinate with hot pdrender dev; ledger LAST — baselines the post-wave state). - **D11 — Characterization discipline is the gate:** every PR's acceptance is byte-identity of shipped color artifacts (check.mjs Part A) plus the surface's own test suite unmodified. api/** PRs wait for the Elixir Test gate before merge. PR bodies carry `Task: <id>`; no Co-Authored-By.
- **D12 — Two-stage gate (w2/DERIVE).** The compiler gate is a NEW check.mjs Part F: `derive(themes/evergreen.json)` must reproduce the current color-slot values in tokens.json byte-equal. emit.mjs and every shipped artifact stay untouched this wave — byte-identity of artifacts follows transitively from the already-green Part A. - **D14 — Fit-first constants, honest pins (formula-fit corrections adopted).** (i) hover is per-mode ΔL (light darkens ~-7.5 OKLCH L, dark lightens ~+4.7), not one constant; (ii) the neutral hue-tint is real (H lands 2–6° off accent natively) but chroma RAMPS 0.004→0.019 — a per-rung tint schedule, NOT a single .10/.06 alpha (those alphas are the accent-TINT constants only); (iii) status ok/danger hues fit the locked targets natively (H150.0/H26.8), warn is 10° off (H65 vs 75) and warn/info light FAIL AA 4.5 on white today — these are PINNED this wave; the AA/hue retint of shipped status colors is a filed follow-up with its own justification, never a silent Part-F side effect; (iv) dark mode is a hand re-pick, not mechanical inversion — the inversion formula covers the brand/neutral spine, dark accents (warn +9°, accent +12°, reading-accent +10°, paper.ink -15°) get pins; (v) the 8<16<22<55 chrome ladder does NOT exist in shipped bytes — derive implements it as a capability, evergreen pins the off-ladder slots; the ladder is imposed only on future themes.
- **D15 — AA-walk honesty.** frick's lightness-walk terminates on threshold OR 48-iteration cap OR lightness bound — it is NOT proven-convergent. derive asserts residual contrast after every walk and reports misses loudly (a returned color that silently fails AA is a bug); a pathological-hue unit test proves the reporting path.

Build it from the contrast helper: pick warm-white vs near-ink by whichever clears AA on the accent; unit-test both branches (evergreen's amber accent hsl(30 92% 42%) is a live flip candidate).
