# API Read-Path Security Sweep — Epic Charter

Epic task: `api-read-path-security-sweep` · Wave 1 Paper: `api-read-path-security-sweep-wave-2026-08-17` · Wave 2 Paper: `api-read-path-security-sweep-wave2-2026-08-17`

## Vision

Seal and certify the SECURITY doors on Barkpark's API read paths so each one fails closed with its OWN mutation-proven verdict, per the field-visibility doctrine (every `Envelope.render` bypass sealed individually — a fix credited to a surface it was not re-probed on is a false seal). The honest finding that shapes this epic: four of the five named doors are ALREADY bolted on origin/main (#6270 pinned public-read at the AnonPerspective chokepoint, #7870 mounted `PublicRead` on `:require_token`, #9613 gave the graph corpus a visibility gate, the drafts-id clamp lives at `query_controller.ex:371`, and `astro.config.mjs` hard-fails the build on a privileged token). So this epic's value is **certification with mutation-proven verdicts, one genuine build, and honest rulings — not re-paving merged clamps**. The deliverable is a ledger where every rendering read path (flat doc, scoped doc, preview/doc, graph traverse, export, analytics, listen, history) is its own door with its own fail-closed proof: revert the clamp → the guarding test reds; restore it → green. A green a blind harness would also produce is not a seal.

## Decisions

- **SEAL-AND-CERTIFY, not build-from-zero** — verification confirmed most doors are already merged; a wave that ships "new" clamps and declares the doors closed manufactures the exact false-seal lie this epic exists to stop.
- **stw10 closes with THREE new committed regression tests, not as-is** — the clamp is real and mutation-proven, but three of its four fail-closed doors (scoped doc + public-read, scoped doc + docs:read share, scoped preview/doc) have ZERO test coverage today, so today's green is a green a blind harness would produce.

Requalified before claim so the close work-digest fence never blocks it.

Fix BOTH callers (`graph_show` + `graph_tasks`).

### Wave 2 decisions (2026-08-17 — verified, ground truth in hand)

- **The ruling menu is THREE paths, not two, and the packet is EXECUTABLE, not prose.** Verify settled the flip mechanism: `schema.visibility="public"` for `task`+`paper` is a CODE declaration (`tasks/schema.ex:51`, `priv/plugins/bulldocs/schemas/paper.json:5`) re-asserted on EVERY boot for `production`-dataset Default-slot rows by `Plugins.Bootstrap` — EXCEPT `pull_provenance`-stamped hosts (skip) and non-production datasets (never re-asserted). So a code-only default change silently misses pulled hosts; a data-only migration is reverted at the next restart on un-pulled hosts; **neither is sufficient alone** (proved live on the dev DB, both directions). The owner-facing ruling therefore offers three executable outcomes, each a pre-filed child task with commands: **(A) stay public — the current shipped state, no change** (recommended default only if the exposure is judged acceptable); **(B) stay public + a server-imposed anon projection** at the `Envelope.render/3` chokepoint (title-only anon reads — a NEW build, since nothing declares field-level visibility today and `render/3` promotes a `blocks` key before redaction); **(C) flip private per host** = code default + per-host data migration (stamped hosts) + per-host console read of `settings["pull_provenance"]` FIRST. A fourth, cheapest-for-dead-hosts outcome rides alongside C: **shrink the host set** — primary (newest paper 2026-06-29) and muscle-1 (frozen since 2026-07-26, byte-identical to the 2026-07-28 census) are dead corpora, so depublish/delete discharges them without touching `visibility` (PDF-D59 alignment).
- **`pr-task-gate.sh` is the hard-red ordering gate — outcome C MUST NOT ship before it is patched.** Confirmed: the gate reads `guerrilla` tokenlessly (`vars.BARKPARK_LEDGER_BASE` unset → default), 404 → `fail()` on the BINDING `enforce_admins:true` "PR references an active task" check. A `task`-private flip on guerrilla makes every task 404 → main unmergeable INCLUDING the token-patch PR. `BARKPARK_TASK_TOKEN` is NOT provisioned as a repo secret (a human step). Fork PRs never get secrets, so under a private flip they red regardless (GitHub has no neutral) — the packet records this. The token-plumbing task (`arpss-pr-task-gate-token-plumbing`) is the pre-filed dependency the flip outcome depends on.
- **The census headline is HALF-WRONG in the charter's OWN numbers — re-derive live, never quote a bare integer.** Live 2026-08-17T08:37Z: primary 0 tasks / 15 papers (widest TYPE surface though — posts/pages/projects/authors), guerrilla 6212 tasks / 776 papers (`?count=true` gives the TRUE total; it does NOT collapse to the page cap — the "≥1000" reading was a page count read as a total), muscle-1 3139 / 551 (frozen), and **`gyldendal` — a CUSTOMER host named in no prior source — 13 / 51, anon-open**. Author `email` is served anon on primary + gyldendal but every non-empty address is `@sanity.io` demo-seed — a low-severity seed note, NOT customer PII.
