# Honest Gates — epic charter

Epic task: `auth-totp-tests-are-time-boundary-flaky` (priority 0)
Founding wave Paper: `gates-tell-the-truth-wave-2026-07-20`

## Vision

A gate must be **able to be green**, **able to be red**, and must **red for exactly one reason — the thing it claims to measure**.

Every defect this epic exists to remove is the same shape: a predicate contaminated by a variable irrelevant to its claim — wall clock, scheduler seed, worker liveness, toolchain version, runner contention. A contaminated gate teaches readers to dismiss it, and a dismissed gate is how a one-character CSS defect survived five waves in production while three gates certified it green.

`continue-on-error: true` is not a third option. It is the terminal stage of the disease: the gate stops being able to fail, so its population grows instead of holding (measured: 87 → 91 → 92 → 94 unformatted Elixir files in 48h; 12 → 30 unformatted Go files under gofmt's advisory).

**Every slice lands in three parts, and a slice missing part three is not done.**
1. **THE CAUSE** — remove the contaminating variable. Never retry around it.
2. **THE POPULATION** — migrate every sibling instance, not the sample that failed.
3. **THE RATCHET** — a tripwire that fails CI if the hazardous shape reappears, plus an affordance that makes the safe path the easy one.

## Decisions

- **D1. The law above is the acceptance bar for every slice.** Cause + population + ratchet; a fix without a ratchet regrows, and the repo contains the proof twice over (the async seam guard, and api/test's `application_env_isolation_test.exs`, are two independent sample-scope fixes for the same hazard, neither aware of the other, both already decayed).
- **D2. A retry wrapper is never a fix.** It hides the race and preserves the lie. Every fix must be proven ABLE TO FAIL by forcing the failure condition and showing the OLD path breaks where the NEW one does not.
- **D3. Exit code can NEVER discriminate a dep error from a real verdict.** Measured live: exit 1 in all four of {dep-missing format, real format drift, dep-missing test, real test failure}. Only stdout text discriminates — `Unknown dependency` / `Unchecked dependencies`. Any harness that reads `$?` alone certifies a dep error as a verdict on the real work.
- **D4. TOTP is fixed in the TEST, never in the server.** `enable_totp/3` (accounts.ex:598) is a bare `NimbleTOTP.valid?(secret, code)` on purpose: `disable_totp/1` does not clear `last_totp_at`, so passing `totp_opts` there converts a disable→re-enable cycle into a permanent enrolment lockout (proven by mutation, and the suite stayed 61/0 green under it). Adding NimbleTOTP's own moduledoc-prescribed grace window to `valid_totp?/2` or `verify_totp/2` **doubles** the live acceptance window on two internet-facing endpoints — and the careful variant that preserves `since:` also passes silently. A prose fence is therefore insufficient: the fence must be enforced by protective tests, because api/test generates **zero** off-period TOTP codes and is structurally blind to window width.
- **D5. The async-global-seam ratchet DERIVES nothing — it bans the shape.** `mix xref` structurally cannot see test files (`elixirc_paths(:test)` excludes `*_test.exs`; zero `*_test.exs` beams in `_build`), and a text scan cannot see transitive reads (2 of 4 documented `:site_box_relay` readers contain zero textual mention of it). A hand-maintained key list also mis-matches both ways: it misses the fully-qualified form and false-positives on `OAuthStub` by prefix. The only predicate the source text can answer correctly is **"is there an `Application.put_env` inside an `async: true` test module?"** — measured cost of enforcing it: +1.6s on 2138 tests, zero failures.
- **D6. The seam ratchet runs over BOTH `cloud/test` and `api/test`.** The current guard's wildcard is relative to `cloud/`, so it structurally cannot see api/test's two swappers — that directory-scope gap is why the same hazard was rediscovered independently a second time.
- **D7. The pr-task-gate's invariant is "this change is task-backed", not "someone is actively typing right now".** A task closed on met acceptance criteria is the SUCCESS case. `done` passes **only when `claim.closed_by` is present** — proof it went through the claim/close engine rather than being hand-flipped. `landed.prs` would be the stronger link but is dead data (0 of 400 done tasks populated) and the Go CLI's close body is pinned by `assertExactKeys`, so gating on it today yields a gate that can never be green.
- **D8. The 404 branch stays definitive, always.** It correctly caught an invented task id (`cloud-gui-remake-epic`) the same day. A predicate change that makes the gate unable to red is the same disease pointing the other way.
- **D9. Fixtures land BEFORE any predicate change.** Deleting the gate's central `in_progress` check leaves `scripts/pr-task-gate.test.sh` **9/9 green** — the fixture set has zero (non-`in_progress` × worker-present) cases, so the lifecycle and worker checks are indistinguishable on it. A builder given both at once will write the predicate first and read a green harness as validation.
- **D10. The format gate is FIXED then PROMOTED — never deleted, never promoted to force the fix.** Deleting it destroys the only signal that makes promotion verifiable; requiring it today (10/10 failure on main, no paths filter, runs on every PR) would block 100% of merges repo-wide. `cloud.yml` runs the identical command BLOCKING and green on the identical pinned toolchain — the live proof that blocking is affordable once the population is clean, and the counter-example to version skew being the whole cause.
- **D11. A partially-clean population still gets a ratchet: the drift ceiling.** Where a full migration collides with live cycles, the count of drifted files becomes a committed baseline that CI forbids increasing. The population can then only shrink. A stated deferral with its reason is itself a truth-telling act; a silent declaw is not.
- **D12. `cancelled` is a non-pass.** The 2026-06-10 never-cancel-main guard was applied at sample scope: `elixir.yml`, `go-tests.yml`, `js-tests.yml`, `security.yml`, `pr-task-gate.yml` got it; `cloud.yml` and `doc-gates.yml` never did. 20 of 30 main pushes today concluded `cancelled`.
- **D13. Nothing in this repo is required-by-name.** `branches/main/protection` → 404, `rulesets` → `[]`, re-confirmed live and independently recorded by three prior tasks that never actioned it. Part three of the law is not finished until branch protection carries the check — and it cannot, because only 2 of 34 workflows run unconditionally on every PR; a required paths-filtered check sits Pending forever and deadlocks the repo. **Protection is wave-2 work with a path-filter skip-shim as its first step, not a settings toggle.**
- **D14. Adopt, never re-file.** `cloud-oauth-replay-test-is-seed-flaky` and `pr-task-gate-contradicts-close-on-criteria` were already filed, root-caused and fix-speced before this wave existed. Re-deriving filed work is the documentation dimension of the same sample-scope disease.
- **D15. Measure the thing, not a proxy.** A pure-`NimbleTOTP` proxy put the same-process straddle risk at 1-in-1,034,483 and would have licensed dismissal; measuring the real `Accounts.enable_totp/3` path put it at 1-in-31,561 per site — 1 in ~1,973 suite runs across 16 sites. The proxy is what makes "unobserved" read as "safe".
- **D16. `--repeat-until-failure` is the wrong loop for concurrency races.** It shares one VM (mix's own docs warn leftover global state confounds later repetitions — a near-exact description of the defect being proven) and empirically caught the confirmed OAuth race **0 times in 92 repeats**, while a fresh-VM external loop caught it on the first 30. It also cannot even complete on `auth_controller_test.exs`: repetition 3 dies at HTTP 429 on the whole-node `:barkpark_rate_limiter` ETS table. Deflake loops boot a fresh VM per iteration and pin `--max-cases` to CI's value (local default is 20 on a 10-core box vs CI's 8 — a 2.5× concurrency difference that changes the race window).

### Wave 2 decisions (2026-07-27) — protection, and the prerequisites that make teeth honest

Every decision below was measured on live GitHub or a live ledger, not inferred. Where a wave-1 belief was refuted, the refutation is stated rather than quietly dropped.

- **D17. `enforce_admins: true` from day one, or protection is decoration.** Proven both ways on throwaway PRs against a throwaway base (main never protected): with `enforce_admins:false`, `gh pr merge --squash --admin` merged a BLOCKED PR whose required check was RED (exit 0, `mergedAt 2026-07-27T18:16:42Z`); with `true`, the identical command exited 1 with `GraphQL: Required status check "probe-will-fail" is failing.` `--admin` sends no server-side bypass — the server decides. The fleet's written merge protocol IS `gh pr merge --squash --admin` (`.claude/workflows/bp-loop-ledger.md:43`), so `false` would be bypassed by 100% of merges: a gate that cannot block, installed by the epic that exists to abolish gates that cannot block. Break-glass is the SR-1 shape and nothing softer: `DELETE …/protection/enforce_admins` (204) down, `POST` (`enabled: true`) back — one attributable command each, never a silent flag, and the verify step must assert `enforce_admins.enabled == true` so a left-open break-glass reds CI.
- **D18. A required name may NEVER live behind a workflow-level `on: paths:` filter.** Measured: a paths-filtered workflow emits NO workflow run and NO check run at all; the PR sits `BLOCKED` permanently and even `--admin` is refused — with a DIFFERENT message from a red check. `"…" is expected.` = a name that has never reported (deadlock); `"…" is failing.` = a real red. That message pair is the machine-readable deadlock signature, and a wrapper that greps only "failing" will read a deadlock as green-pending. Path decisions move to job-level `if:` behind an always-running dispatcher. 30 of 39 workflows are workflow-level path-filtered and are therefore disqualified as required names until restructured.
- **D19. `skipped` SATISFIES a required context — which makes the aggregator a CHARTER requirement, not a GitHub one.** Measured: a PR merged with NO `--admin` on a required set satisfied only by `skipped` conclusions, one of which skipped because its dependency FAILED. A `needs`-of-a-failed-job reports `skipped`, so a naive needs-chain converts an upstream FAILURE into a green required context. `if: always()` alone does not save it either: the probe aggregator RAN with a failed dependency and reported `success`, because it only echoed `needs.will-fail.result` instead of asserting on it. **`if: always()` buys the right to decide; it does not decide.** The aggregator must enumerate every upstream result and fail on anything outside an explicit allow-set — the charter's "FAILURE WHEN IT CANNOT TELL" clause. This repo has zero precedent: `grep -rn "^    if: always()" .github/workflows/` returns nothing (all 12 hits are step-level).
- **D20. The required-check spec is GENERATED from observed check runs, never typed — and the generator must reject three specific poisons.** (a) The matrix suffix is ALL-OR-NOTHING: GitHub appends the full matrix tuple only when the job `name:` interpolates NO matrix value — `probe-matrix-consumes-a (1)` did not gain its unconsumed `b: 9`. That is why `Format (mix format --check-formatted, advisory) (27.0, 1.18.1)` carries a suffix in matrix-DECLARATION order while `Test (Elixir 1.18.1 / OTP 27.0)` carries none and reads in the OPPOSITE order, in the same file. (b) A job that never STARTED — cancelled run, or a `needs` dependent of a failure — publishes the literal uninterpolated `Prod compile gate (Elixir ${{ matrix.elixir }} / OTP ${{ matrix.otp }})` as its check-run name; a generator sampling such a run commits a name that can never report. Reject any candidate containing `${{`; never sample a `cancelled` or `skipped` run. (c) `required_status_checks.contexts` shares its namespace with the legacy commit-status API, where `Vercel – barkpark` and `Vercel – demo` (EN DASH, U+2013) are `failure` on every sha sampled — the spec must DENY that namespace explicitly, and compare normalized bytes so a hyphen/en-dash transcription cannot silently mis-key.
- **D21. GitHub validates neither the context string nor the `app_id`.** A `PUT` naming `Test (Elixir 1.18.1 / OTP 27.O)` (capital O for zero) and a context that has never existed returned **200** and read both back verbatim — then deadlocked the PR forever. And `app_id: 99999999` returned 200 and read back `app_id: null`, i.e. "ANY app may satisfy this context" — since anything with `checks:write` can publish a matching name (Vercel app 8329 already publishes here), a typo'd id silently turns a pinned gate into a spoofable one. Verify must round-trip-compare `checks[]` (context AND `app_id`) against the committed spec and treat `app_id: null` where the spec pins an id as a hard failure.
- **D22. Legacy `PUT /branches/main/protection` is the instrument; `strict: true` is forbidden.** Legacy PUT is an idempotent full-replace on a fixed URL with one verify read; rulesets are POST-and-stack needing a name→id lookup, itself the D5 key-list shape. `restrictions` must be `null` (org-only; this repo is user-owned, which also kills merge queue as a variable — `isInOrganization=false`, `mergeQueue(main)=null`, zero `merge_group` triggers). `strict: true` would force serial rebase-and-rerun on a fleet that merged three PRs inside 78 seconds.
- **D23. The claim lease is SETTLED: the gate accepts a RECENTLY-LAPSED claim, read from the DOCUMENT.** Rejected — CI renewing the claim: `pulse` bumps `claim.epoch` and `close` fences on exact epoch equality, so a CI-side renewal would 409 the holder out of their own close (CI corrupting the ledger to satisfy CI), and a lease that renews for as long as a PR is open makes "claimed" permanently true, a D8 violation on its face. The reap stamps `claim.previous_worker` + `claim.expired_at` on the very doc the gate already curls unauthenticated — confirmed live. Predicate: lifecycle `open` passes iff a claim exists AND `worker` is null AND `previous_worker` is non-empty AND `expired_at` parses AND `now − expired_at ≤ LAPSE_GRACE_SECONDS` AND NOT `released_at ≥ expired_at`. **That last clause is load-bearing**: `Release` MERGES into the surviving claim and never writes `previous_worker`, so a reaped→re-claimed→released task keeps a stale `expired_at` and would read "recently lapsed" without it — the vacuous pass in this slice. Grace = 21600s (6h): measured dwell over 30 merges is median 17.1 min, p90 115.1 min, max 599.8 min, 7/30 over the 2700s lease; 6h covers 29/30 while a 6.5-day-old lapse still reds. The events feed is the WRONG source — its `kind`/`doc_id` params are SILENTLY IGNORED (a vacuous filter), it requires a bearer token the gate does not have, and a full walk is 237 requests / 118,347 events / 111s.
- **D24. Fixing the pr-task-gate's NEUTRAL path with `set +e` alone would make it WEAKER, not stronger.** The handler is unreachable dead code: the step writes `set -uo pipefail`, which does not clear the `-e` GitHub sets (`shell: /usr/bin/bash -e {0}`, read verbatim from a production run log), so exit 2 aborts before `rc=$?`. It fired TWICE in production on 2026-07-27 on guerrilla 500s — printing NEUTRAL, then `##[error]Process completed with exit code 2`, with the `::warning` never emitted. But GitHub removed the `neutral` conclusion for exit codes in 2019: making the handler reachable turns every 5xx into a SILENT GREEN, a required check passing having verified nothing. The shape is **bounded retry, then FAIL with a self-describing message** ("ledger unreachable after N attempts — re-run this check once the ledger is up") — honest and unblockable-by-rerun. `docs/ops/merge-gates.md:50-52` documents behaviour that has never existed and must be corrected in the same PR.
- **D25. A guard that fails open is worse than no guard, and this repo has one in the gate whose job is blocking.** The pr-task-gate's merge-base grandfather tests only `git cat-file -e "$BASE_SHA:.github/workflows/pr-task-gate.yml"`, which cannot distinguish "base predates the gate" from "BASE_SHA does not resolve"; both yield `enforced=0`, every downstream step carries `if: enforced == '1'`, and the job reports SUCCESS having checked nothing. The gate landed 2026-07-07 and the oldest open PR is 2026-07-13, so **the legitimate grandfather branch is dead and the only reachable path to `enforced=0` is the bug.** Three states, not two — or delete the clause and fail closed.
- **D26. A harness nobody runs is not a ratchet.** `scripts/pr-task-gate.test.sh` is 30 green fixtures executed by NOTHING in CI: every repo reference is prose, and `shell-harnesses.yml` — the workflow whose own header says it exists for orphaned `scripts/*.test.sh` — has exactly one tenant (`doctor.test.sh`) behind a paths filter a `pr-task-gate.sh` edit does not even trigger. Necessary and NOT sufficient: the harness is script-scoped and could not have caught either YAML defect above, so it also needs cases that execute the step bodies under `bash --noprofile --norc -e -o pipefail`.
- **D27. `continue-on-error` is NOT readable from any GitHub API — derive advisory from the check-SUITE rollup, never from a name.** Introspected three ways (REST check-runs, REST actions jobs, GraphQL `CheckRun`): no such field anywhere, so the assignment's "just read the jobs API" fallback is refuted. A job at `failure` inside a suite at `success` IS continue-on-error, by GitHub's own rollup semantics — two cheap calls, zero names. `scripts/release-scan.sh` instead classifies advisory by `name ~ /advisory|lighthouse/`, the D5 key-list shape, so Sobelow (continue-on-error, with "advisory" only in the YAML comment) is called BLOCKING and flips `ci.status` to failure on 3 of 25 recent main shas — which stops `release-curator.md:31-40` from proposing a release at all. **The derivation has an honest blind spot: under a RED suite you cannot tell which reds were advisory, and the reader must ADMIT it cannot tell** rather than emit a two-valued flag. Corollary gift for the spec guard: GraphQL `CheckRun.isRequired` DOES exist, so GitHub can be asked whether a name is required rather than trusted from a local list.
- **D28. Superseded is separable from cancelled — and the residue must admit it.** Main's queue-collapse victims carry `jobs.total_count == 0` (never dispatched); a genuinely cancelled RUNNING run carries jobs at `conclusion: cancelled`. Victim `updated_at` equals the successor run's `created_at` within 0–1s, 5/5. Three-valued: SUPERSEDED / CANCELLED / UNKNOWN — a human cancel of a still-QUEUED run is indistinguishable on the run object and must read UNKNOWN. Duration is NOT a discriminator (7s to 11m56s, both collapses). **Do not touch `concurrency`**: `cancel-in-progress: false` on main works exactly as its comment says, and per-sha grouping resurrects the 2026-06-10 starvation the guard exists to prevent.
- **D29. `--skip` is the one-flag Sobelow fix, and committing today's artifact would silently revert a deliberate migration.** `api/scripts/sobelow-baseline-reconcile.sh:49` runs `--mark-skip-all` WITHOUT `--skip`; sobelow 0.14.1 pairs inline `# sobelow_skip` annotations with their function only `if get_env(:skip)` (`lib/sobelow.ex:420-421`), so without it the annotated finding is generated, fingerprinted and written into the baseline. Measured back-to-back on one tree: **164 entries without `--skip`, 106 with — pure deletion, 58 removed, 0 added.** Zero of the 51 gate-reddening findings is a new insecure class; they are line drift, a `media.ex → media/blobstore/{local,s3}.ex` split, and a new janitor file. The harm is not breakage (a superset baseline still exits 0) but **unfalsifiability**: a file baseline that also carries an inline-annotated finding swallows that annotation's failure silently, and the committed file already does this 18 times. Flip the flag FIRST, then take the artifact.
- **D30. Sobelow's ten `workspace_bundle.ex` SQL sites are REQUEST-derived, and the file says otherwise.** Seven of ten interpolate `entry["name"]` / `entry["columns"]` / `entry["order_columns"]` straight off the uploaded bundle manifest, with no `table_exists?/1` check on the COPY/INSERT path — while `qi/1`'s comment at `:1128` claims "every name originates from the live catalog, never user input". Not exploitable (quote-doubling neutralises every break-out payload tested; admin-gated; `:merge` fail-closed behind `:allow_bundle_import`) but the comment is FALSE for the import path, and any waiver must say "request-derived identifiers behind correct quoting plus an admin gate" — never "catalog-derived", which would be a false annotation on the one bucket where a real injection could hide.
- **D31. The Elixir suite's path dependency is NOT `api/**`.** Machine-derived census of every `"../…"` escape: 24 repo-root reads, and the obvious filter list misses THREE families read by DEFAULT-lane tests — `internal/taskboard/**` (the only Elixir-side enforcement of the GUI↔TUI glyph parity contract), `internal/chat/testdata/**` (a byte-identity assert against the Go mirror), and `.codex/skills/epic-cycle/scripts/**` (a `System.cmd("python3", …)` cross-language parity test). `design/status-manifest.json` is an `@external_resource` of `status_vocab.ex:20`, so compile-affecting paths and test-only fixture paths are two different sets and must be authored as two. Over-inclusions cost the shim exactly what it exists to save: no Elixir test reads repo-root `templates/**`, and `scripts/claude-pinned-version.txt` is reachable only from a `:real_binary`-excluded test. **The enumeration ratchet must NOT enumerate via `git ls-files`** — with the mutation fixture present-but-untracked it reported "OK: every repo-root read is covered" and exited 0, a textbook vacuous pass of exactly the class wave 1's review found three times.
- **D32. S4 NEVER LANDED. The wave-1 log asserted a merge that did not happen.** PR #5046 is CLOSED with `mergedAt: null`; neither `.format-drift-ceiling` nor `scripts/format-drift-ceiling.sh` exists on origin/main; "lower the ceiling to 39" is unexecutable because there is no ceiling. It was closed on a MISREAD: the "exactly one file" the close comment quotes is the CEILING job's off-roster output, and it proves the OPPOSITE of what it was read as — all 50 locally-formatted files were format-CLEAN under CI's pinned 1.18.1, so the toolchains agreed 50/50, not zero. The task ledger was right (`hg-w1-format-drift-ceiling` sat at 8/9 with criterion 9 = "PR merged") and the prose was wrong. **This is the epic's own disease inside the epic's own record; reconciling it is a deliverable, not bookkeeping.** The sibling Go ceiling DID land separately, and its header still cross-references the Elixir script that does not exist.
- **D33. Adopt the S4 branch (D14), and harden it before landing.** `0bf3b4551` is alive with exactly 2 conflicts (both `api/test` chat controller tests) and `elixir.yml` auto-merging clean. But the script has NO min-files plausibility floor and DOES report a vacuous green on a zero-file scan — proven by mutation: a stub `mix` yields `ok: 0 drifted files, ceiling is 42.` at exit 0 and then advises LOWERING the ceiling to 0 and deleting all 42 roster paths. A vacuous green does not merely pass; it recommends demolishing the roster. The zero scan is reachable with the real toolchain (a `.formatter.exs` `inputs:` glob matching nothing exits 0). Its Go sibling has `GO_CEILING_MIN_FILES` (300), a hard floor failure, and a four-case `--selftest` run as a CI tripwire at `go-format.yml:57` — mirror all three. **The roster MUST be regenerated on the pin**: main's population is 89–90, not 92/42/39; 12 files drifted since the cut are neither rostered nor formatted by the branch and would red the new blocking job BY NAME on run one (and 12 ≥ 10 trips the script's own misleading "formatter version disagreement" note), while 9 roster entries are already clean.

### Wave 2 (2026-07-27) — TEETH, AND A MOUTH THAT CAN CLOSE

Wave Paper: `honest-gates-wave-2026-07-27`. Seven slices in three dispatch rounds. The sequencing is not preference — it is forced: you cannot require a check whose rendered name you cannot derive, cannot require a check that reds because a timer expired, and cannot enable protection before the shim exists without deadlocking the repo (D18). Protection ships LAST, and the whole wave is the prerequisite chain that makes it honest.

The required set on day one is deliberately minimal: **the shim's stable aggregator name plus `PR references an active task`** — the two contexts that provably always report. `Format` never joins it (D10). The perf bench never joins it (a wall-clock check on a shared runner is a flaky required check). Sobelow cannot join until its baseline is falsifiable (D29) and its fingerprints migrate to inline annotations.
