# API Content & Render-Engine Correctness Audit — Epic Charter

Epic task: `api-content-render-correctness-audit` (open) · Wave 1 Paper: `api-content-render-correctness-wave-2026-08-18` · Fence: `api/lib/barkpark/content` + `api/lib/barkpark/portable_doc` and their `api/test` trees ONLY. Disjoint from the cloud correctness wave (`cloud/`), the js/ SDK wave, and the `api/lib/barkpark/plugins` wave.

## Vision

A Felix-style Phoenix/Ecto **correctness** audit (non-security, improvement-only, evidence-based) of the two hottest engines in the product: the document write/publish/dedup/revision pipeline (`api/lib/barkpark/content`) and the PortableDoc render tree (`api/lib/barkpark/portable_doc`). The deliverable is an honest **per-class robustness verdict** — each class is either a confirmed bug fixed fail-safe and mutation-proven, or filed with a concrete failing scenario, or a cited SAFE verdict naming why the pattern already holds. The denominator is the deliverable: zero confirmed in a swept-and-cited class is an A-grade, and **nothing is manufactured** — a pattern already safe is cited, never dressed up as a fix. In a codebase already hardened by Felix and the content-plane security campaign, an honest lean verdict is the win: **1 built, 1 dropped, 2 filed, 6 classes swept SAFE-and-cited.**

## Decisions

- **D1 — The wave is deliberately LEAN: one built fix, two filed findings, one dropped class, six classes cited SAFE.** *Why: twelve surveyors + five verifiers swept both trees on today's origin/main with run-proofs and zero coverage deficit; the mature-codebase premise held. Manufacturing more slices would violate the wish's explicit "do not manufacture a finding."*
- **D2 — BUILD the crown as the COMPLETE `children_of/1` coercion through ALL 16 walk.ex children→Enum.map sites — NOT the two-helper guard.** The original slice guarded only `render_children/3` + `paragraph_inner/3`; verification SETTLED BY RUNNING that this is insufficient — the 6 container-routed kinds green but the 5 INLINE kinds (PdText, PdParagraph, PdHeading, PdLink, PdWikilink) still RAISE, each doing its own inline `Map.get(n,"children",[])|>Enum.map` (sites: text/3, paragraph_html/4, heading_inner/3, link/3, wikilink_label/3). PdParagraph and PdHeading are named by the mutation test, so a two-helper fix would ship them RED. The complete fix — `defp children_of(c) when is_list(c), do: c` / `defp children_of(_), do: []` routed through every site (guard on the two shared helpers + `children_of()` at the 5 inline sites, ~7 edit points) — greens all 11 kinds. *Why: the one correction the inherited direction got wrong, proven by running phase-1/2/3 probes against origin/main; all 11 kinds green, 86 existing render tests still pass.*
- **D3 — The crown is fail-safe hardening of the PUBLIC raw-tree entry, NOT a live reader 500.** Every content reader composes-first (`render_blocks`/`render_block`/`render_document`), which coerces author `"children":null` to `[]` before the walk (inline.ex, compose.ex `container_children`), so no HTTP reader route raises. The raise is structurally real only on the PUBLIC `Render.render_html/2` and `Walk.render_body/3` — reachable by the Go pdrender twin, a plugin, or a test hand-building a Pd-tree — and violates the module's own `# DEGRADE, never raise` invariant (walk.ex ~:160-175). *Why: verifier A1 refuted the reader-crash framing empirically; the fix is IDENTICAL under either framing, so the build is unblocked regardless of severity language.*
- **D4 — DECOY: `compose.ex` ~:2269 `render_children/2` already coerces non-list to `""` — do NOT patch there.** It is a DIFFERENT function (block-composition, style arg); patching it is a vacuous green. The crash lives in `walk.ex`. *Why: three surveyors independently flagged the decoy; it is the single most likely wrong-file mistake for the builder.*
- **D5 — FILE the dedup TOCTOU — do not build it.** The dedup CHECK (`AuthoringWall.enforce`, lifecycle.ex:145) runs outside/before the publish `Repo.transaction` (lifecycle.ex:173) with its own read-only txn (dedup_wall.ex) and no serializing lock; two near-dup publishes can both pass the check and both commit. Honest severity is a **quality-gate bypass** (a valid duplicate pair of published rows), not durable corruption. *Why: verifier A2 confirmed the structure; the only fix is a scope-keyed `pg_advisory_xact_lock` — the design change the wish scopes OUT, with no offline-deterministic slice (needs a concurrent-txn race harness). HIGH-FLIP write path → independent second review before any future build. Distinct from the merged #8406 / #12346 dedup work.*
- **D6 — FILE the publish-atomicity gap — do not build it — and note it BROADENS beyond publish.** `save_revision`/`save_event` (broadcast.ex:337/310) run POST-COMMIT, outside the publish txn (called at lifecycle.ex:202); the same gap is on the writer single-write path (~20 callers incl. request-reachable `POST /api/documents/:type`). The broadcast.ex "atomic" invariant comments are TRUE only for the `apply_mutations` batch path, FALSE for publish/single-write. *Why: verifier A3 confirmed it; a mutation-proof needs DB fault injection, not a unit test; a naive txn-wrap must keep `save_revision` non-fatal (savepoint) while making `save_event` roll back. HIGH-FLIP → independent review.*
- **D7 — DROP the recursion class — measured DEAD, no task.** Jason decoded a 6,000,000-level / 90MB tree in 2.95s (`:ok`, no stack blow); the 100MB request-body cap bounds max reachable nesting to ~6.6M levels and BEAM grows the process stack on the heap. *Why: verifier A4 refuted the "Jason gates first" assumption but the safety verdict holds by a different mechanism (BEAM absorbs the depth); a depth guard would be defense-in-depth with no proven-reachable failure behind it.*
- **D8 — Six classes swept SAFE-and-cited, zero confirmed, no tasks:** revision-chain (append-only immutability + `ON DELETE SET NULL`), N+1 (render tree does zero Repo calls; `expand` batched; `task_resolver` memoizes), uuid-cast-guard (both request-reachable binary_id reads guarded), changeset-gaps (`validate_required` matches NOT-NULL cols; unique_constraint names match live indexes), with-chain error handling (closed dispatch, terminal `{:error,:malformed}`), rescue-swallow (narrow/logged/reraise). *Why: the per-class denominator IS the A-grade artifact — a swept-and-cited SAFE class is a result, not a gap.*
- **D9 — Rounds are law; this wave is single-round.** The one build slice (S1) is dependency-free → round 1, builds this run; the two FILE findings are backlog, not slices. *Why: no inter-slice code dependency exists, so nothing defers to round 2.*
- **D10 — The mutation test is promoted to a committed regression test.** The verify-phase probe lived in a throwaway worktree; the builder re-creates the cases inside `render_tolerance_test.exs` (which currently exercises ONLY the compose-first path — the exact blind spot), feeding `Render.render_html/2` a `children:null` and a scalar-children node for all 11 kinds. *Why: the wave requires a mutation-proof for any built fix, and the raw-tree entry is the case the existing rig never reached.*
- **D11 — Charter PR supersedes the stalled #12390.** The prior wave stalled (builder claim lapsed, nothing merged); its charter PR #12390 is CONFLICTING on the rotating charter slot and its charter text prescribed the insufficient two-helper fix. This wave opens a clean charter PR off current origin/main with the corrected D2. *Why: reconcile-not-refound — same canonical paper and tasks, one clean PR; the lead closes #12390.*
