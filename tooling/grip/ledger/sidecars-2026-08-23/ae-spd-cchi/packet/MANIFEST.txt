=========================== TWO INSTRUMENT DEFECTS FOUND WHILE READING ===========================
1. `--filter` DOES NOT COMPOSE, AND THE CLI HELP SAYS IT DOES. `bp doc query --help` states
   "Repeatable — every --filter is ANDed". MEASURED: one filter (_id^=spd-) = 169 rows; two filters
   (_id^=spd- AND lifecycle_status=open) = 200 rows, NOT all spd- — byte-identical to the LAST filter
   alone. The lead's warning is right and the shipped help is wrong. Use one --filter and post-filter.
2. `bp doc query task -o json` RETURNS MALFORMED JSON for large task bodies. The server over-escapes
   embedded quotes, emitting a bare `\\\\"` that terminates the JSON string early; `jq` and Python's
   `json.loads(strict=False)` both reject it. Reproduce:
     bp doc query task --filter '_id^=sup-' --limit 200 -o json | jq .count
   Workaround used here: `--fields` projection (which drops the offending prose) plus a backslash-repair
   pass. A ledger whose query output a standard JSON reader cannot parse is worth its own row.
