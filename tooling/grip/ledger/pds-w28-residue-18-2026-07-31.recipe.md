## 4. Does PDS-D364's one-round deferral converge? The arithmetic.

`scripts/pds-ledger-census.sh:749-767`:

```python
live_bare_rows = [r for r in live if not disposition_of(r)]
...
(in_round if born <= anchor else live_bare_residue).append(row)
```

So, writing `B` for the live bare set and `A` for the round anchor:

```
in_round(N)  = { r in B : born(r) <= A_N }
residue(N)   = { r in B : born(r) >  A_N }
```

A round pays `in_round(N)`. Its residue becomes the **next** round's inbox. The next
round's anchor `A_{N+1}` is its own Paper's `_createdAt`, so every row filed **during**
round N+1 lands in `residue(N+1)`.

**Therefore residue(N) = 0 requires a round that files nothing.** Rounds do not file
nothing — this epic's rounds file *heavily*: **16 of these 18 rows were filed by wave 27
itself, inside a 79-minute window**, and at the pinned instant wave 28 had already
produced **15** post-anchor rows (7 of them its own slices, this task included).

**It converges on a per-row basis and does not converge on the aggregate.** Each
individual row is deferred at most one round — that part of D364 works, and it is the part
that matters for honesty. But the *count* `|residue|` is a fixed point of "whatever the
round filed", not of zero. A done-condition clause written as `residue == []` is therefore
**unsatisfiable by construction**, which is precisely why `pds-w27-round-bare-30`'s
criterion 7 cannot be flipped and why its builder was right to refuse.

The satisfiable form is the one the census already prints: `live_bare == []` over the
IN-ROUND population, with the residue **enumerated by id**, each row named rather than
merely counted.
