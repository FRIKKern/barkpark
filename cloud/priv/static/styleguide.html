Barkpark Cloud style guide

The living spec for the console. Everything on this page is rendered by the shipped app.css — tokens, scales and shared components, light and dark side by side. The same file the product loads, no copies.

Sign-off surface: changes to the mark or the brand hues merge only after a human says yes to this page (charter decision 27).

Lifecycle vocabulary

The shared task-state vocabulary — the same seven states the Go TUI paints from internal/taskboard/tokens_gen.go (GenLifecycle / GenLifecycleOrder). The glyph and ordering are the design source; the hue is a status role, so each state is colored live from --ok / --warn / --danger / --info (plus --text / --muted-text / --dim for the role-less states). Change a status hue in tokens.json and this row re-tints in lock-step with the TUI.

Console states

The cloud console's two orthogonal axes (charter azure-hetzner). Instance lifecycle is STATUS — each of the seven states maps to one semantic status role, so the pill is the single state voice (top rows) and the shared CLI/TUI glyph (below) is tinted live from that role via the generated .bp-inst--<state> classes — the same seven states the Go chrome paints from GenInstanceLifecycle in internal/semrole/chrome_gen.go. Provider is IDENTITY, never status: the chip tints its border and mark from --provider-hetzner / --provider-azure but never a pill background (DESIGN.md §5). Change a status hue or a provider tint in tokens.json and every element here re-tints in lock-step with the CLI.
