# Barkpark · Monday 16 November 2026

17 pull requests merged. Most of the day went to Barkpark's built-in Studio: two new pages for workspace admins, a Used in list for media, and four fixes to what admin pages and refusals let a viewer see. The rest made the chat API that BarkBot talks to safer when the database fails. One started this News ([#26552](https://github.com/FRIKKern/barkpark/pull/26552)).

## What a person can now do

**Webhooks page** ([#26570](https://github.com/FRIKKern/barkpark/pull/26570)). As a workspace admin, open **Webhooks** from the Studio menu, beside Search.

1. See each webhook of the dataset: address, events, type filter, on or off, and "off after failures" with the count and when it tries again.
2. Add one with a name, address, events and document types. The signing secret shows once, with a Copy button. You see it again only after **New secret**.
3. Send a test and see the result. Open a hook's deliveries (time, status code, duration, attempts) and send one again.

You see this project's hooks and the workspace-wide ones, never another workspace's or project's.

**Activity, the audit log** ([#26615](https://github.com/FRIKKern/barkpark/pull/26615)). Admins get an **Activity** tab in Studio, in English and Norwegian. It lists content changes, token mints and revocations, access grants, webhook changes, and the seat changes that SSO and SCIM make. Filter by category, by actor (type an id or click a name) and by dates; **Load more** pages back. The same rows come from `GET /w/:ws/p/:proj/v1/audit` and from `bp audit ls --category … --since …`.

**Used in, for media** ([#26535](https://github.com/FRIKKern/barkpark/pull/26535)). In the media library, select a file. The inspector lists the documents you can read that use it (title, type, Published or Draft), up to 1,000, each a link that opens the document. A file nothing uses says "Not used anywhere". `bp media usage <asset-id>` prints the same list.

**Who sees what.** Refused media and dataset deletes now name only documents you can read; the count still blocks the delete ([#26560](https://github.com/FRIKKern/barkpark/pull/26560), [#26580](https://github.com/FRIKKern/barkpark/pull/26580)). The org-admin page shows only your own workspaces' activity, and organization settings only for organizations where you are admin in every workspace, with one line saying so ([#26637](https://github.com/FRIKKern/barkpark/pull/26637), [#26648](https://github.com/FRIKKern/barkpark/pull/26648), [#26653](https://github.com/FRIKKern/barkpark/pull/26653)).

**Chat that fails safe.** On a registered computer (a chat host), when your message cannot be stored even after one retry, and no computer has started the turn yet, the turn is ended and you get a 503 that says nothing ran. If a computer has already started it, it runs and the answer is 202 ([#26632](https://github.com/FRIKKern/barkpark/pull/26632)). When the store worked but its reply was lost, the message is found by its turn key and not stored twice ([#26659](https://github.com/FRIKKern/barkpark/pull/26659)). Text holding a NUL character (U+0000), which the database refuses, is now a plain 400 before anything runs. Before, it was a 500, a 503 that failed the same way on every retry, or a 202 with the message lost ([#26657](https://github.com/FRIKKern/barkpark/pull/26657)).

## Where it is slow or rough

- Admin page reads by a token bound to one dataset write an audit row; an operator can turn on enforce mode to refuse them ([#26624](https://github.com/FRIKKern/barkpark/pull/26624)).
- Activity shows rows of this project and workspace-wide rows. Sign-ins, MFA, SSO logins, SCIM and organization changes carry no workspace, so they never show there ([#26615](https://github.com/FRIKKern/barkpark/pull/26615)).
- Used in runs a text scan of the documents on each click; each extra page of matches costs about 30 to 40 ms at 6,000 documents ([#26535](https://github.com/FRIKKern/barkpark/pull/26535)).
- The org-admin page renders English only for now; the Norwegian line is in the catalog but the page sets no Studio language ([#26653](https://github.com/FRIKKern/barkpark/pull/26653)).
- A new admin page that shows a stored HTML page in a sandboxed frame, with its age ("Stale" past 30 minutes), has no Studio tab yet; it opens by its address ([#26603](https://github.com/FRIKKern/barkpark/pull/26603), [#26607](https://github.com/FRIKKern/barkpark/pull/26607), [#26623](https://github.com/FRIKKern/barkpark/pull/26623)).

## Across the projects

BarkBot reads a chat session up to 50 times per page load, asking only for messages past the newest. Barkpark used to load every message for that and throw them away; now it loads none: 0 rows where a 500-message chat loaded 500 ([#26658](https://github.com/FRIKKern/barkpark/pull/26658)). BarkBot's own fixes the same day ([FRIKKern/barkbot#69](https://github.com/FRIKKern/barkbot/pull/69)) lean on how Barkpark orders a send: the turn goes to the computer first, and the message is stored after. The Studio app ([barkpark-studio](https://github.com/FRIKKern/barkpark-studio)) got bulk delete for ticked rows ([FRIKKern/barkpark-studio#1266](https://github.com/FRIKKern/barkpark-studio/pull/1266)). It reads each row's references from Barkpark twice and never forces the delete, so Barkpark's own refusal of a referenced document is the last check.
