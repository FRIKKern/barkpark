# Barkpark · Saturday 21 November 2026

47 pull requests merged. Seventeen went to the desk, Barkpark's own document editor, being rebuilt to match the TanStack Studio (the separate Studio app). Eight went to schemas and content, three to callouts in Papers, one to history restore and eleven to BarkUI. Two removed an old picker flow, two kept dependencies at fixed releases, and two fixed tests and tooling. One was Friday's News page.

## What a person can now do

**A type with a fixed set of documents** ([#28080](https://github.com/FRIKKern/barkpark/pull/28080), [#28182](https://github.com/FRIKKern/barkpark/pull/28182)). In a schema, list the type's document ids, for example:

```json
"fixedDocuments": ["about-page", "contact-page"]
```

1. Barkpark then refuses a new document of that type, a duplicate included, on every door: the API, `bp`, the old Studio, imports and plugins. The answer is 409 `fixed_document`.
2. A listed id that does not exist yet may be created, for a first import or to restore a deleted page.
3. A listed document cannot be deleted. One left from before the list was set still can.
4. `[]` means nothing new may be created; no list means everything works as before. Edits, publish, unpublish and discarding a draft are unchanged.
5. A singleton's list must hold its own id, the type's name, or the schema save is refused.

**A cross rule once per list item** ([#27930](https://github.com/FRIKKern/barkpark/pull/27930)). Cross rules check fields against each other. Add `"each": "menu"` and the rule runs once per object item of the `menu` list; `menu.children` checks every sub-item of every item. `"type"` keeps only items of that `_type`. A field the rule names is the item's field; `"scope": "document"` reads the document root. So every menu item can be held to link a page or an area, exactly one. Each broken item is its own finding, at a path such as `/menu/1/page`, and on an enforcing dataset an error-level item rule refuses the write. The first 50 broken items are named; the rest are one finding, "(N more items)". Later the same day:
- a rule whose `title` is not text, such as one per language, reads by its `name` ([#28089](https://github.com/FRIKKern/barkpark/pull/28089));
- a rule whose `all`, `any` or `one` is not a list is skipped and logged, like any rule the server cannot read ([#28112](https://github.com/FRIKKern/barkpark/pull/28112)).

**`"$today"` in the workspace's time zone** ([#27933](https://github.com/FRIKKern/barkpark/pull/27933)). In a schema's initial values on create, and in any query filter on every read, `"$today"` is today's date where the workspace is; `"$today.year"` is the year. A desk list filtered on `{"content.endDate": {"gte": "$today"}}` moves at midnight. A workspace with no time zone (set by `bp workspace set-time-zone`) gets the UTC date, as before. A filter value of exactly `"$today"` used to match that text.

**A cleared field stays empty on create** ([#28091](https://github.com/FRIKKern/barkpark/pull/28091)). A create that sends `null` where an initial value would land leaves that field empty and stores nothing there. A field left out still gets its initial value, and a `null` anywhere else is stored as before.

**Listen in Vision** ([#27799](https://github.com/FRIKKern/barkpark/pull/27799)). In the desk's query tool, press **Listen** beside Fetch. The query's changes show as they happen, newest first, the last 50, until **Stop**. A GROQ query must name its types (`_type == "post"`). At most 20 changes a second are shown; the rest read "N changes not shown". Fetch, another dataset or leaving Vision ends it. With Params that are not a JSON object, Listen and Fetch grey out in the Studio's colours ([#28128](https://github.com/FRIKKern/barkpark/pull/28128), [#28137](https://github.com/FRIKKern/barkpark/pull/28137), [#28153](https://github.com/FRIKKern/barkpark/pull/28153)).

**Search document types** ([#27813](https://github.com/FRIKKern/barkpark/pull/27813)). The navbar's **+** (Create new document) opens with a search box focused. Type to keep the types whose title holds the text; arrow keys and Enter open one. Nothing left reads "No results for …". On a touch screen the box and rows are 44 px.

**Undo covers more.**
- A tree codelist pick or **Remove** is one step of Mod+Z ([#27992](https://github.com/FRIKKern/barkpark/pull/27992)).
- **Paste field** and **Paste document** are undo steps, one per field written, last field first ([#27999](https://github.com/FRIKKern/barkpark/pull/27999)).
- Mod+Z on a focused checkbox or radio, or in a widget's own box such as a tree codelist's search, is the document's undo, as in the Studio ([#28127](https://github.com/FRIKKern/barkpark/pull/28127)).

**Save status in words that warn** ([#28130](https://github.com/FRIKKern/barkpark/pull/28130), [#28135](https://github.com/FRIKKern/barkpark/pull/28135), [#28139](https://github.com/FRIKKern/barkpark/pull/28139), [#28146](https://github.com/FRIKKern/barkpark/pull/28146), [#28164](https://github.com/FRIKKern/barkpark/pull/28164)). In the desk, a save that did not land ("Not saved: Title") shows in the caution colour, in the form and the footer. So does "Updated by another user" when another user saves over edits you have not saved. When you have nothing unsaved, their save comes in and the desk says nothing; the footer keeps "Edited …".

**Focus stays on a control** ([#28058](https://github.com/FRIKKern/barkpark/pull/28058), [#28106](https://github.com/FRIKKern/barkpark/pull/28106)). Opening a revision with a field focused moves the focus to the History entry shown, the first group tab or **Revert to revision**. Going Back from a revision or the published view puts it at the form's start.

**Callouts with a body.**
- The reader shows a callout's content, then each body block as a block, in the article and the email ([#28045](https://github.com/FRIKKern/barkpark/pull/28045)).
- `bp paper pull` prints the body inside `<slot name="body">`, and a push keeps it. Where a body holds a block BPML cannot write, its top-level block prints as one `<kept>` line: leave it as pulled. To delete a body, take `<slot name="body">` out. `bp paper push --check` answers what the push would ([#28022](https://github.com/FRIKKern/barkpark/pull/28022)).
- The rich editor shows such a callout read-only, each body block in order, whole or as a line naming its kind, and never writes over it. A callout with no body stays editable ([#27900](https://github.com/FRIKKern/barkpark/pull/27900)).

**A restore that names what it saw** ([#27880](https://github.com/FRIKKern/barkpark/pull/27880)). `POST /v1/data/revision/:dataset/:id/restore` takes an optional `ifRevisionID` (the rev you saw) or `"ifAbsent": true` (you saw no document). If the document has moved on, the answer is 412 and nothing is written. Without them a restore works as before.

**Harder to break.** Adding or removing a tag saves only into a tags field ([#28208](https://github.com/FRIKKern/barkpark/pull/28208)). The old reference and image picker dialogs, which no page opened, are gone from the desk and the old Studio ([#28174](https://github.com/FRIKKern/barkpark/pull/28174), [#28193](https://github.com/FRIKKern/barkpark/pull/28193)). Server dependencies are kept at fixed releases and checked daily ([#28119](https://github.com/FRIKKern/barkpark/pull/28119), [#28154](https://github.com/FRIKKern/barkpark/pull/28154)). Tests pin field options through a schema round trip, and three checks red on main pass again ([#28120](https://github.com/FRIKKern/barkpark/pull/28120), [#28039](https://github.com/FRIKKern/barkpark/pull/28039), [#28082](https://github.com/FRIKKern/barkpark/pull/28082), [#28194](https://github.com/FRIKKern/barkpark/pull/28194)).

## Where it is slow or rough

- The old Studio still shows Delete and Duplicate on a fixed type; a refused delete there says only "Failed to delete" ([#28080](https://github.com/FRIKKern/barkpark/pull/28080)).
- A callout's body cannot be edited in place yet, and source mode still opens such a Paper read-only ([#27900](https://github.com/FRIKKern/barkpark/pull/27900)).
- `"$today"` is not read in the listen stream's filter or in GROQ. On a datetime field `gte` matches from 00:00 UTC of the local date ([#27933](https://github.com/FRIKKern/barkpark/pull/27933)).
- The old Studio's history panel does not yet send the state it saw with a restore ([#27880](https://github.com/FRIKKern/barkpark/pull/27880)).
- After another user's save over a clean form, the footer's "Edited …" still counts from the edit before you opened the document ([#28164](https://github.com/FRIKKern/barkpark/pull/28164)).
