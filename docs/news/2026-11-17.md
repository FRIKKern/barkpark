# Barkpark · Tuesday 17 November 2026

86 pull requests merged. Four gave the desk new tools. The desk is Barkpark's own document editor, being rebuilt to match the TanStack Studio (the separate Studio app, [barkpark-studio](https://github.com/FRIKKern/barkpark-studio)); it is for workspace admins. Two changed how people get into a workspace. More than half went to the chat API that BarkBot and Studio chat use: text holding a NUL character, which lease a turn belongs to, answers to asks, and a resend that runs once. Two were Monday's News page and its correction.

## What a person can now do

**See what blocks Publish** ([#26685](https://github.com/FRIKKern/barkpark/pull/26685)). Open a document in the desk. While it has a problem, a **Validation** button sits in the pane header (never in the Published view).

1. Press it. A panel lists each problem with the field's place and Sanity's words, such as "Must be lower than or equal to 5". A bad value shows before you edit anything.
2. Press a problem. The desk switches to the field's group, opens folded fieldsets on the way and puts the caret in the field.
3. While an error blocks, **Publish** is off, and its tooltip says why. Warnings never block. Back and a reload keep the panel open.

**Publish or unpublish many at once** ([#26719](https://github.com/FRIKKern/barkpark/pull/26719)). In a desk list, open **List options** and pick **Select documents**. Tick rows (Shift-click ticks a range, up to 500). The **Bulk actions** bar shows "3 selected", **Clear**, **Publish selected** and **Unpublish selected**. Unpublish asks first, in a dialog with one part per document that others refer to. One message sums it up, such as "Published 2 of 3" and "1 had no changes to publish". A document deleted meanwhile counts as failed, and changing dataset drops the ticks.

**Tags** ([#26807](https://github.com/FRIKKern/barkpark/pull/26807)). In the desk, a string array with `options.layout: "tags"` is a box of chips. Type and press Enter to add one; × removes it. Removing the last tag clears the field.

**Array items** ([#26813](https://github.com/FRIKKern/barkpark/pull/26813)). Each item of an object array is a row with its title, a drag handle and a "…" menu: Remove, Copy, Duplicate, Add item before, Add item after. The item's fields open in a dialog. In a row's preview, a document link shows the linked document's title, not its id. On an array of several item types, Add item asks which type first.

**Ask for a seat** ([#26848](https://github.com/FRIKKern/barkpark/pull/26848)). A signed-in user with a confirmed email and no seat runs `bp auth access-request-create` with a workspace and an optional note. The workspace's owners and admins see it with `bp workspace access-request-ls` and approve it with a role, or deny it. Approving seats the user at once, with no invitation; only an owner can grant owner. The asker can list and withdraw their own requests. Each user gets five asks an hour and one pending per workspace.

**Sign in and land where you were** ([#26732](https://github.com/FRIKKern/barkpark/pull/26732)). Open a Barkpark page while signed out, then sign in with **Log in with Barkpark Cloud** or an emailed sign-in link: you land on that page, not on Studio. The page is remembered for 15 minutes and used once. Password, MFA, passkey, SSO and token sign-in already did this.

**Who can do what.** Over the admin API, someone who is not a listed operator changes only organisations where they are admin in every workspace ([#26699](https://github.com/FRIKKern/barkpark/pull/26699)). Barkpark can now be set to refuse workspace admin changes made with an admin key bound to one dataset, in the API and in Studio. Refusing is off by default; until it is on, each such change is recorded in a log line and an audit row ([#26724](https://github.com/FRIKKern/barkpark/pull/26724), [#26825](https://github.com/FRIKKern/barkpark/pull/26825)). A workspace import by a non-operator stays inside its own workspace ([#26822](https://github.com/FRIKKern/barkpark/pull/26822)).

**Retries that run once.** A chat message sent again with the same optional `Idempotency-Key` and the same body gets the first answer back and runs nothing ([#26689](https://github.com/FRIKKern/barkpark/pull/26689)). When the first send's answer was an error after it reached the computer's queue, the resend reuses that turn instead of starting a second one ([#26894](https://github.com/FRIKKern/barkpark/pull/26894)). On `/v1/data/mutate`, the same key with another body is now a 422, not a replay of the first answer ([#26786](https://github.com/FRIKKern/barkpark/pull/26786)). A keyed mutate that was saved but answered with an error is replayed, not run again ([#26855](https://github.com/FRIKKern/barkpark/pull/26855)). User prefs take `If-Match` and `If-None-Match: *`, so a write lands only over the value you read, or only on an unset key ([#26861](https://github.com/FRIKKern/barkpark/pull/26861), [#26891](https://github.com/FRIKKern/barkpark/pull/26891)), and a `set` changes one field of a pref object ([#26681](https://github.com/FRIKKern/barkpark/pull/26681)).

## Where it is slow or rough

- Asking for a seat has no button yet. This is the server half that Studio's no-access screen needs ([#26848](https://github.com/FRIKKern/barkpark/pull/26848)).
- The desk does not yet check that a URL field holds a URL, so "not a url" shows no problem; that rule belongs in the server's validation ([#26685](https://github.com/FRIKKern/barkpark/pull/26685)).
- The desk has no document undo. Cmd+Z after removing an array item brings nothing back ([#26813](https://github.com/FRIKKern/barkpark/pull/26813)).
- String-array rows have no drag handle or item menu yet; that waits on the object-array work above ([#26807](https://github.com/FRIKKern/barkpark/pull/26807)).
- A bulk run goes one document at a time; unpublishing 121 showed "Unpublishing 1 of 121…" up to "121 of 121…" ([#26719](https://github.com/FRIKKern/barkpark/pull/26719)).

## Across the projects
