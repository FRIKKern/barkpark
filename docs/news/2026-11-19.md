# Barkpark · Thursday 19 November 2026

31 pull requests merged. Ten went to the desk, Barkpark's own document editor, being rebuilt to match the TanStack Studio (the separate Studio app, [barkpark-studio](https://github.com/FRIKKern/barkpark-studio)); three of those also fixed the old Studio. Seven changed who may do what in a workspace. Three went to chat hosts (the machines that run a workspace's chat turns), four to Barkpark Cloud's servers, three to the BarkUI colour sheet, two to content, one to CI. One was Wednesday's News page.

## What a person can now do

**Run a query in the desk: Vision** ([#27621](https://github.com/FRIKKern/barkpark/pull/27621)). Vision sits after Structure in the navbar, More and the phone drawer, for workspace admins.

1. Type a GROQ query (Sanity's query language), or a type plus a query string such as `post?limit=5`.
2. Pick a Perspective: raw, published, or drafts (the default).
3. Press **Fetch** or Ctrl/Cmd+Enter. The result is a tree that folds, with timings, **Save result as JSON** and a copyable Query URL. A GROQ error shows a caret under the bad part.

Vision only reads, with your own session, so the query routes' own access rules answer.

**Pick Drafts or Published from the navbar** ([#27492](https://github.com/FRIKKern/barkpark/pull/27492)). A Perspective pill before Help opens a menu with Published and Drafts. It is the same choice as the pane's Draft and Published pills, so they always agree.

**The desk at phone width** ([#27492](https://github.com/FRIKKern/barkpark/pull/27492), [#27538](https://github.com/FRIKKern/barkpark/pull/27538)). Below 900 px an **Open menu** button before the logo opens a drawer with every tool, Help, the appearance buttons and Sign out. Below 600 px the bar is one 52 px row with no sideways scroll. On a touch screen every bar button is a 44 px tap, and so are the pane's Draft and Published pills up to 768 px wide; a mouse keeps the 25 px pills.

**See the published version** ([#27369](https://github.com/FRIKKern/barkpark/pull/27369)). Press the pane's Published pill. The form shows the published version, read-only, and the server refuses every write but Unpublish while it is shown. The footer reads "Last published 2h ago" or "Unpublished just now" beside **Unpublish**, which keeps your draft as it was. With nothing published the form is empty and Unpublish is greyed out.

**Undo your own typing** ([#27435](https://github.com/FRIKKern/barkpark/pull/27435)). In a top-level text field, Cmd+Z (Ctrl+Z) takes back your last change; Shift+Cmd+Z or Cmd+Y redoes it. Typing less than 600 ms apart is one change, up to 100 kept. Another editor's words in the same field stay. An undo of a field on another tab switches to that tab first.

**A URL field that holds no web address blocks Publish** ([#27443](https://github.com/FRIKKern/barkpark/pull/27443)). A `url` value must be an http or https address with no user name or password, at the top level, in objects and in array items. It is listed in Validation and Publish stays off; picking the entry puts the caret in the field, opening an array item's dialog first. Saving is never refused.

**Tree codelists** ([#27107](https://github.com/FRIKKern/barkpark/pull/27107)). A codelist is a field you fill from a fixed list of codes. In the desk, a tree codelist's search now finds a code from a paste or autofill too. Arrow keys move through the tree, Right and Left open and close, Enter and Space pick. A pick writes only into the document it was pressed in.

**Ask for a higher role** ([#27339](https://github.com/FRIKKern/barkpark/pull/27339)). A member runs `bp auth access-request-create <workspace> --role <role>`. The role must rank above the one they hold. Admins see the requested and current role in `bp workspace access-request-ls`; approving changes the seat as a role change does, so only an owner can grant owner, and nobody approves their own request. Any change to the seat after the ask makes the request stale: it cannot be approved, and asking again replaces it. This is the server side of Studio's "Ask to edit"; a database migration comes with it.

**List a workspace's roles** ([#27409](https://github.com/FRIKKern/barkpark/pull/27409)). Any seated member can run `bp workspace roles`: the built-in roles, then the custom and global ones. Names only, never who holds what.

**Chat hosts** ([#27646](https://github.com/FRIKKern/barkpark/pull/27646), [#27644](https://github.com/FRIKKern/barkpark/pull/27644), [#27634](https://github.com/FRIKKern/barkpark/pull/27634)). A workspace owner, or an agent with the owner's token, runs `bp chat-host list`, `enroll --name <name> --root <path>` and `revoke`. Enroll prints a one-time code once, inside the command to run on the machine, which feeds it on stdin, off the command line. A refused code that once worked says why (expired, replaced, revoked or used) and what to do. `new-code` waits for a server route that was not yet merged that day.

**Content.**
- Publishing now makes a waiting weak reference strong. That is a reference picked before its target was published: once the target is published (and of the type the reference names, where it names one), publish stores a normal reference. Otherwise it keeps waiting. Scheduled publishes do this too ([#27286](https://github.com/FRIKKern/barkpark/pull/27286)).
- Markdown import follows 14 cases shared with portable-doc. A link whose address the renderer would refuse keeps its text and is not a link; raw HTML keeps only its visible text; a nested list stays nested. Any value nests at most 1,000 JSON levels ([#27261](https://github.com/FRIKKern/barkpark/pull/27261)).

### Found and fixed

**Who may write.** A token's permissions now cap what its seat allows. A read-only token cannot write through workspace admin routes, even on an admin seat; signed-in sessions are judged by their role as before ([#27277](https://github.com/FRIKKern/barkpark/pull/27277)). A workspace's secrets and webhooks need a token holding the `admin` permission, not only an admin seat ([#27297](https://github.com/FRIKKern/barkpark/pull/27297), [#27334](https://github.com/FRIKKern/barkpark/pull/27334)). Workspace schema writes keep needing `write` plus an owner or admin seat, and `docs/auth.md` now says all three rules ([#27349](https://github.com/FRIKKern/barkpark/pull/27349)).

**Imports.** A workspace import never carries access requests; people ask again. The target's own requests stay exactly as they were, and the result counts what it left out ([#27448](https://github.com/FRIKKern/barkpark/pull/27448)).

**Codelist values kept as stored**, in the desk and the old Studio. A codelist can only show a code, but an import or the API can store a number, an object or a list there.
- A top-level codelist keeps such a value until you change that field. Its select reads "Not a code (kept as stored)"; "— Select —" clears it ([#27464](https://github.com/FRIKKern/barkpark/pull/27464)).
- An array of codelist values keeps each such row until that row is changed; a pick in any row still writes ([#27497](https://github.com/FRIKKern/barkpark/pull/27497)).
- A codelist inside an object field over a stored object or list opens, and an edit elsewhere keeps the value ([#27482](https://github.com/FRIKKern/barkpark/pull/27482)).

**Cloud servers.** A box's address record lives a minute in caches, a launch that can take a warm server (one kept booted and ready) says in its console whether it did and why not, a box's package installs wait for the system's package lock, and `bp cloud warm-pool` shows platform operators the worker's pool target ([#27603](https://github.com/FRIKKern/barkpark/pull/27603), [#27605](https://github.com/FRIKKern/barkpark/pull/27605), [#27607](https://github.com/FRIKKern/barkpark/pull/27607), [#27647](https://github.com/FRIKKern/barkpark/pull/27647)).

**BarkUI sheet.** The colour sheet writes a hover and a pressed fill for every control fill, on every surface, skin and mode, each step visible and the label at 4.5:1 on all three ([#27298](https://github.com/FRIKKern/barkpark/pull/27298)). Every tone has a soft fill, and a pressed one keeps its tone: a pressed warning reads amber, not beige. A sunken well has a 1 px rim ([#27257](https://github.com/FRIKKern/barkpark/pull/27257), [#27343](https://github.com/FRIKKern/barkpark/pull/27343)).

**CI** tests with the Erlang and Elixir production runs, from version files; a drift check fails any other version ([#27394](https://github.com/FRIKKern/barkpark/pull/27394)).

## Where it is slow or rough

- Undo covers top-level text fields only, not selects, lists or nested fields; the desk footer never says "Saved" ([#27435](https://github.com/FRIKKern/barkpark/pull/27435)).
- Vision has no Params, Listen, dataset picker, saved queries or CSV yet ([#27621](https://github.com/FRIKKern/barkpark/pull/27621)). Opening a tree codelist branch takes 0.2 to 0.8 s; TanStack's is instant ([#27107](https://github.com/FRIKKern/barkpark/pull/27107)).
- The perspective applies to the edit pane, not yet to lists and links; the drawer has no Tasks sidebar ([#27492](https://github.com/FRIKKern/barkpark/pull/27492)). The published view is not drawn for paper and sheet editors ([#27369](https://github.com/FRIKKern/barkpark/pull/27369)).
- A bad URL shows no error under its input, and email, integer and date rules are still to come ([#27443](https://github.com/FRIKKern/barkpark/pull/27443)).
- Kept-as-stored does not yet cover a codelist in a paper block or in a rich-text block's dialog ([#27482](https://github.com/FRIKKern/barkpark/pull/27482)).
