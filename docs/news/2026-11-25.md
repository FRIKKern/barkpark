# Barkpark · Wednesday 25 November 2026

74 pull requests merged. 49 went to two people editing one document in the desk, Barkpark's document editor, and in the Studio. Five went to chat: three closed who may use one on a workspace's registered host, and two keep a question's answers. Ten went to stored HTML and its links, two turned a NUL byte from a 500 into a 422, and one made a timing test count work instead of time ([#28710](https://github.com/FRIKKern/barkpark/pull/28710)). Four went to BarkUI, and three were the News for Sunday to Tuesday.

## What a person can now do

**Two people edit different words of one paragraph, and both are kept** ([#28781](https://github.com/FRIKKern/barkpark/pull/28781), [#28795](https://github.com/FRIKKern/barkpark/pull/28795)). Open one document in two tabs, A and B, on a rich text inside an object, holding "one two three".

1. B changes it to "ONE two three". A, before seeing it, changes it to "one two THREE".
2. Both words are stored, "ONE two THREE", with no banner (the conflict notice, "Someone else rewrote …").
3. A bold or a link on one word now merges with the other side's edit of another word ([#28802](https://github.com/FRIKKern/barkpark/pull/28802)), as does B setting the block to a heading while A fixes a word ([#28817](https://github.com/FRIKKern/barkpark/pull/28817)).
4. Both typing in the same word is still a clash: one side is held under the banner with its words in the form, and typing on saves them.

In the Studio, a clean merge no longer says "Updated by another user" ([#28907](https://github.com/FRIKKern/barkpark/pull/28907)).

**Two saves at the same moment no longer lose one in silence** ([#28792](https://github.com/FRIKKern/barkpark/pull/28792)). A save B landed while A's was being written went under A's with no banner: in Chrome, 2 of 5 desk runs and 4 of 4 Studio runs. Now A's post is read again under the document's lock and merged, or held under the banner: 0 silent losses in 10 runs on each. The same now holds for a string field ([#28803](https://github.com/FRIKKern/barkpark/pull/28803), [#28821](https://github.com/FRIKKern/barkpark/pull/28821)), a rich text in an array row ([#28898](https://github.com/FRIKKern/barkpark/pull/28898)), and the Save button ([#28826](https://github.com/FRIKKern/barkpark/pull/28826), [#28832](https://github.com/FRIKKern/barkpark/pull/28832), [#28840](https://github.com/FRIKKern/barkpark/pull/28840)). Two tabs replacing the same letter of a string field lost A's letter in 6 of 6 Chrome runs; now every letter of both survives ([#28833](https://github.com/FRIKKern/barkpark/pull/28833)).

**A page that reconnects keeps its typing and the other editor's** ([#28779](https://github.com/FRIKKern/barkpark/pull/28779), [#28830](https://github.com/FRIKKern/barkpark/pull/28830), [#28850](https://github.com/FRIKKern/barkpark/pull/28850), [#28855](https://github.com/FRIKKern/barkpark/pull/28855)). A page that rejoins the server and posts typing done on the old value is held under the banner, not written over B's save. A field the post was not about, posted as A's page showed it before B's save, is put back to B's value and redrawn. Reload sends the page every string it changed.

**Typing and IME input go where they were** ([#28716](https://github.com/FRIKKern/barkpark/pull/28716), [#28723](https://github.com/FRIKKern/barkpark/pull/28723), [#28735](https://github.com/FRIKKern/barkpark/pull/28735), [#28732](https://github.com/FRIKKern/barkpark/pull/28732), [#28856](https://github.com/FRIKKern/barkpark/pull/28856)). When B adds "X " at the start of A's paragraph, A's next letter lands at A's caret, not at the end; a selection stays, and a double space survives. An IME, the input method for Japanese and similar scripts, is left alone: nothing is posted or drawn mid-composition.

**The Studio asks before it drops held words** ([#28836](https://github.com/FRIKKern/barkpark/pull/28836), [#28891](https://github.com/FRIKKern/barkpark/pull/28891)). While a field is held, a link that leaves asks "Not saved: Notes. What you typed there will be lost." A list row, a crumb or New document stops once with that line and "Press again to leave." The banner now lists every block of theirs the view lacks, not five ([#28809](https://github.com/FRIKKern/barkpark/pull/28809)), and folds those past five under an "N more" line.

**A chat on a person's own computer is for its owners** ([#28693](https://github.com/FRIKKern/barkpark/pull/28693), [#28844](https://github.com/FRIKKern/barkpark/pull/28844), [#28848](https://github.com/FRIKKern/barkpark/pull/28848)). A registered host is a computer a workspace owner enrolled; its chats carry that computer's files and command output, and any member with chat access could use them. Now only an owner or admin seat in the workspace, or a token whose owner holds the owner seat, may create, drive or see one. Anyone else gets a 403 on create and a random id's 404 elsewhere; the fleet stream and rollup leave it out. Each new chat records who made it. An answered question now keeps the chosen answers after a reload, over the API and from the Studio's form ([#28852](https://github.com/FRIKKern/barkpark/pull/28852), [#28905](https://github.com/FRIKKern/barkpark/pull/28905)).

**A script link in stored HTML is refused** ([#28695](https://github.com/FRIKKern/barkpark/pull/28695), [#28711](https://github.com/FRIKKern/barkpark/pull/28711)). A write that brings a `javascript:`, `vbscript:` or `data:` link into a rich text stored as an HTML string is a 422 naming the field, and the Studio shows the reason under it. An address the row already held stays editable. A workspace bundle import keeps a Portable Text link with such an address, moves the address out of reach and names it in the import's stats ([#28728](https://github.com/FRIKKern/barkpark/pull/28728)). A bundle whose rows Postgres would read another way, and might import in part, is refused ([#28736](https://github.com/FRIKKern/barkpark/pull/28736), [#28739](https://github.com/FRIKKern/barkpark/pull/28739)).

## What got harder to break

- Seven fixes closed ways a save dropped a change with no word: B's earlier change read as A's delete ([#28755](https://github.com/FRIKKern/barkpark/pull/28755)), more than 8 waiting saves ([#28762](https://github.com/FRIKKern/barkpark/pull/28762)), one document's text written into the next one opened ([#28766](https://github.com/FRIKKern/barkpark/pull/28766)), a hold's view missing a change ([#28801](https://github.com/FRIKKern/barkpark/pull/28801), [#28806](https://github.com/FRIKKern/barkpark/pull/28806)), and block fields the editor does not draw ([#28867](https://github.com/FRIKKern/barkpark/pull/28867), [#28883](https://github.com/FRIKKern/barkpark/pull/28883)).
- Stored ids in an old Paper's HTML move into their own namespace, so a stored `id="paper-body"` cannot take the page's place; links to them still land ([#28659](https://github.com/FRIKKern/barkpark/pull/28659), [#28700](https://github.com/FRIKKern/barkpark/pull/28700), [#28709](https://github.com/FRIKKern/barkpark/pull/28709)).
- A NUL byte in a document, task or session write is a 422 naming where it is, not a 500 that invites a retry ([#28712](https://github.com/FRIKKern/barkpark/pull/28712), [#28715](https://github.com/FRIKKern/barkpark/pull/28715)).
- An old Paper's cleaned HTML is cached: a 2 MB body that takes 1,003 ms to clean is served again in 0.81 ms ([#28731](https://github.com/FRIKKern/barkpark/pull/28731)).

## Where it is slow or rough

- A top-level rich text field still has the race: the same word stores A's with no banner, and different words lose B's. Only rich text in an object or an array row is read under the lock so far ([#28898](https://github.com/FRIKKern/barkpark/pull/28898)).
- Past 15,000 inline objects the merge inside one block is not tried, and two different edits are a clash ([#28882](https://github.com/FRIKKern/barkpark/pull/28882), [#28893](https://github.com/FRIKKern/barkpark/pull/28893)).
- A page that typed while away, with no other save, gets a needless banner on rejoin, losing no words ([#28830](https://github.com/FRIKKern/barkpark/pull/28830)). On the desk, typing done while offline for more than 15 s was lost, before this change and after ([#28779](https://github.com/FRIKKern/barkpark/pull/28779)).
- The Studio's browser Back does not ask yet ([#28836](https://github.com/FRIKKern/barkpark/pull/28836)).
- A bundle import does not read links inside a rich text stored as an HTML string ([#28728](https://github.com/FRIKKern/barkpark/pull/28728)). A Connector chat token has no owner, so it cannot drive a host chat even when an owner minted it ([#28693](https://github.com/FRIKKern/barkpark/pull/28693)).
- Most of these PRs were not run in a browser; five were checked in real Chrome, among them the two-saves fixes ([#28792](https://github.com/FRIKKern/barkpark/pull/28792), [#28833](https://github.com/FRIKKern/barkpark/pull/28833)).
