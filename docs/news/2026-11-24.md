# Barkpark · Tuesday 24 November 2026

13 pull requests merged. Eleven went to BarkUI, the UI parts kit in this repo: eight new parts in its showroom and three to its check. Two closed ways a `javascript:` link reached the old Studio's rich text editor.

## What a person can now do

**The link dialog refuses an unsafe address** ([#28655](https://github.com/FRIKKern/barkpark/pull/28655)). In the old Studio, open a rich text field.

1. Select some words and add a link with the address `javascript:alert(1)`, in the toolbar's link row or the annotation dialog.
2. The row or the dialog stays open and says, in TanStack's words: "Use a web, mail or phone address (https:, mailto:, tel:) or a path." Nothing is saved. The same holds for mixed case, leading spaces, a tab inside, an entity-encoded letter, `data:text/html`, `vbscript:` and `//host`.
3. Put the address right: the reason goes and the link saves. A bare domain still gets `https://`.

Before, both paths took any address; the next save dropped it, but it had already reached the editor. It was found in the review of Sunday's link fix ([#28371](https://github.com/FRIKKern/barkpark/pull/28371)).

**A legacy HTML rich text draws safely** ([#28402](https://github.com/FRIKKern/barkpark/pull/28402)). A rich text field stored as an HTML string, not Portable Text, was put in the old Studio's editor as stored. Now a refused link draws as its words, script-bearing elements and handlers are removed, and an `onerror` written after a `/` or a quote is renamed so it never runs. Only what the editor shows changes: an edit of another field saves the stored string byte for byte. This covers a top-level rich text field and a rich row of a localized text.

## BarkUI

Told in [its own README](../../js/packages/barkui/README.md): eight parts joined the showroom, from the select ([#28362](https://github.com/FRIKKern/barkpark/pull/28362)) to the segmented control ([#28669](https://github.com/FRIKKern/barkpark/pull/28669)), and the check reads each part with the other stages hidden ([#28654](https://github.com/FRIKKern/barkpark/pull/28654)).

## Where it is slow or rough

- #28402 and Monday's parser rewrite of the legacy HTML cleaner ([#28404](https://github.com/FRIKKern/barkpark/pull/28404)) both guard against the same `onerror` spelling. With both landed, #28402's rename is redundant but harmless, and can be dropped later ([#28402](https://github.com/FRIKKern/barkpark/pull/28402)).
- A rich text subfield inside an object draws only Portable Text in this editor; a string there goes to a plain input ([#28402](https://github.com/FRIKKern/barkpark/pull/28402)).
- In BarkUI, the select is the one part still over two thirds of its time limit on a slow runner; its own top-layer readings set its time ([#28654](https://github.com/FRIKKern/barkpark/pull/28654)).
