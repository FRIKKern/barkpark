# Barkpark · Friday 27 November 2026

40 pull requests merged. 33 went to two people editing one document, in the desk, Barkpark's document editor, and in the Studio: 16 to a top-level rich text such as a body, 6 to rich text inside rows, 6 to a reference or image another editor picked, and 5 to writes made while a field is held. 3 went to seats and the cache of the default workspace, 2 to CI, one to the README's new look, and one was the News for Thursday.

A held field is one under the conflict banner: another editor's save is stored, and your words wait in the form. A rejoin is a page that lost its connection and came back on the same page. "Under the lock" means the server reads the stored row while it holds the document's lock, just before it writes.

## What a person can now do

**Words typed while the page was away are kept, and so is the other editor's save** ([#29054](https://github.com/FRIKKern/barkpark/pull/29054), [#29065](https://github.com/FRIKKern/barkpark/pull/29065)). Both were checked in headless Chrome, with A's connection cut through a proxy so the page rejoined.

1. Open a document with a body in two tabs, A and B. Type in A.
2. Let A's connection drop, and type on in A.
3. If B saves the body meanwhile, A's next key keeps B's body stored and holds A with the banner and "Autosave is paused for Body until you Save or Reload." On Thursday B's words were lost with no banner. Save writes A's words; Reload ends the hold.
4. If nobody saved, A's offline words are written, also when the form had been drawn again before the drop. In that case main lost them: the store read "body0 B4 A1 A8", and now it reads "body0 B4 A1 A7 A8".

The held body keeps its editor; before, it fell back to read-only text and a Save could not post it ([#29057](https://github.com/FRIKKern/barkpark/pull/29057)). A redraw caused by another field keeps it held ([#29062](https://github.com/FRIKKern/barkpark/pull/29062)). A save A sent before B's save reached A's page now merges or holds too, without a rejoin ([#29098](https://github.com/FRIKKern/barkpark/pull/29098)). Show more, a sort pick, Publish, Unpublish and a bulk action no longer leave a false hold after a rejoin ([#29110](https://github.com/FRIKKern/barkpark/pull/29110)).

**What the page drew is told apart by 64 bits.** The fingerprint a page sends of the value it shows was 27 bits, and "title 15779" and "title 19776" shared one, so a post typed on one read as typed on the other and was written over B ([#29073](https://github.com/FRIKKern/barkpark/pull/29073)). It is now 64 bits of sha256, also for rich text in rows and objects, where `<p>row text 1120</p>` and `<p>row text 8568</p>` collided ([#29142](https://github.com/FRIKKern/barkpark/pull/29142)).

**More kinds of body are read under the lock.**

- A body stored as an HTML string is held as a block body is, and kept byte for byte: an image, an iframe or a class B adds is no longer dropped by the compare ([#29063](https://github.com/FRIKKern/barkpark/pull/29063), [#29066](https://github.com/FRIKKern/barkpark/pull/29066), [#29144](https://github.com/FRIKKern/barkpark/pull/29144), [#29156](https://github.com/FRIKKern/barkpark/pull/29156)). The same holds for a Portable Text field that an API write left holding a string ([#29116](https://github.com/FRIKKern/barkpark/pull/29116)).
- A field B removed stays removed and A is held ([#29148](https://github.com/FRIKKern/barkpark/pull/29148)). B's words in an empty field are kept under A's first words there ([#29177](https://github.com/FRIKKern/barkpark/pull/29177)).
- A body A cleared takes A's next words. A cleared editor can post `<br>`, `<p></p>` or `<p><br></p>`, and on main 12 of the 16 test cases dropped the next words ([#29174](https://github.com/FRIKKern/barkpark/pull/29174)).
- A merge of new blocks keeps each side's order ([#29185](https://github.com/FRIKKern/barkpark/pull/29185)).

**Rich text inside rows.** A rich text nested in a row's own array or object is now merged or held, where main wrote it as posted: 10 of 12 new tests failed there ([#29164](https://github.com/FRIKKern/barkpark/pull/29164)). A post in flight across a row insert or move is read under the lock ([#29165](https://github.com/FRIKKern/barkpark/pull/29165)). Sections whose rows share keys, as after a duplicate, draw and match their own rows ([#29171](https://github.com/FRIKKern/barkpark/pull/29171), [#29206](https://github.com/FRIKKern/barkpark/pull/29206)), and a row with no key is read against the row with no key at its index ([#29178](https://github.com/FRIKKern/barkpark/pull/29178)).

**A reference or image A did not change keeps B's pick** ([#29075](https://github.com/FRIKKern/barkpark/pull/29075)). The widget is drawn once, so after a rejoin a key A typed in the body posted A's old reference and wrote it over B's pick. Now that post is dropped, and that widget alone is drawn again, showing B's pick; the body A types in is not redrawn. The same holds when B's save has not reached A's page yet ([#29085](https://github.com/FRIKKern/barkpark/pull/29085)), after a remote replace ([#29133](https://github.com/FRIKKern/barkpark/pull/29133)), and for a pick from the old drawing after B's undo ([#29160](https://github.com/FRIKKern/barkpark/pull/29160)). A pick A makes is still written, also one in flight across B's redraw and a re-pick on the desk after it ([#29139](https://github.com/FRIKKern/barkpark/pull/29139), [#29146](https://github.com/FRIKKern/barkpark/pull/29146)).

**Writes made during a hold keep it.** Paste field, undo, Review changes' Revert and Paste document on the desk keep the banner and the paused line ([#29071](https://github.com/FRIKKern/barkpark/pull/29071)). An array op on the held field's own object keeps B's value there, and takes B's newest save ([#29078](https://github.com/FRIKKern/barkpark/pull/29078), [#29102](https://github.com/FRIKKern/barkpark/pull/29102)). A whole-document clash, which no path reaches today, now holds the fields A's words differ in ([#29067](https://github.com/FRIKKern/barkpark/pull/29067)). On the desk, a typed post or an array op that lands during a hold keeps its undo step ([#29129](https://github.com/FRIKKern/barkpark/pull/29129)).

**A lost seat ends a host chat stream** ([#28989](https://github.com/FRIKKern/barkpark/pull/28989)). A host chat runs on a person's own computer. An owner demoted to member, or removed from the workspace, kept an open stream of that chat until the client reconnected. Now the stream gets one `unauthorized` frame and ends on the next re-auth tick, every 2 s, and the fleet stream stops that chat's frames.

**The default scope cache follows rollbacks.** It names the default workspace and project. A raise inside a write's transaction skipped the bust, so a rolled-back seat was served for the cache's 60 s; now the bust runs on every exit ([#29077](https://github.com/FRIKKern/barkpark/pull/29077)). Nested inside a plain transaction, the bust came before the outer commit, so the wrapper now refuses that nesting with an error before anything is written ([#29138](https://github.com/FRIKKern/barkpark/pull/29138)).

**The README** opens with a knitted band of the park and Maske, the spitz, then what you can do, a "Where we're going" table for the alpha in December, with the focus on good and stable, and the seven repos of the family ([#29015](https://github.com/FRIKKern/barkpark/pull/29015)).

**CI.** Chrome 158 spells a computed `flex-start` as `"flow-start"`, which turned the required Console gate red on every PR touching console paths; the overflow guard now takes both ([#29070](https://github.com/FRIKKern/barkpark/pull/29070)). The paper bundle gate's host test now runs in CI; it never had ([#29083](https://github.com/FRIKKern/barkpark/pull/29083)).

## Where it is slow or rough

- A reference or image inside an object or a row is not read this way yet ([#29075](https://github.com/FRIKKern/barkpark/pull/29075), [#29133](https://github.com/FRIKKern/barkpark/pull/29133)). Filed as a task.
- After a rejoin, A's first pick back to the old value is dropped and the widget drawn again; a pick made again is written ([#29139](https://github.com/FRIKKern/barkpark/pull/29139)). A page that left before its own clear was confirmed is held after the rejoin ([#29148](https://github.com/FRIKKern/barkpark/pull/29148)). A page open across the deploy is held once on its next rejoin; a Save clears it ([#29073](https://github.com/FRIKKern/barkpark/pull/29073)).
- Two row cases still write into the wrong place: a duplicate row key, and a post with no key landing on a keyed row ([#29178](https://github.com/FRIKKern/barkpark/pull/29178)).
- A page that took more than 8 changes of one field from others before its post arrives reads as before ([#29098](https://github.com/FRIKKern/barkpark/pull/29098)).
- Of the two-editor PRs, two were run in a real browser ([#29054](https://github.com/FRIKKern/barkpark/pull/29054), [#29065](https://github.com/FRIKKern/barkpark/pull/29065)); the rest were checked by tests only.
- CI's runners mix Chrome 157 and 158, so CI tested only the old spelling; the new one was checked locally ([#29070](https://github.com/FRIKKern/barkpark/pull/29070)).
