# CycleFleet HTTP contract

CycleFleet is the immutable, profile-driven execution ledger shared by Epic and Legendary Codex cycles. The canonical root is `/w/:workspace_slug/p/:project_slug/v1/cycles/:epic_id/:wave_id`; resolved path scope is authoritative. Flat `/v1/cycles/*` routes are token-workspace-bound, projectless legacy routes and never alias a project row.

## Authorization and routes

- `GET …` requires a normal `read` token and returns exactly `{cycle_ledger, fleet, assignment_attributions, authority}`. `assignment_attributions` is the insertion-ordered immutable retrieval seed; it is not nested under `fleet`. Public-read-only tokens receive `403` on both route shapes. `authority.connection` identifies local/remote execution from the configured canonical server origin (never request `Host`) and returns that origin plus persisted workspace/project scope and the connected cloud URL.
- `POST …/open` requires `write` and freezes profile, inventory, and experiment intent. Legendary also freezes the complete scale contract. Exact replay returns the original wave; changed input returns `409`.
- `POST …/seal` requires `write` and freezes capacity, format, evidence revision, failure contract, golden fixtures, opening rubric, and Build plan. Legendary requires the exact completed Experiment fleet with no dangling failed/cancelled leaf before sealing; Build requires the seal.
- `POST …/assignments` requires `write` and appends a typed snapshot. Planned phase counts are hard capacities: Epic has exactly three Review assignments; Legendary Experiment and Review each have exactly 15 live assignments; Experiment closes at seal. Effort is exact: Epic Survey/Verify are `medium`, Build/Review are `high`; Legendary Survey/Verify/Experiment/Build are `medium`, Review is `high`. Legendary inventory has at least 15 real units (never padding). Every Build snapshot, including a replacement, owns a non-empty unique list of non-empty string inventory unit ids and must not exceed sealed `proven_batch_capacity`.
- Canonical scoped assignment writes may include a physical `task_id`. The server derives workspace/project authority from the path and freezes the same-project Task binding in the assignment transaction; malformed, missing, non-Task, or cross-scope authority returns `422` and rolls the assignment back. Replays may omit or repeat an existing binding but never add or replace one (`409`); flat projectless legacy writes remain valid without `task_id`. Caller-authored scope or claim facts are never accepted as binding authority.
- Assignment writes and the cycle projection expose an additive immutable retrieval attribution seed: physical `cycle_assignment_id`, physical `cycle_wave_id`, logical `assignment_id`, exact `unit_ids` (empty outside Build), the wave `inventory_digest`, and the assignment `snapshot_digest`. `assignment_attributions` is insertion-ordered, project-scoped, append-only, and exact replays retain the original physical identity and attribution.
- `POST …/assignments/:assignment_id/results` requires `write` and appends or exactly replays one terminal result. Conflicting assignment/result replays return `409`.

## Retrieval benchmark v2/v3

The canonical artifact envelope remains exactly `{format, ledger, attribution, attribution_digest, ledger_digest}` with format `barkpark-epic-benchmark-v2`; `ledger` remains the byte-compatible v1 artifact. Legacy retrieval contract/attribution schema v2 remains importable. Schema v3 adds exact `cycle_phase` and preserves the physical CycleFleet `unit_ids`: Build has its one bound corpus unit, while every non-Build phase has `[]`. The logical `assignment_id`, not Build ownership, binds each attribution to the identically named corpus record. This permits the six Task-bound Epic Verify assignments without fabricating Build ownership.

The manifest freezes `retrieval_attribution_contract`. Contract and attribution corpora carry `{sha256, repo_commit, schema_version, unit_ids, claim_domain, claim_domain_digest}`. `claim_domain` is keyed exactly by corpus unit/assignment id, each value is a unique non-empty claim-id list, and its digest is canonical JSON SHA-256. Every contract, attribution, and trial assignment must retain the outer experiment `epic_id`/`wave_id`. The cross-runtime gate executes the Python producer and imports its exact emitted attribution through Elixir; copied digest vectors alone do not prove the handoff.

Observed usage requires opaque provider session/turn/counter identities, monotonic non-negative integer token counters, exact token delta, and typed context occupancy. Unavailable usage is exactly `unsupported`, `missing`, or `invalid` with a non-empty reason and `unit: "tokens"`. Observed VUI is a non-negative integer equal to `verified_claim_ids` length; verified/missing/contradicted/unsupported claim lists are individually unique, mutually disjoint, contain no IDs outside the assignment claim domain, and exactly partition it. An observed VUI has no non-verified claims. Unavailable VUI is reason-only or carries the same exact claim partition with `unit: "claims"`.

## Replacement and reconciliation

`replaces_assignment_id` is the logical assignment id in the exact cycle scope. Immutable phase and agent-type mismatches are reported as `409` before generic profile validation. A project-scoped lookup never searches another project: a same-named cross-project predecessor remains `replacement_not_found` (`422`) to hide its existence. On projectless compatibility routes, a same-workspace legacy EpicFleet predecessor can be identified safely and returns `replacement_contract_mismatch` (`409`) because it is not bound to the immutable CycleFleet wave. Only a failed or cancelled matching predecessor may be replaced; pending and completed predecessors remain `422`. One predecessor has at most one successor, producing a linear chain; a distinct concurrent loser returns `assignment_already_replaced` (`409`). Replaced attempts remain historical, while the live leaf determines reconciliation.

Reconciliation is exact only when every planned phase has its exact completed live fleet at the profile's exact effort, no live failed/cancelled or result-missing leaves remain, assignments/results are valid, and each completed Build result supplies all three typed outcome lists that exactly partition its owned units without overlap. Epic may reach exact without a post-Pilot seal. Epic and Legendary Paper preflight compare embedded `cycle_ledger` and fleet projections with explicitly workspace/project-scoped live CycleFleet. An Epic Paper may omit its ledger only when the explicit legacy validator flag is supplied, live `--paper` retrieval provides immutable `_createdAt`, and that timestamp proves creation before the documented `2026-07-15T00:05:00Z` CycleFleet cutoff. Caller-controlled `--paper-json` remains valid for ledger-bearing validation but can never establish this legacy exception.

The manifest deliberately publishes canonical scoped CycleFleet path templates directly. This is the exception to the otherwise deferred `scoped_prefix` mirror hint: clients resolve `:workspace_slug` and `:project_slug` from explicit context, while flat routes remain projectless compatibility only.

Workspace/project teardown removes tenant-owned cycle ledger rows through guarded parent deletion. Direct updates/deletes remain forbidden.
