View ↔ Edit parity · pd-doctrine rule 3

View ↔ Edit render-path parity matrix

Slice au-w5-paper-parity-w3 · render-path unification · 2026-07-05

The PortableDoc editor renders a document on two surfaces that a user toggles between: the View (the public /papers/:slug reader and the Studio View pane) and the Edit canvas. Doctrine rule 3 demands they look byte-for-byte identical — same producer. This audit enumerates every block type that emits visible HTML, diffs the View emitters against the Edit CSS, adversarially verifies each candidate divergence, and installs a machine-checkable drift tripwire so the parity can never silently regress (the seed the M3 spine — t8 fleet-in-canvas, t10 parity gate — extends).

The two paths, one producer

View
render.ex · :article
Emits bare semantic HTML — <h1>, <p>, <ul> — with no competing inline style (roles/tones/chrome carry bp-* classes).
Edit
ProseMirror · .bp-paper-editor-body
Emits the same semantic tags; typography from the .bp-paper-editor-body <el> rules in root.html.heex.
Single source
paper-surface.css → Stylesheet.css/0
The --bp-* typography tokens + the .bp-paper-surface <el> rules. Both surfaces resolve THESE tokens — parity by construction, not hand-matched mirrors.

Because the article renderer emits bare tags and both surfaces descend from .bp-paper-surface and read the same --bp-* tokens, typography values already cannot drift. The only residual surface is cross-file: a property changed on .bp-paper-surface <el> (in the CSS source) without the matching change to .bp-paper-editor-body <el> (in root.html.heex), or vice-versa. That is exactly what the new tripwire closes.

Drift tripwire (the parity gate seed)

test/barkpark/portable_doc/render/view_edit_parity_test.exs parses the two live sources — Stylesheet.css/0 (View) and root.html.heex (Edit) — and asserts, for every shared (element, property) pair, a byte-identical value; that every --bp-*/--paper-* token the editor typography references is defined in the single source (no dangling token); and that article prose emits bare tags with no inline style. A parser-sanity guard fails loudly if a selector rename would empty the diff into a vacuous pass. The intentional list-margin divergence is encoded as a guard so re-introducing it into Edit trips the wire.

The wire also covers the third copy: Studio loads only the root.html.heex inline rules (BP_PAPER_EDITOR_NO_INJECT) while embedders load only assets/paper-editor/src/styles.css — two hand-kept mirrors whose sole prior enforcement was "keep byte-aligned" comments. The same shared-pair diff now runs Studio↔bundle across h1…hr + pre.bp-canvas-code, so the embedded editor cannot silently stop looking like the canvas.

Adversarially verified, both wires: mutating the editor p margin to a literal 20pt 0 0 produced the expected View↔Edit failure (p.margin: View="var(--bp-para-margin-top) 0 0" Edit="20pt 0 0"); mutating the bundle p margin to 19pt 0 0 produced the expected Studio↔bundle failure. Reverting restored green both times. The gate catches real drift, not noise.

Methodology

Phases: Enumerate the article block types (compose.ex) → Sources extract the View emitters (render.ex, render/walk.ex, render/stylesheet.ex) and the Edit CSS (root.html.heex .bp-paper-editor-body) → Diff per element × property → Verify (static equality + a live render-output emit check + mutation tests on both tripwires) → Report (this document). Basis is static analysis plus render-output. Candidate #2 was subsequently resolved statically (light-DOM mount + surface ancestor + no competing rule — cascade outcome is deterministic); #3 (slash-menu chrome palette) remains flagged for a separate task, not closed.

Re-run

The tripwire re-runs every CI cycle via mix test test/barkpark/portable_doc/render/view_edit_parity_test.exs (part of the render suite gate). The full adversarial audit workflow is view-edit-parity (.claude/workflows/view-edit-parity.workflow.js), invoked via the Workflow tool with that name.
