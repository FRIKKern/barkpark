## The defect, measured before the fix

`Console gate` is one of the four required contexts. When a diff touches none of
its declared path sets it concludes `success` having executed nothing, and the
only thing separating that green from a measured one is a single `::notice::`.
Read straight off the check-runs API:

```
$ gh api repos/FRIKKern/barkpark/commits/22dc98ba7/check-runs \
    -q '.check_runs[] | select(.name=="Console gate") | ...'
# PR #18693, docs-only diff — NOTHING RAN
id=104959107612 concl=success title=null summary=null text=null ann=1

$ gh api repos/FRIKKern/barkpark/check-runs/104959107612/annotations
notice | Console gate: green — nothing ran | NOTHING CONSOLE RAN on this head. …

# PR #18686, cloud/lib diff — the harness RAN
id=104959198409 concl=success ann=0
```

`title`, `summary` and `text` are null on every Actions check run, the name is a
frozen required context, and the whole disclosure is ONE annotation. GitHub keeps
the first 10 annotations per level per step and drops the rest silently, so any
future step that emits ten notices deletes the disclosure and leaves the green.

## The fix

A check run's NAME is not rationed, and `jobs.<job_id>.name` accepts the `needs`
context. `console-gate-subject` publishes one of three names off
`needs.console-gate.outputs.nothing_ran`:

* `Console gate subject: NOTHING CONSOLE RAN — that green is NOT APPLICABLE to this diff`
* `Console gate subject: the console harness RAN and measured this head`
* `Console gate subject: the Console gate is NOT GREEN — read it, not this`

`nothing_ran` is an output of the very `if [ "$dispatched" -eq 0 ]` branch that
emits the notice, not a re-read of the dispatcher output, so the two channels are
one measurement rendered twice. The notice is unchanged and stays where it is.

## Ratchet change, and why it is stronger

Both shape ratchets pinned `coe_jobs = ""`, which forbids the reporter this
needs. Replaced with a predicate plus an exact roster: a continue-on-error job is
admitted only as a POST-GREEN REPORTER — `needs == [<aggregator>]` exactly, `if:`
exactly `always()`, continue-on-error true, and named by no other job's `needs` —
and the roster of those is pinned by name. `coe_in_needs = ""` is untouched.
