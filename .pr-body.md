## The leak reproduces today

Measured live on 2026-09-16 with a local server that records the `Authorization`
header of every request it receives (invented credential, 41 chars; nothing here
authenticates against anything):

```
config.json saved for https://guerrilla.barkpark.cloud
$ bp -s http://127.0.0.1:47391 task ready
  -> GET /v1/capabilities?views=1&chat=1   Authorization: Bearer <41 chars>
$ BARKPARK_API_URL=http://127.0.0.1:47391 bp task ready
  -> GET /v1/capabilities?views=1&chat=1   Authorization: Bearer <41 chars>
```

The credential leaves on the **first** request bp issues — the manifest fetch,
before any command dispatch. Controls: the same run against the server the
credential IS saved for records all 41 chars (so "it is never used" is refuted),
and an unconfigured `bp` records 18 (`barkpark-dev-token`, the baked floor).

After this change the two mismatched arms record 18 and the matching arm still
records 41.

## The decision

**Bind, and withhold** — not a rendering tweak, and not "keep them independent and
warn". The predicate is narrow on purpose: it fires only when the token won at the
**active layer** (saved `config.json`, or a repo `.barkpark.json` naming a saved
entry), which is the only layer that *records which server its credential belongs
to*. A typed `--token`, an exported `BARKPARK_API_TOKEN`, and `bp -s <saved-name>`
are the operator pairing the two themselves in this invocation, and are untouched.

**The loser, named.** The operator who deliberately points a saved credential at a
host they did not save it for: they must now say so, with `--token` or
`BARKPARK_API_TOKEN`.

**What it costs the dev flow, priced explicitly.** `BARKPARK_API_URL=localhost` on
top of a saved remote config does **not** break, because the withheld credential
falls to `bakedDefaults().Token` (`barkpark-dev-token`) and **not to empty**.
Falling to empty is exactly the false-404 shape `hq-doc-get-auth-tier-gap` existed
to kill — the cure and the disease being the same shape is why the previous builder
declined to ship this — and the dev floor is what a localhost instance wants anyway.
`-s <saved-name>` is unaffected (server and token are injected together, matched by
construction); `-s <raw-url>` at a host that is not the saved one withholds and
prints a two-line stderr notice naming both hosts plus the fix.

**Not decided here:** whether an anonymous CLI tier should exist. The floor is a
public well-known constant (docs/auth.md §Dev token), so sending it discloses
nothing; making it empty is a contract change across every tier-`none` verb.
`TestNoCLIInvocationResolvesAnEmptyToken` stays a characterization test and now
says on itself that **change nothing** was the decision, and why.

## The guard is on the wire, not on the output

`TestNoAuthorizationHeaderCarriesASavedCredentialToAMismatchedHost` enters through
`Execute` — the real path, manifest fetch included — against an `httptest` server
that records the `Authorization` header of **every** request, and asserts the saved
credential appears in none of them (and that at least one request arrived, so the
test cannot pass by never reaching the server). Its sibling subtest is the control:
the matching host still receives it.

### Mutation-proved, three directions

| mutation | red |
|---|---|
| remove the binding block | `BINDING GONE …` (resolution) **and** `LEAK: the credential saved for … reached …` (wire) |
| drop the `normalizeServerURL(...) != ...` conjunct so it withholds everywhere | `CONTROL FAILED (bare invocation, active layer)` **and** the wire control |
| withhold to `""` instead of the floor | `withheld token fell to "", want the baked floor` |

The over-fire arm is the one that matters most: a binding that withholds everywhere
passes the leak arm and silently unauthenticates every command. Note the `-s
<saved-name>` control alone did **not** catch it (that token wins at *flag*
precedence, outside the binding's line of fire) — the bare-invocation control was
added for exactly that.
