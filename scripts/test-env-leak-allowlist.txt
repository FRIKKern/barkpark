# test-env-leak-allowlist.txt — reviewed waivers for scripts/test-env-leak-gate.sh
#
# The gate flags an ExUnit test that mutates VM-global state
# (Application.put_env / put_all_env / :persistent_term.put) with no paired
# restore in the same module. 13 sites already existed when the gate landed;
# task-949912e93ee948d4 PAID the 11 that were real leaks, and 2 remain. They are
# LITERAL, COMMITTED rows — never a floor computed from the tree, which would
# agree with a gutted tree by construction.
#
# FORMAT (TAB-separated, exactly four fields):
#   <count>	<path relative to api/test>	<app>/<key>	<reason>
#
# A row with fewer than four fields, or a reason under 12 characters, is
# REFUSED. An allowlist whose rows nobody had to justify is a mute button.
#
# The key is (count, file, app/key) and deliberately NOT file:line — a
# line-anchored pin slides on any insertion above it and then names files the PR
# never touched.
#
# COUNTS MAY ONLY FALL. Fix a site and the row reds until you lower it; that is
# the ratchet working, not a bug. Delete the row when the file reaches zero.
#
# EVERY ROW WAS READ INDIVIDUALLY before being written here. 21 candidate sites
# were adjudicated; 6 were false positives the scanner was then taught to stop
# flagging (a def/defp-scoped try/after, and case-template credit); 15 survived,
# and the motivating specimen's row was deleted mid-review (see below) leaving
# 13. Of those 13, 11 were real leaks tracked by task-949912e93ee948d4 and are
# now FIXED — each mutating file captures the prior value in `setup` and puts it
# back in `on_exit` (erasing a :persistent_term that had no prior value, so an
# absent key stays absent) — so their six rows are DELETED here rather than
# lowered. What is left is the 2 KNOWN false positives, kept as rows rather than
# papered over in the detector; their reason says so.
#
# THE DEBT ROW IS PAID, AND THE RATCHET IS WHAT COLLECTED IT. Deleting a row
# without fixing its file cannot pass: the gate re-reads the tree and reds on any
# site it still finds. The six deletions below are therefore each a receipt.
#
# THE FILE DID NOT GROW WHEN #14414 LANDED, AND THAT IS THE POINT. #14414
# rewrote the :plugins idiom across the tree and touched three files this file
# named at the time. It raised 12 NEW hits in three OTHER files — every one of them a false
# positive on code that is not merely correct but better than the inline idiom,
# because it restores through `Barkpark.PluginEnv.restore/1` and so tells an
# absent :plugins from an explicit [] (the discovery kill switch). Baselining
# twelve well-written tests is how a waiver file becomes the real policy, so the
# scanner learned the idiom instead — a restore performed by a CALLED support
# module now credits its caller. The regenerated baseline came back byte-for-byte
# identical to these rows.
#
# One line moved (audit_dispatch_test.exs 52 -> 63) and nothing here changed,
# because the rows are keyed on COUNTS, not file:line.
#
# THE MOTIVATING SITE IS NOT IN THIS FILE, and that is the ratchet working
# rather than an omission. barkpark_web/write_hotpath_telemetry_test.exs — the
# incident specimen, two tests setting :plugins with no on_exit — was baselined
# at 2 while its fix was in flight, and #14074 landed the fix mid-review. The
# gate refused to stay green over the stale row:
#
#   RATCHET  barkpark_web/write_hotpath_telemetry_test.exs (:barkpark/:plugins)
#            — now 0, allowlisted 2. Lower or delete the row.
#
# so the row was deleted. Counts may only fall, and a floor nobody re-earns is
# a floor that rusts.

# ── PAID AND DELETED — the 11 real leaks (task-949912e93ee948d4) ────────────
# Six rows stood here: the SSRF kill switch (:barkpark/:allow_private_outbound,
# 1 each in webhooks/audit_dispatch_test.exs and webhooks/audit_webhooks_test.exs)
# and four :persistent_term capture-term rows (plugin_callbacks_test.exs 3,
# registry_collect_test.exs 3, registry/boot_collectors_test.exs 2,
# indx/recovery_persistence_test.exs 1). Every one now captures its prior value
# in `setup` and restores it in `on_exit`. Nothing was lowered — a fixed file
# leaves the census entirely, so its row goes.

# ── KNOWN FALSE POSITIVES — kept as rows, not hidden in the detector ─────────
# These two ARE restored: the file writes `use Barkpark.RegistryCase`, whose
# on_exit calls Barkpark.Plugins.Registry.reset/0, which reaches
# :persistent_term.put(@snapshot_key, …) inside api/lib. The gate credits a case
# template's on_exit (that is why four other sites are no longer flagged), but
# it will not follow a remote call out of api/test into api/lib to see what it
# writes — a scanner that chased arbitrary call chains would pardon far more
# than it should, and the looseness would be invisible.
#
# Waiving two known-good sites is the honest trade against teaching the detector
# to guess. If Registry.reset/0 ever stops restoring the snapshot, these rows
# are where a reader looks first.
2	barkpark/plugins/registry_cache_test.exs	:persistent_term/@snapshot_key	KNOWN false positive, not a leak — RegistryCase's on_exit restores @snapshot_key via Registry.reset/0, a call the scanner will not follow into api/lib
