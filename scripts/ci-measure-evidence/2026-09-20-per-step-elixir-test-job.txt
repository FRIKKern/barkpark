HOW TO RE-DERIVE THIS FILE, exactly:

    bash scripts/ci-measure.sh --per-step --workflow elixir.yml --runs 300 --pages 3 \
      --split-at 2026-09-20T11:23:09Z --raw-out steps.ndjson
    bash scripts/ci-measure.sh --per-step --raw-in steps.ndjson --split-at 2026-09-20T11:23:09Z

WHY A NEW MODE. --per-job (the sibling evidence file, 2026-09-20-per-job-pull-request.txt)
ranks Test (Elixir 1.18.4 / OTP 27.0) first at 15.82 median job-minutes and
STRUCTURALLY cannot say which 15.82: it projects every step to
{started_at, completed_at} and throws the step NAME away. Setup and test
execution have opposite remedies, so the ranking alone cannot pick one.

WHAT IT IS. Same rules as every other mode in this harness. Minutes are
STEP-derived. Every conclusion comes from actions/runs/<id>/jobs; no run
rollup is read, so there is nothing for continue-on-error to launder.
Cancelled jobs and zero-step jobs are COUNTS in their own columns and are
never summed into a minute column. A jobs page that could not be fetched is
counted as a read FAILURE and is never allowed to become a zero-minute row.

WHAT IT IS NOT. It is not a sample: inside the stated window every completed
elixir.yml pull_request run the feed lists was descended into.

THE BUCKET IS POSITIONAL, NOT A NAME LIST. Steps are PRE / TEST / POST by
their position relative to the step named "Test" INSIDE THEIR OWN JOB. A
hardcoded list of setup step names would silently reclassify the first step
anyone renames. Selftest arm p2 holds this: a step the classifier has never
seen is still bucketed PRE.

THE HEADLINE. Setup is NOT the cost. Over 157 executed jobs the whole PRE
bucket — checkout, BEAM, Node, six guard steps, deps cache+fetch, libxml2,
compile, DB setup — is 168s median, 14.7% of the job. The single step named
"Test" is 994s median, 87.0%. A setup diet cannot move this job; only the
size of the test selection can.

E. WHAT THIS FILE DOES NOT MEASURE

   - QUEUE WAIT. Every number above is COMPUTE (step spans). The reason a PR
     sits at three-of-four green for half an hour is latency, which this mode
     does not separate from concurrency. --job-latency is the mode for that.
   - WHICH TESTS ARE SLOW. The Test step is one step; this file proves it is
     87% of the job and says nothing about which of the 1892 files dominate it.
   - PUSH-EVENT RUNS. Section A-C are event=pull_request only. Section D shows
     push is 44% of live load; its per-step cost is UNMEASURED.
   - WHETHER #19443 RAISED THE ALL-RATE. n=5. See section B. The honest answer
     is that the question is not yet answerable, not that the answer is no.
   - THE 33 NOARTIFACT RUNS. 33 of 64 runs on 2026-09-20 had no
     elixir-impacted-selection artifact (cancelled before upload, or expired).
     Section C's denominators are the 31 that had one, and are stated as such.

   API CALLS SPENT: ~510 (300 jobs pages, 64 ancestry compares, ~128 artifact
   list+download, ~15 run-feed and queue pages, 4 rate_limit probes).
